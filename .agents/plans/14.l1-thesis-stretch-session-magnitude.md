# L1 Thesis — Stretch / Session-maturity / Magnitude Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`)
> syntax for tracking.
>
> **Execution agent rules:** make ALL code changes the plan requires; delete any debug logs you
> add during execution (keep pre-existing ones); leave ALL changes UNSTAGED — do NOT `git add` or
> `git commit`.

**Goal:** Close the gaps the L1 thesis model (`agent-docs/strategy/decisions/thesis.md`) hits when
the day is young or price has run far from structure — surfaced by a manual point-in-time testing
session (`manual-l1-thesis/`). Give the model (1) **session-anchored recall** options, (2) a
**session-maturity soft prior** so it reads a thin early ledger as data-scarcity rather than market
ambiguity, (3) **magnitude-of-clearance scaling** on P1/P2/P4 evidence plus a **stretch discount**
so a far-from-equilibrium TREND declaration is discounted, (4) a **nearest-meaningful-level
distance** fact so it prefers a closer existing predicate over a far default when structure is
sparse, and (5) **cross-family price-cluster confluence tagging** (audit-only) so a tracked level
coinciding with an old, untracked historical extreme is surfaced rather than invisible.

**Architecture (house pattern — "model judges, code computes", `agent-optimizations.md` §1):** the
model tags evidence / selects predicates from the closed vocabulary; deterministic code derives
sign, magnitude, distance, and consistency. Every new value here is a code-computed
`FactsBundle` field or a code-applied multiplier — never a model self-report. New facts reach the
model through the additive S9 block (`render_evidence_text`, already exists) and the S8 predicate
menu; new scoring reaches the decision through `score_thesis_evidence` (already the P1/P2 ledger
scorer) and its `_derive_thesis_arithmetic` wiring.

**Tech Stack:** Python, pandas (bar resampling via the existing `ohlc()` helper), pytest (existing
suite only — see Global Constraints).

**Complexity:** ⚠️ Medium — bounded to the facts/menu/scoring layers; no new predicate type, no
executor change, no `MarketView`/schema change. The one non-trivial thread is routing a
code-derived magnitude lookup from where the `FactsBundle` exists (`bench/facts.build_facts`) down
to `score_thesis_evidence` (Task 5).

- Modify: `agent/derive_facts.py` — add `build_evidence_magnitude(bundle) -> dict` helper (near

- Modify: `agent/bench/facts.py` — `FactsResult.evidence_magnitude` field + populate it in

- Modify: `agent/run_agent.py` — `_derive_thesis_arithmetic` gains `magnitude=None`
  (`:579-606`); `decide_thesis` gains `evidence_magnitude=None` and passes a closure into
  `_run_call` (`:858-878`).

**Interfaces:**
- Consumes: `bundle.htf_close_status[tkr][name][tf]["close"]` (raw close, plan 13),
  `bundle.levels[tkr][name][0]` (level price), `bundle.avg_range_1h/4h[tkr]` (Task 1).
- Produces:
  - `derive_facts.build_evidence_magnitude(bundle)` → `{(asset, level, tf): ratio}` where
    `ratio = |close − level_price| / avg_range[tf][asset]` (skip entries with immature/None close or

    later declares.

  - `score_thesis_evidence(evidence, magnitude=None)` — each item's points gain a magnitude

    (identical to today).

**Design notes:**
- Magnitude buckets (v1 seeds, pending calibration), defined next to the existing multiplier tables:
  ```python

  _MAG_BUCKETS = ((0.5, 0.75), (1.5, 1.0), (float("inf"), 1.25))   # (ratio_upper, multiplier)

  def _magnitude_mult(ratio):
      if ratio is None:

  ```
