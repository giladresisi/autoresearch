## Fix 1 — Code-enforced default TTL for ALL non-standing (low-conf/waiting) theses

**Gap:** spec §2.1 gives `recall.max_age_min` but only the FAILSAFE factory got a default
(plan 11). A VALID NEUTRAL/LOW thesis whose model-authored recall has max_age_min=0/absent
and whose recall events never fire waits forever — 07-02 diag run: th_04 waited 20.5h through
the crash. The user's original requirement: "we'll also have a default max time from the
last call to the 1st level."

**Fix (data + clamp, both consumers):**
- New config constant `DEFAULT_LOWCONF_RECALL_MAX_AGE_MIN = 60` (same value as the failsafe
  default; single source in `agent/contracts/schemas.py` or decisions config — wherever
  FAILSAFE_RECALL_MAX_AGE_MIN lives, keep them adjacent).
- Enforcement in CODE, not the model output: bench `lifecycle._run_waiting` and executor
  `TradeDirector` compute `effective_max_age = min(declared if >0 else default, cap)` —
  i.e. a missing/zero/absurdly-large declared max_age is clamped to the default. Declared
  values BELOW the default are respected (the model may ask to be re-called sooner).
- Also applies while a STANDING thesis's TTL is longer: no change to standing-thesis TTL
  tiers (that's bench config, already exists).
- Spec: add one sentence to `agent-optimizations.md` §2.1/§5 noting the code-enforced
  default (meta doc, stays untracked — edit in place).

Named tests (bench + executor):
- valid low-conf thesis, no recall block → re-call at default (60m).
- max_age_min=0 → default; max_age_min=30 → 30 (sooner respected); max_age_min=600 → clamped
  to default cap.
- failsafe path unchanged (existing tests stay green).
- TradeDirector: THESIS_LOW_CONF with no recall → L1 re-called at default.
- Replay validation ($0): rescore `test_0702_run2_diag` — NOTE: rescore replays logged
  lifecycles; if the TTL change alters lifecycle boundaries, rescore of OLD runs must remain
  byte-stable (it replays logged decisions/gates, not new TTL logic) — assert that explicitly;
  the TTL fix manifests only in NEW runs. If the bench engine applies TTL at replay time and

## Fix 2 — Wrong-side DOL: th_02 completed in 2 min on a DOL above price (DOWN thesis)

**Symptom:** `test_0702_run2_diag` th_20260702_02: DOWN thesis born 20:01, DOL
prev1_day_low @30009.2, arrival_price 29966.2 (price BELOW the "low" pool) → exhaustion
(price_beyond above-side touch) fired in 2 min → bogus "completed".

**Investigate first (free, from logged artifacts):** decisions.jsonl for th_02 has the facts
hash + the S8 menu the model saw. Determine which failed:
(a) DOL menu offered prev1_day_low as a DOWN target while price was already below it
    (menu correct-side filter bug — likely: the filter compared against a stale/other price,
    or the pool was "unswept" by wick/body nuance while price sat beyond it);
(b) menu was correct but the model escape-hatched / picked a wrong-side entry and the
    validator's side check missed it (validator gap);
(c) menu+choice fine at 20:01 facts but price moved across the level between facts build and
    born_ts (race — then the fix is a freshness guard: reject/re-side DOLs within X pts of
    current price or crossed since facts build).
Fix whichever is real (possibly more than one): the DOL menu side-filter must use the same
price snapshot the menu is stamped into; the contracts validator gains an explicit
SEM_DOL_WRONG_SIDE check (thesis.dol on the bias side of facts price) so this class can
never pass validation again regardless of menu correctness; scoring gains a sanity flag
(completion within N minutes of arrival AND dist_to_dol_pct at arrival <= 0 → flag
`suspect_completion` in the lifecycle record so metrics can exclude).

Named tests:
- menu: pool beyond current price never offered as a same-direction target (both directions,
  wick/body variants).
- validator: DOWN thesis with DOL above facts price → SEM_DOL_WRONG_SIDE reject (and UP
  mirror).
- scoring: synthetic th_02-shaped lifecycle gets suspect_completion=True; normal completion
  False.
- Root-cause regression: reproduce the actual th_02 facts (from the logged run dir) through
  the menu builder and assert the offending entry is now absent/rejected — this is the $0
  proof the bug is fixed.
