## Phase 1 — Contracts package (`agent/contracts/` or extension of `agent/`)

Schemas + predicate language + validators. Pure code, no pipeline wiring.

1. `thesis.json` / `trade_plan.json` schema definitions (spec §2.1/§2.2) as structured-output
   JSON schemas + dataclasses.
2. Predicate language (spec §6): closed vocabulary, parser, and a bar-close evaluator
   `eval_predicate(pred, market_view) -> bool`. `market_view` = a thin deterministic adapter
   over the pipeline frames (price, closes per tf, level sweep/depletion states, clock).
3. Validator extensions: syntactic (enums, closed mechanism kinds, mandatory
   `on_dol_falsified` on SETUP), semantic (levels exist in facts, unswept/undepleted —
   reuse TARGET CONTRACT logic), cross-level (stop must not satisfy thesis `falsified_if`;
   target must not satisfy thesis `exhausted_if`).

Test cases (minimum, named):
- schema: valid SETUP accepted; unknown mechanism kind rejected; SETUP missing
  `on_dol_falsified` rejected; WAIT with no recall rejected.
- predicates: each atom true/false on synthetic bars; `n_closes_beyond` boundary (n-1 vs n);
  `all_of`/`any_of` nesting; unknown predicate type rejected.
- cross-level: stop that trips a thesis falsification predicate rejected; target equal to the
  thesis DOL exhaustion price rejected; valid pair accepted.

## Phase 2 — Executor state machine (deterministic core, stub decisions)

`TradeDirector` (new module, executor-owned): the spec §5 state machine, attempt counter
(per plan_id, failed entries only, cap 3), session risk gate wrapper (daily loss limit via
`loss_limit.py`, max trades/session, halt-after-N-losers — config), and AI-call scheduling
(which level to call on which transition). Driven entirely by injected decision providers so
Phase 2 tests need no LLM and no pipeline.

Test cases (named; one per transition edge at minimum):
- session open → L1 called once; low-conf → no L2 call; recall event → L1 re-called;
  max_age TTL → L1 re-called.
- confident thesis → L2 called; WAIT → recall on event and on TTL; SETUP → armed.
- thesis falsified in each of THESIS_LOW_CONF / AWAITING_SETUP / SETUP_ARMED → dependent plan
  dropped, L1 called.
- IN_POSITION: no AI calls fire under any event except via defined exits; thesis falsified
  while open → `on_dol_falsified` executed deterministically, THEN L1.
- stop-out at attempts 1,2 → re-arm same plan; attempt 3 → L2 re-call (setup-falsified path).
- profitable exit with valid thesis → L2; with exhausted thesis → L1.
- risk gate: loss-limit breach mid-session → HALTED, no new entries, open position still
  managed; breach cannot be reset by any decision input.
- failure policy: provider raising/timeout → standing decisions retained; no thesis → flat.

## Phase 5 — Confidence module scaffold

`agent/confidence.py`: feature extraction (deterministic, from decision + facts: evidence
count, item-type diversity, tier mix, freshness stats, score band, regime, session phase) →
calibration-table lookup (TSV/JSON artifact, loadable; bootstrap table derived from the
289-trigger batch audit) → tier + gate decision. Model self-report becomes audit-only
everywhere the gate reads confidence.

Test cases: feature extraction on a known audit record matches hand-computed values; missing
cell → configurable floor (LOW); gate threshold respected; bootstrap-table build script runs
on the existing batch audit files and emits a table (values are placeholder-quality — that's
acceptable and documented).
