# Plan 10 — L1 lifecycle bench

Complexity: ⚠️ Medium
Context: `agent-optimizations.md` (v2 spec) + plan 9 execution report. The bench is the
measurement instrument for the upcoming L1-internals effort: it replays full days through the
L1 thesis lifecycle (call → standing thesis → code-evaluated predicates per bar → death by
falsification/exhaustion/TTL → re-call) and scores lifecycle quality. It exists so every
internals iteration (KB docs, prompts, menus) shows up as metric deltas on the same days.

Purpose framing (matters for validation): with today's skeleton prompts the real-API L1 mostly
falls to NEUTRAL/LOW failsafes — the bench's run #0 baseline is EXPECTED to show near-zero
coverage and mostly failsafe lifecycles. That baseline scorecard is a deliverable, not a bug.

Scope guard: NEW code only (`agent/bench/` package + tests). No modifications to
session_pipeline / backtest_smt / automation / executor behavior. If a tiny read-only export
is needed from an existing module (e.g. a constant), prefer importing what exists; do not
change existing behavior. Therefore NO byte-identity gate is required — but the full test
suite must stay at baseline.

Repo-standing constraints: everything UNSTAGED, no commits/pushes. Real-API spend only via
per-run shell env, never `.env` defaults. Meta docs stay untracked.

## Design (locked)

**Bench loop (per date):** start at session open 18:00 ET (prior day); build facts as of the
current timestamp (OFFLINE path — 17-day primary df from main parquets, mirroring
`calibration/prepare_cuts.py` / `facts_adapter._with_history` parity); call
`run_agent.decide_thesis`; stamp `arrival_ts = trigger_ts + latency_sec` and begin predicate
evaluation only from the arrival bar (production parity). Then walk 1m bars:

- Confident thesis (gate via `agent/confidence.py`, model self-report audit-only): evaluate
  `falsified_if` / `exhausted_if` each bar via `agent/contracts/predicates.eval_predicate` +
  a bench `MarketView` over the day's bars, PLUS the configurable code-injected standing
  safety-net triggers, PLUS the confidence-tiered TTL.
- Low-confidence thesis: does not stand; wait on its `recall` events / `max_age_min`.
- On any death: log the lifecycle record (cause, timestamps, excursions), immediately re-call
  L1 at that bar (+latency). Repeat to session end (16:59 ET), then close the last lifecycle
  as `session_end`.

**Safety-net triggers (config, all toggleable — they are iteration subjects):**
`ttl` (per-confidence-tier minutes, e.g. HIGH 180 / MEDIUM 90; LOW handled by recall),
`acceptance_flip` (N consecutive 1m closes on the anti-thesis side of the daily mid),
`opposite_extreme` (new session extreme against the thesis direction). Default ON: ttl only.

**Churn cap:** max L1 calls per day (default 20). Hitting it aborts the day with outcome
`CHURN_CAP` — a scorecard fact, and the runaway-API guard.

**Outcomes per lifecycle:** `completed` (DOL touched before any falsification) · `falsified`
· `safety_net` (which trigger) · `ttl` · `recall` (low-conf) · `failsafe` (validator fell
back) · `session_end` · `churn_cap`.

**Metrics:**
- Per lifecycle: born/arrival/died ts, cause, bias, DOL level+price, confidence (gate + self
  report), time alive, max favorable/adverse excursion, distance-to-DOL covered (%),
  `false_kill` (after a non-completion death: did price touch the dead thesis's DOL within
  the lookahead horizon H — reuse `agent/decisions/annotate.py` horizon conventions, H=4h),
  `late_kill_adverse` (for falsified-when-wrong: adverse pts between the thesis's peak
  favorable point and the falsification fire).
- Per day: completion rate (directional theses), false-kill count, median late-kill adverse,
  churn (calls/day), coverage (% of session minutes under a standing confident thesis),
  failsafe rate, API cost, per-call latency.
- Aggregate across dates: same metrics + per-regime split (regime labels from the batch:
  trend/chop/reversal/bigrange — accept a small static date→regime map in config).

**Modes:** `stub` ($0, StubBackend), `real` (per-run shell env key), `rescore` (re-run
scoring/predicate replay from a previous run's logged decisions JSONL, $0 — MUST be
byte-stable for identical inputs).

**Outputs:** `agent/bench/runs/<run-id>/<date>/lifecycles.jsonl` + `decisions.jsonl` (full
thesis JSON + attempts/violations/usage per call) + `scorecard.md` per date +
`aggregate.md` + `aggregate.tsv` at run root. `agent/bench/runs/` gitignored.

**Explicitly NOT in scope:** candidate-predicate/DOL menus, KB/prompt content changes, L2
anything, TradeDirector integration, live wiring. Drift guard note: the bench's lifecycle
semantics intentionally mirror spec §5's L1 subset; reuse `eval_predicate`, the confidence
gate, and shared config constants (latency, TTLs) rather than re-defining them, so bench and
executor cannot silently diverge on those.

## Phase 1 — Lifecycle engine (`agent/bench/engine.py`)

The bench state machine driven by injected decision provider + bar source (no facts, no LLM):
standing/low-conf handling, arrival gating, predicate evaluation, safety-net triggers, TTL
tiers, churn cap, lifecycle record emission.

Named tests (`agent/bench/test_engine.py`):
- completed: DOL touch before falsification → outcome completed, excursions correct.
- falsified: predicate fires → re-call scheduled at fire-bar + latency; late_kill_adverse
  computed vs the favorable peak.
- arrival gating: predicate that is true between trigger and arrival does NOT fire pre-arrival.
- low-conf: no standing thesis; recall event fires → re-call; max_age fires → re-call.
- ttl tiers: HIGH survives past the MEDIUM ttl; MEDIUM dies at its ttl.
- safety-net: acceptance_flip fires when enabled, silent when disabled; opposite_extreme ditto;
  cause recorded as safety_net(name).
- churn cap: scripted always-falsify provider hits the cap → day aborts with churn_cap.
- session_end: open lifecycle at 16:59 closes with cause session_end.
- failsafe decision (fallback=True) → lifecycle recorded as failsafe, treated as low-conf.

## Phase 2 — Facts + call integration (`agent/bench/run_bench.py` core)

Offline facts builder for arbitrary intra-day timestamps (17-day primary df, both tickers,
truncate at ts — assert parity with the prepare_cuts path on one known cut: same facts
content hash) + `decide_thesis` invocation (stub + real backends via existing `make_backend`)
+ `decisions.jsonl` logging (attempts, violations, usage, latency, facts_hash).

Named tests: facts-parity-with-prepare_cuts on a burned cut; lookahead guard (facts max_ts
never exceeds trigger ts); stub end-to-end single-day run produces lifecycles.jsonl +
decisions.jsonl with linked ids.

## Phase 3 — Scoring + scorecards (`agent/bench/score.py`, `report.py`)

Per-lifecycle enrichment (false_kill lookahead H=4h vs the dead DOL, distance-covered),
per-day scorecard.md (the table from the design), aggregate.md/tsv with per-regime split,
`rescore` mode (replay from decisions.jsonl; byte-stable).

Named tests: false_kill true/false cases on synthetic bars; distance-covered arithmetic;
rescore byte-stability (two rescore runs identical); aggregate regime split with the static
map; scorecard renders with zero directional theses (all-failsafe day — the run-#0 shape).

## Phase 4 — CLI + validation runs

`python -m agent.bench.run_bench --dates D1,D2 --mode stub|real|rescore [--run-id ...]
[--latency-sec N] [--safety-net ttl,acceptance_flip,...] [--churn-cap N]`.

Validation:
1. Stub run on 2026-05-19 + 2026-05-01: completes, deterministic machinery (two stub runs →
   identical lifecycles given identical stub decisions), ~0 coverage expected (stub neutral).
2. Real-API smoke on ONE date (2026-06-25), per-run shell env, expected cost < $1: verify
   full decisions.jsonl reconstruction, arrival stamps, failsafe lifecycles recorded cleanly.
3. Rescore of run 2 at $0 → identical scorecard.
4. **Run #0 baseline deliverable:** real-API bench over 3 dates spanning regimes (06-25
   reversal, 05-19 trend, 05-18 chop; expected < $3 total) → committed-to-disk (NOT git)
   baseline aggregate scorecard. This is the "watch it improve" anchor the user asked for.
5. `pytest tests/` unchanged vs Phase 0; full `agent/` suite green.
