# 34. TDO as an eligible DOL target (both directions)

Status: IN PROGRESS. Complexity: ⚠️ Medium.

## Why

`derive_facts._dol_menu` drops every candidate whose `side` is not `"above"`/`"below"`.
`TDO` is built as `(price, None, None, "session", ts)` — `side=None` — so an open-price
level can never be offered as a draw. The spec has always assumed it can be: §6's
validation records read "07-21 (thesis down, DOL = TDO 29072.50) → TDO +126.50" and
"08-10 (thesis up, DOL = TDO) → TDO TP +65.75", and §10.3's 24-session sweep defines its
DOL as "nearest of overnight/prev-RTH/TDO pools >= 60 pts away". So this is an
IMPLEMENTATION GAP, not a new mechanism.

Motivating evidence (2026-09-09, measured this session): with the direction corrected to
UP, production's menu could offer nothing nearer than `london(cur)_high @ 29634.00`, which
was never reached (closest approach 40.00 pts). The midnight open at 29561.75 was crossed
at 09:59:20 — an oracle replay targeting it books **+91.75** against the **-15.25** the
run actually took. 2026-09-08 is the control: its DOL is `prev2_day_low`, unaffected by
this change, and must stay at **+64.25**.

## Rule decisions (user, 2026-09-12)

1. **TDO = the 00:00 ET open** of the trade date. `derive_facts` currently anchors it at
   the 18:00 session open, giving a third value again (29528.00 vs 29561.75 vs
   `levels.json`'s stale 29742.50 on 09-09). Midnight is the ICT canonical reference.
2. **Spent-ness is measured from the plan boundary forward.** An open price is crossed at
   00:00 BY DEFINITION and usually again pre-09:30 — measured 7/7 sample days. Anchoring
   the sweep at the level's own instant would mark it spent before every arm and make the
   whole change inert. There is no resting liquidity at an open price to consume; it is
   spent when the armed plan reaches it (`dol_reached`).
3. Scope limited to `TDO`. `TWO` is the same shape but was not asked for and has no
   evidence attached; widening is a one-tuple change.

## Deliverables

- [ ] `DOL_OPEN_PRICE_LEVELS = ("TDO",)` in `derive_facts`, documented.
- [ ] TDO price + `active_from` anchored at the midnight bar (fallback: session open).
- [ ] `_duplicate_sweep_losers` takes the session opening bar as an ARGUMENT instead of
      reading `lv["TDO"][4]` — otherwise re-anchoring TDO silently moves the §2.1d
      gap-cascade collapse key from 18:00 to midnight. Unrelated to targets; must not move.
- [ ] S2 renders open-price levels in the parser's `<name> <price> [side]: <rest>` form,
      side derived from the ticker's last close, marked not-swept-at-the-boundary with the
      pre-arm cross recorded as context. No `add_card` — P1 evidence is untouched.
- [ ] `_dol_menu` admits open-price levels to whichever side of price they sit on.

## Test cases (write first, from the rules above)

1. TDO price == the 00:00 ET bar open, and `active_from` == that bar's timestamp.
2. TDO above the last close -> appears in the UP menu; below -> DOWN menu.
3. TDO inside the draw floor (`max(5.0, 1.0 * avg_1h)`) -> excluded, both directions.
4. A pre-arm cross does NOT mark it swept; `vd["levels"]["TDO"]` exists, `swept=False`,
   with the side the menu used.
5. `_duplicate_sweep_losers` still collapses on the 18:00 session open after the
   re-anchor (regression guard for the ripple).
6. TWO stays out of the DOL menu (scope guard).
7. P1 evidence is unchanged: no sweep card is emitted for TDO.
