## 1. Background / the problem (grounded)

The single constant family `FULFILL_PTS_MNQ` / `FULFILL_PTS_MES` (`smt_detect.py:36-37`), read everywhere through `_fulfill_pts(tier, inst)` (`smt_detect.py:106-108`), is **overloaded across three structurally-distinct jobs**. An overfit trial that raised the `session` tier backfired: trades stayed byte-identical (the SMT layer is **shadow** — detection-only, does not drive trades), but the SMT-div *stream* got noisier, because raising "what counts as fulfilled" ALSO delayed the depletion-retirement latch — the flood-stopper. One constant, three jobs, no way to tune one without moving the others.

### The three jobs `_fulfill_pts` currently performs (grounded line numbers @ `653084c`)

1. **FULFILLMENT** — measured from the SMT's **FIRE close**; favorable follow-through this far ⇒ success. **(keep on `_fulfill_pts`)**
   - `smt_detect.py:603` — live detection block (a) (`pts = _fulfill_pts(tier, "mnq")`).
   - `smt_detect.py:161` — Phase 1.2 `pending_smt_terminal` re-validation of a carried SMT (`ful = _fulfill_pts(tier, "mnq")`).
2. **DEPLETION** — measured from the **LEVEL**; price ran this far past the level ⇒ liquidity gone ⇒ retire the ticker (per-ticker `__level_inv__` latch). **(migrate → `_deplete_pts`)**
   - `smt_detect.py:687-688` — the per-ticker depletion latch (`_thr_mnq = _fulfill_pts(tier,"mnq")`, `_thr_mes = _fulfill_pts(tier,"mes")`).
   - `smt_detect.py:129` — Phase 1.1 `pre_session_depleted` pre-session seed (`thr = _fulfill_pts(tier, inst)`). **Note: this site passes a variable `inst`** (mnq OR mes), so `_deplete_pts` must accept arbitrary `inst`.
3. **DEPARTURE** — measured from the **LEVEL**; price left the level by this margin ⇒ fixed-level becomes re-arm-eligible ("departed"). **(migrate → `_depart_pts`)**
   - `smt_detect.py:621` — fixed-level re-arm departure margin (`abs(mnq_close - mnq_lvl_price) >= _fulfill_pts(tier,"mnq")`). **Only ever uses `inst="mnq"`.**

`INVALIDATE_PTS_MNQ` / `INVALIDATE_PTS_MES` (adverse-run; sites `:162` and `:729`) is ALREADY a separate knob — **do NOT touch it**.

### Current values (the no-op seed for the two new families)
```python
FULFILL_PTS_MNQ = {"week": 80.0, "day": 40.0, "session": 20.0}
FULFILL_PTS_MES = {"week": 12.0, "day":  6.0, "session":  3.0}
```

### Why the split must seed equal-to-FULFILL first
Because all three jobs currently read the *same* numbers, initializing `DEPLETE_PTS_*` and `DEPART_PTS_*` to **exactly the current `FULFILL_PTS_*` values** makes the split a **pure no-op refactor**: every call site computes the identical number it computed before. That guarantees the refactor commit is byte-identical on BOTH trades AND the SMT-div detection stream — which is the primary acceptance gate (§5). **Any value change is a separate, later, explicitly-flagged step (§6) — never bundled into the refactor.**

## 2. Grounded design

### 2.1 Two new constant families (seed = current FULFILL_PTS, verbatim)
Add directly below the existing `FULFILL_PTS_*` block (`smt_detect.py:32-37`):

```python
# Depletion thresholds (pts) by tier+instrument. Measured from the swept LEVEL (not the fire
# close): once price runs this far PAST a level it is treated as depleted/consumed → the
# per-ticker retirement latch fires and the ticker is skipped (the flood-stopper). Split out of
# FULFILL_PTS (GIL-25 Phase 1.3) so depletion can be tuned independently of fulfillment.
# Seeded EQUAL to FULFILL_PTS so the split is a pure no-op; tune separately.
DEPLETE_PTS_MNQ = {"week": 80.0, "day": 40.0, "session": 20.0}
DEPLETE_PTS_MES = {"week": 12.0, "day":  6.0, "session":  3.0}

# Departure thresholds (pts) by tier+instrument. Measured from the LEVEL: a fired FIXED level
# becomes re-arm-eligible ("departed") once price leaves the level by this margin. Split out of
# FULFILL_PTS (GIL-25 Phase 1.3) so the re-arm margin can be tuned independently. Only the MNQ
# leg is consumed today (site smt_detect.py departure check uses inst="mnq"); the MES table is
# carried for symmetry/future use. Seeded EQUAL to FULFILL_PTS so the split is a pure no-op.
DEPART_PTS_MNQ = {"week": 80.0, "day": 40.0, "session": 20.0}
DEPART_PTS_MES = {"week": 12.0, "day":  6.0, "session":  3.0}
```

### 2.2 Two new helpers (mirror `_fulfill_pts` shape EXACTLY)
Add directly below `_fulfill_pts` (`smt_detect.py:106-108`), identical structure incl. the `table.get(tier, table["session"])` fallback:

```python
def _deplete_pts(tier: str, inst: str) -> float:
    table = DEPLETE_PTS_MES if inst == "mes" else DEPLETE_PTS_MNQ
    return table.get(tier, table["session"])


def _depart_pts(tier: str, inst: str) -> float:
    table = DEPART_PTS_MES if inst == "mes" else DEPART_PTS_MNQ
    return table.get(tier, table["session"])
```
