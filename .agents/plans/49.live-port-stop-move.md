# 49. Live port stop move (2026-10-02 session D1 / O4)

Complexity: ⚠️ Medium (live order path; no replay behaviour change).

## Problem

`ACT_STOP_BE` (break-even at 50% of the way to T2, `l2-mechanisms.md` §8) moves the stop
through `move_stop`. `OrderSim` has it, `MirroringOrderPort` did not, so a replay moved
the stop and live recorded `veto reason=trail_unwired` and moved nothing. On 2026-10-02
live armed at 09:45:40 ET and kept 31098.25; both replays moved to 31128.25. Every replay
that arms the break-even measured a behaviour live did not have.

## Scope

Wire the stop move live. NOT in scope: whether break-even at 50% is a good rule (O4's
"re-decide" half) — that is the operator's risk decision, recorded in §8.

## Change

| File | Change |
|---|---|
| `agent/trader/order_port.py` | `MirroringOrderPort.move_stop`: model first, one `stop_moved` to the sink, own `seq`. A not-ok ack keeps the tighter model stop, sets no `external`, returns the event with `far_side=<reason>`. |
| `automation/agent_dispatch.py` | `stop_moved` -> one `update-stop-loss` signal (`STOP_KIND`, `STOP_REASON`); `_ack_stop` reads the stop back off position.json. |
| `live_orders.py` | `dispatch`: `update-stop-loss` -> `update_stop_loss(...)` when a position is active, log-only otherwise. |
| `automation/main.py` | `update-stop-loss` joins `_AGENT_OWNED_KINDS`. |
| `agent/trader/executor.py` | docstrings only. |
| `l2-mechanisms.md` §8, `CLAUDE.md` | the "live cannot move a stop" sentences. |

Fail-safe argument for keeping an unconfirmed move: every caller only tightens; the
model tests its own stop on the tick and sends a market close when it is touched; the
close flattens whatever the broker's stop did.
