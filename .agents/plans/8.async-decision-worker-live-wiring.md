# 8. Async decision worker as the execution model (backtest + live) 🔴

**GIL-44 Phase 3, slice 2.** Make the AI decisions engine run ASYNCHRONOUSLY via its
worker (`DecisionWorker`) in BOTH the backtest and live trading, so the live 1s loop never
blocks on an LLM call and the backtest uses the same worker/execution path. Observation-only
throughout (decisions logged, never acted on), behind the master flag `AI_DECISIONS_ENABLED`
(env `ACT_AI_DECISIONS`), default OFF. **QUALITY work is OUT OF SCOPE** (no doc changes, no
inter-checkpoint re-eval, no multi-day batch — those come after this slice lands).

Complexity: 🔴 (threading + live-loop hot path + backtest determinism + flag-OFF byte-identity).

## Executive summary (phase structure)

1. **Phase 0 — baseline + contract.** Record full-suite baseline (pass/broken/skipped). Freeze
   the pipeline↔worker interface contract (the worker's `submit_*`/`note_*` API replaces the
   direct engine calls the pipeline makes today).
2. **Phase 1 (Wave 1) — worker as the backtest execution path + determinism.** Route the
   backtest's engine through `DecisionWorker`; make the pipeline talk to the worker
   (`submit_checkpoint` / `submit_hypothesis_trigger` / `note_hypothesis_superseded` on
   new-hypothesis AND trend-broken); at day-end `drain()` → deterministic finalize (sort audit
   JSONL + `events_native`, recompute `discarded` from the arrival-vs-supersede timeline) →
   `shutdown()`. Update the three integration tests to the worker interface.
3. **Phase 2 (Wave 2) — live attachment (flag-gated OFF).** Construct the worker in the live
   `SmtV2Dispatcher` behind the flag; per-session out_dir under `sessions_dir()`; a
   **session-end lifecycle** (drain-bounded → finalize → shutdown, idempotent) hooked into the
   session-closed branch; staleness driven by the same emit stream; hard OFF default keeps live
   byte-identical.
4. **Phase 3 (Wave 3) — tests + A/B gates.** Per-component named tests; flag-OFF 1s A/B
   byte-identical on ≥2 regime days; flag-ON (stub) trades byte-identical + non-AI event
   subsequence unchanged.
5. **Phase 4 — supervised live smoke (USER-GATED, documented, not executed here).**

Rollback for the whole slice: the flag. `ACT_AI_DECISIONS` unset ⇒ no worker, no thread, no
spend, byte-identical live + backtest.

## Interface contracts (outputs of wave N = inputs of wave N+1)

- **C1 (Wave 0 → 1):** Pipeline↔decisions contract = the **DecisionWorker submit API**:
  `submit_checkpoint(now, frames)`, `submit_hypothesis_trigger(now, frames, hyp_event, kind)`,
  `note_hypothesis_superseded(new_hyp_id, now=None)`. All non-blocking, never raise. The
  pipeline no longer depends on `on_checkpoint`/`on_hypothesis_trigger` return values (it
  already ignores them today, `session_pipeline.py:979`).
- **C2 (Wave 1 → 2):** `DecisionWorker` gains a deterministic-finalize helper and a bounded
  session-end helper reused by live:
  `finalize_deterministic(session_parquet=None)` (drain unbounded → recompute discarded →
  sort+rewrite audit → sort `events_native` → engine.finalize) and
  `close(timeout, session_parquet=None)` (drain bounded → finalize_deterministic → shutdown).
  Backtest calls `finalize_deterministic`; live calls `close`.
- **C3 (Wave 1 → 2):** `_build_decision_worker(out_dir)` factory (wraps
  `_build_decision_engine`'s engine in a `DecisionWorker`) is importable and used by both
  `backtest_smt.py` and the live dispatcher.
- **C4 (Wave 2 → 3):** live dispatcher exposes `on_session_end(now)` (idempotent) so a test and
  the 1s loop both drive teardown through one path.

## Design decisions (each grounded, with a recommendation)

### D-A — frame race in live (the hot-path data question)
**Finding:** the feared race is largely absent by construction. In the live 1s loop
(`automation/main.py:197-237`) `today_mnq`/`today_mes` are rebuilt **fresh every second**
(boolean-index slice → `.copy()`/`pd.concat`), never mutated in place after being passed;
`hist_mnq`/`hist_1hr` are set once at pipeline construction and the IB source *replaces* its
DataFrame reference via `pd.concat` (a new object) rather than mutating the captured one
(`signal_smt.py:826-828`). The pipeline reads `today_mnq` only via non-mutating slices/`.values`
(`session_pipeline.py:1077-1081,1267,1733-1742`). So a frames dict captured at submit references
**immutable-by-construction snapshots**; `compute_facts` (~0.68 s) runs on the worker thread,
off the loop — which is the whole point of the worker.
**Recommendation (chosen):** pass the frame references to the worker, but **shallow-copy the
frames dict** at submit (decouples from `_ai_decisions_ctx` being overwritten next bar —
`session_pipeline.py:1000`; cost = one dict, not the DataFrames). Do **not** build the snapshot
on the loop (reintroduces a 0.68 s hiccup we're trying to remove) and do **not** deep-copy
frames (unnecessary given immutability; memory: `today_*` ≈ one session of 1m rows, `hist_*`
shared by reference → negligible on 16 GB, ≤ a couple frames alive at once given ≤25 triggers/day
draining in ~79 s). Protect the invariant with a guard test (W3-T7) that mutates a source frame
after submit and asserts the recorded facts are unchanged.

### D-B — backtest determinism under async
**Finding:** the user requires the backtest use the **SAME worker/execution path**
(`prod-agent.md:82`), so a "synchronous-with-bookkeeping" fork of the code path is rejected —
it would diverge from the live path we're trying to align to. Async also overlaps LLM calls with
bar replay → real wall-clock speedup on the (later) real-API multi-day batch. The cost is
determinism, which we restore explicitly:
1. **Content** is already deterministic under the **stub** backend (the byte-identity gate runs
   on the stub; real-API content is inherently non-deterministic and is *not* under the gate).
2. **Arrival** = `trigger + DECISION_LATENCY_SEC` in the record (`engine.py:169,222`) —
   independent of wall-clock completion.
3. **Ordering:** audit JSONL is appended in worker-completion order (`records.py:150`) and
   `events_native` in completion order → both **sorted at finalize** by
   `(arrival_ts, trigger_ts, trigger_kind)` and the audit file **rewritten**.
4. **Staleness:** the worker's `discarded` flag is set by a wall-clock race
   (`async_wrapper.py:84`). For the backtest, **recompute `discarded` deterministically at
   finalize** from the arrival-vs-supersede timeline: a trigger record is stale iff a later
   new-hypothesis/trend-broken supersede event has a logical time in
   `(trigger_ts, arrival_ts]`. This is exactly the `prod-agent.md:84-85` "arrival bookkeeping"
   model and matches the `async_wrapper.py:10-12` docstring ("arrival is when the worker
   finishes; the frozen-at-T facts are identical").
5. **drain() (unbounded) before finalize** so every job has completed.
**Recommendation (chosen):** async worker in the backtest with the four determinism guards
above. To feed (4), `note_hypothesis_superseded` records the logical `now` into a deterministic
`_supersede_log` on the worker (see D-D). Marked as the load-bearing open decision — see HOLES.

### D-C — worker lifecycle in live
**Finding:** the live pipeline is (re)built per CME session in `on_session_start`
(`automation/main.py:985-996`, idempotent by `cme_session_date`). There is no engine teardown
today. The session-closed window is handled every second at `automation/main.py:168-174`.
**Recommendation (chosen):**
- **Start:** build the worker inside `on_session_start` (flag-gated) alongside the pipeline,
  out_dir = `SESSIONS_DIR/<cme_session_date>` (matches `automation/main.py:1071`).
- **Stop:** add `SmtV2Dispatcher.on_session_end(now)` — **idempotent** (guarded by a
  `_session_closed` flag, since `_on_bar` re-enters the closed branch every second) — that calls
  `worker.close(timeout=SHUTDOWN_TIMEOUT, session_parquet=None)`; wire it into
  `automation/main.py:168-174` (the `SESSION_CLOSE <= time < SESSION_OPEN` branch). A wedged LLM
  call can never hang session close (bounded `drain`, `async_wrapper.py:97-100`).
- **Restart mid-session:** new process → new worker; in-flight decisions are lost (acceptable,
  observation-only) and the standing daily-trend re-warms at the next checkpoint. **Persisting
  engine state across restarts is OUT OF SCOPE for this slice** (engine state is in-memory only,
  `engine.py:76-86`; observation-only + flag-OFF default makes it non-load-bearing). Documented
  as a follow-up, not built.

### D-D — staleness wiring (both modes)
**Finding:** new-hypothesis staleness is implicit (`submit_hypothesis_trigger` sets
`_current_hyp_id`, `async_wrapper.py:51`). trend-broken must also supersede — trend-broken is
emitted through `self._emit` (`session_pipeline.py:836,1205,1290`) but
`_emit_with_ai_decisions` currently only handles `new-hypothesis` (`:971-972`).
**Recommendation (chosen):** in `_emit_with_ai_decisions`, on `kind == "trend-broken"` call
`self._ai_decisions.note_hypothesis_superseded(None, now=ctx["now"])`. Extend
`note_hypothesis_superseded(new_hyp_id, now=None)` to append `(now, new_hyp_id)` to a
deterministic `_supersede_log` (used by the backtest recompute, D-B(4)); the live wall-clock
`_current_hyp_id` behavior is preserved unchanged. `submit_hypothesis_trigger` also appends its
own `(now, hid)` boundary so a *new* hypothesis supersedes a prior in-flight one in the
recompute too.

### D-E — live logging + end-of-session hook
**Finding:** engine writes `ai_decisions_audit.jsonl` + `snapshots/` to `out_dir`
(`engine.py:73-74`); `events_native` are merged into `events.jsonl` only in the backtest
(`backtest_smt.py:1645`). Live has no `events.jsonl` writer.
**Recommendation (chosen):** live out_dir = `SESSIONS_DIR/<cme_session_date>` so the audit JSONL
+ snapshots land in the live session folder next to `comments.md`
(`automation/main.py:1155`). At `on_session_end`, after `finalize_deterministic`, dump the
sorted `events_native` to `<session>/ai_events.jsonl` (a NEW file, `source:"ai-decisions"`
lines) rather than touching any strategy output — keeps live strategy artifacts byte-identical
and gives session-analysis a native AI event stream. The `outcome` slots stay null (Phase-4
annotation is out of scope).

### D-F — contention + failure containment on the live box
**Finding:** worker thread is a daemon (`async_wrapper.py:44`), never-raises
(`:71-72`), submit is non-blocking; engine never-raises (`engine.py:160-162,215-217`);
`_emit_with_ai_decisions`/`_ai_decisions_on_bar` already swallow all exceptions
(`session_pipeline.py:980,1007`). API timeout + failsafe (NEUTRAL/LOW) live in `run_agent`
(unchanged). Flag OFF ⇒ dispatcher never constructs the worker ⇒ zero code path.
**Recommendation (chosen):** no new threading knobs. Add a single bounded
`SHUTDOWN_TIMEOUT` (config, default 8.0 s) for session-end `close`. Keep the daemon thread so a
crashed session can never be blocked by the worker. Document (no code) that the real-API
contention check on the 16 GB box is the Phase-4 supervised smoke, not this slice.

## Phase 1 — Worker as the backtest execution path + determinism (Wave 1)

### Tasks
**W1-T1 — Worker finalize/lifecycle helpers (C2, C3).** In `agent/decisions/async_wrapper.py`:
- `note_hypothesis_superseded(self, new_hyp_id, now=None)`: keep setting `_current_hyp_id`;
  additionally `self._supersede_log.append((now, new_hyp_id))` (init `_supersede_log=[]` and a
  `_submit_log=[]` in `__init__`). `submit_hypothesis_trigger` appends `(now, hid)` to
  `_submit_log` (its own boundary) before enqueuing.
- `finalize_deterministic(self, session_parquet=None)`:
  1. `self.drain()` (unbounded).
  2. Recompute `discarded`: for each trigger record in `self.engine.records`, clear any prior
     `"; discarded-stale"` and set it iff a boundary (from `_submit_log` ∪ `_supersede_log`)
     has logical time strictly after the record's `trigger_ts` and `<= arrival_ts` and is a
     *different* hypothesis id. Rebuild `self.discarded` from that.
  3. Sort `self.engine.events_native` in place by `(arrival_ts, trigger_ts, kind)`.
  4. Read the audit JSONL (`read_audit_records`), sort by `(arrival_ts, trigger_ts,
     trigger_kind)`, rewrite the file atomically (write temp, replace).
  5. `self.engine.finalize(session_parquet)`.
- `close(self, timeout, session_parquet=None)`: `drain(timeout)` (bounded, returns bool);
  `finalize_deterministic(session_parquet)`; `shutdown(timeout)`. Never raises (wrap body in
  try/except appending to `self.errors`; `finally: self._stop.set()` so the thread always dies).
- Expose read-through props the callers need: `events_native` → `self.engine.events_native`,
  `records` → `self.engine.records`, `audit_path` → `self.engine.audit_path`.

## HOLES (adversarial: requirement-vs-code conflicts, risky assumptions)

- **H1 — determinism is the whole risk, and it rests on the finalize recompute (D-B(4)).** If
  the recompute's timeline model diverges from the live wall-clock `discarded` semantics, the
  backtest and live disagree on which decisions were stale. Mitigation: the recompute mirrors the
  documented arrival model (`prod-agent.md:84-85`, `async_wrapper.py:10-12`) and is covered by a
  5×-repeat determinism test (W1-Tt2/Tt5). **This is the one place to review hardest.**
- **H2 — `note_hypothesis_superseded` signature change** (adds `now=`) touches the existing
  worker unit tests (`test_async_wrapper.py:57`). Keep `now` optional/defaulted so the live
  wall-clock path and old tests still pass; only the backtest recompute reads `_supersede_log`.
- **H3 — two live entry points.** `automation/main.py` (real orders) and `signal_smt.py` (human
  signal) both build `SessionPipeline` with no `ai_decisions=`. This slice wires only
  `automation/main.py` (D-C/W2-T4). If the user expects the signal process to log AI decisions
  too, that is an explicit added scope (three identical edits).
- **H4 — live has no `events.jsonl`.** The AI events-native have no existing live file to merge
  into (unlike backtest `:1645`). W2-T3 writes a NEW `ai_events.jsonl`; confirm session-analysis
  tooling can consume it (or that leaving it engine-audit-only is acceptable) — flagged, not
  assumed.
- **H5 — `_build_decision_worker` shared between backtest and live.** Importing `backtest_smt`
  into the live process pulls a heavy module. Recommend a thin `agent/decisions/live_factory.py`
  holding `_ai_decisions_enabled` + `_build_decision_worker` imported by both, so the live
  process doesn't import the backtest. (Backtest keeps its local wrappers or re-exports.)
- **H6 — frames immutability is an invariant, not a guarantee (D-A).** It holds today
  (loop rebuilds fresh per second) but a future live-loop change that mutates `today_mnq` in
  place would silently corrupt an in-flight snapshot. W3-T7 guard test pins the invariant; a code
  comment at the submit site states it.
- **H7 — multi-date backtest thread hygiene.** Each day builds+shuts down a worker (W1-T3). If
  `shutdown` is skipped on an exception path, threads leak across a long regression range.
  Mitigation: `close`/`shutdown` bodies use `finally: self._stop.set()`; the day-end block stays
  inside `try/except`.
- **H8 — checkpoint submits with the flag ON but stub can still be slow enough** to matter in a
  1s backtest? No — stub is ~instant; but the audit/snapshot **file writes** now happen on the
  worker thread concurrently with bar replay. Concurrent appends are serialized by the single
  worker thread (safe); the finalize rewrite is after `drain()` (no writer racing the reader).
