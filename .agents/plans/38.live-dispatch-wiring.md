# 38. Live dispatch wiring: the agent stack's entries, stops and exits reach the real dispatcher

🔴 Complex — small amounts of code on a path where every mistake is a real order. The
investigation below found things in the live path that contradict or sharpen the decisions
this plan was handed; read "FINDINGS" before any wave.

## Goal

Stage 3 directly: the L1/L2/L3 stack (Analyzer -> Planner -> Executor) owns the dispatcher
for a session, live, one contract. Entries, stop-losses and exits go out through the
existing signal kinds; `OrderSim` remains the brain's position model and the live side
MIRRORS its events. Stages 0-2 (shadow fixture, recorder-sink conformance, DISCONNECTED) are
SKIPPED by the user's decision; the first live session is therefore run as a deliberate
conformance test (Wave 4).

- **D24 (was Q8).** Stretch-override days trade live like any other day.
- **D25 (was Q9). NO NEW FLAG.** `ACT_TRADER_LIVE` is DELETED from this plan. In

      ACT_TRADER on (the default)  -> the AGENT owns the dispatcher; legacy is dark
      ACT_TRADER=0                 -> LEGACY owns it, exactly as today minus the observer

  Whether an order reaches the broker stays where it already is — `LIVE_TRADING` and
  `DISCONNECTED`, read by the legacy order module — so the existing flags compose into

      ACT_TRADER on, LIVE_TRADING=true                        LIVE
      ACT_TRADER=0                                            legacy (the rollback)

  **THE CONSEQUENCE, stated so nobody is surprised:** once this merges, the NEXT
  orchestrator start trades with the agent BY DEFAULT. The "agent observes while legacy
  trades" mode no longer exists in the live process. Scope is `automation/main.py` only:
  `SessionPipeline`'s default, `signal_smt.py`, `backtest_smt.py`, `regression.py` and
  `run_replay` are untouched, so the locked legacy regression baselines stay valid.

- **D26 (was Q3, F5). NO PRE-CLOSE RECONCILE ON AGENT CLOSES in v1.** The synchronous
  reconcile delays every `market-close` by a headed-browser Tradovate login (seconds, each
  step bounded at 15 s). The user does not want an exit order delayed. Every agent
  `market-close` carries `skip_recon: true`, and `dispatch` skips `_reconcile_on_close` for
  it — ONE conditional in the legacy order module; legacy closes are untouched.

  **Why this is safe for the agent when it was not for legacy.** GIL-42 exists because
  legacy ASSUMES a broker stop fired and sends NOTHING, so a phantom leaves the strategy
  flat and the broker long, and the next entry stacks. The agent sends a REAL PMT flatten
  on EVERY exit, so its state and the broker's converge at each close whatever the feed
  printed. And a PMT `close` against an already-flat account is not a novel act: it is the
  legacy CANCEL mechanism — `cancel_stop_entry` is "gated on no-open-position" and sends
  exactly that (`live_orders.py:586-594`, `:662-671`). It also clears any leftover working
  stop, which is wanted after a take-profit.

  **What is given up, stated.** No broker-truth check at the close. If the broker's stop
  fires on a Tradovate print the IB feed never showed, the agent manages a position that
  no longer exists until its own exit, then sends a harmless close. It cannot stack (it
  will not enter while it believes it holds), but its recorded P&L for that trade is wrong
  and the post-session diff cannot see it — only the broker statement can. The GIL-36
  POST-ENTRY verify is unaffected: it is asynchronous and delays nothing.

  **What this DELETES from the plan:** F4's double-tap (with no reconcile, a close against
  a flat `position.json` simply sends the flatten); the `adopt` / `resize` /
  `suppress_close` branches of D10 for agent closes (they can no longer occur); and D6's
  reconcile reasoning (moot — the close always goes out). D10 reduces to what
  `position.json` shows: a manual `trade.py` change, the GIL-36 thread clearing `active`
  or moving the stop, a restart.
- **D27 (model backend, confirmed).** Live runs OpenRouter with
  `anthropic/claude-haiku-4.5` — `DEFAULT_MODELS["openrouter"]` (`run_agent.py:86-88`), so
  `ACT_TRADER_BACKEND` and `ACT_TRADER_MODEL` both stay UNSET. With both keys present,
  auto-select prefers OpenRouter (`run_agent.py:512`); `ANTHROPIC_API_KEY` need not be

  the ANTHROPIC route (`claude-haiku-4-5`, same model, different route, different cache
  key). The post-session replay must therefore be served the LIVE thesis from
  `thesis_state.json` (as gate 2 does), never re-called and never looked up in the cache.

## FINDINGS — what the code says that the decisions did not

**F1 — Live and replay hand the Executor DIFFERENT bar shapes, and `OrderSim` reads the
difference.** Replay's MNQ partial-minute row carries RAW per-second High/Low
(`backtest_smt.py:1690`, reproduced and explained at `agent/study/entries.py:615-622`:
cumulative extremes are a basis "the mechanisms were never calibrated against"). Live's row
is CUMULATIVE for the minute (`data/ib_realtime.py:608-614` `_update_partial_1m`, handed
over at `:765` and `automation/main.py:199-211`). `OrderSim.on_bar` tests stop/TP on that
row's High/Low (`order_sim.py:92-111`) and `now_mid` prices §6's market fill off it
(`executor.py:229-241`). Live, a §6 tick-path fill mid-minute (09:44:01, 09:55:04, 10:03:05
in the recorded runs) is followed one second later by a stop test against a Low printed
BEFORE the fill. Gate 2 never saw this: its cycle-1 fixture predates the fill model. D2's
"agree by construction" is FALSE until this is fixed. -> tasks 1.7 and 2.7.

**F2 — `position.json["active"]["contracts"]` is hard-coded to 2** (`live_orders.py:379`,
`:553`) regardless of `TRADING_CONTRACTS`. With 1 contract at the broker,
`decide_correction` returns `resize` on EVERY close (`recon_on_close.py:81-83`). Under D10
as worded that kills the plan after the first trade of every session. -> D18 (fix at source).

**F3 — `TraderGraft.on_bar` swallows every exception itself** (`graft.py:112-117`), and the
Executor swallows order-book failures into `_state["order_error"]`
(`executor.py:393-399`). So the `except Exception: pass` in `session_pipeline.py` that D11
names never sees anything. D11 needs a health surface on the graft, polled from outside.
-> tasks 1.5 and 2.4.

**F4 (NEUTRALISED for agent closes by D26 — kept as the record of why) — A
`market-close` dispatched while `position.json` is FLAT cannot close a broker
position — it ADOPTS it** (`recon_on_close.py:53-63` returns `adopt`; `_apply` returns
True; `dispatch` then suppresses the close, `live_orders.py:810-813`). Every fail-closed
path where the sim was voided but the broker may still hold needs TWO dispatches: the first
adopts, the second (strategy-holds + broker-holds -> `noop`) closes. -> task 2.5.

**F5 (RESOLVED by D26: agent closes skip it) — The reconcile runs a headed-Chromium
Tradovate login SYNCHRONOUSLY before every
close**, bounded at 15 s (`broker_state.py` `_PAGE_TIMEOUT_MS = 15_000`;
`live_orders.py:168-186`). Under D6(c) the agent's `market-close` IS the real stop for
entries whose stop is under 10 pts, so that stop executes seconds-to-15 s late and the bar
loop is blocked meanwhile. -> D26: agent closes skip it.

**F6 — The Analyzer RESTORES its thesis from `thesis_state.json` on construction**
(`analyzer.py:196-219`) and `plan_id` hashes `now` (`planner.py` `_plan_id`). A mid-session
restart therefore re-derives a NEW plan with `attempts_used=0` and no position on the next
bar close — silently. `plans.json` (`plan_store.py`) already persisted the first plan,
which is the detector D10 needs. -> task 1.4.

**F7 — `artifact_id` is not unique per trade.** `_enter_by_market` sets
`artifact_id = fire.get("gap_id") or mechanism` (`executor.py:1507`), so every §7 and
`tmso_reject` fill in a session carries the same id. D13's key
`(plan_id, mechanism, artifact_id, kind)` would SUPPRESS the session's second legitimate
§7 entry and its close. The key must carry a per-event sequence. -> task 1.2.

**F8 — The dispatcher can refuse an entry AFTER the sim has booked the fill**:
`is_paused()` (`live_orders.py:746`), the `recon_suppress_force_entry` sentinel
(`:786-792`), and the PMT window gate returning before `position.json` is written
(`:544-546`). Each is a phantom fill by construction. The PMT POST itself is
fire-and-forget on a pool (`pickmytrade.py:194-196`), so an HTTP failure is invisible until
the close. -> the ack in task 2.2. (`session_times.is_entry_allowed` is an always-True shim
today, `:50-60`, and the 15:30-16:55 block is outside our window, so the window gate is
inert in practice.)

**F9 — Two asynchronous writers change `position.json` behind the agent.** The GIL-36
post-entry reconcile thread can clear `active` on `ENTRY_REJECTED` (`reconcile.py`
`_clear_position_to_flat`) or move `active.stop` on `SL_REJECTED`; a manual `trade.py`
close runs in ANOTHER PROCESS, so `dispatch`'s module globals never see it.
`position.json` is therefore the only rendezvous — D10's detector is a per-bar watchdog on
it, outside `agent/`. `adopt` is identifiable by `active["source"] == "recon-adopt"`
(`recon_on_close.py:186`). -> task 2.3.

**F10 — `_emit` prints `json.dumps(sig)` BEFORE dispatching** (`live_emit.py`;
`automation/main.py:1183-1185`). A signal carrying a `pd.Timestamp` raises and the order is
never sent. Signals must be plain floats and ISO strings, ASCII only (the orchestrator's
stdout is cp1252). -> task 2.2.

**F11 — Live has no 13:00.** The window is a REPLAY construct (`replay.py:50-67`); live,
the graft runs the whole CME session, and a live plan would keep entering after 13:00 the
day D15(b) is dropped. D8 needs a bar-time window end IN THE EXECUTOR. Replay's last bar is
12:59:59, so a rule firing at `now >= 13:00:00` is unreachable there and replay stays
byte-identical. -> task 1.3.

**F12 — `_build_trader` degrades to `None` silently** (`automation/main.py:1009-1034`).
Harmless while the trader only observed; with legacy dark it means NOTHING trades and
nothing says so. And the live backend defaults to `openrouter` (`:1030`) while every replay
and every warm cache in this cycle used `anthropic`. -> tasks 2.6, 2.6b; D20, D21.

**F13 —** `_pending_close_after` CAN swallow a `market-close` for 3 s
(`live_orders.py:800-808`) but is armed only by the cancel-stop-entry kind (`:907-908`),
which the agent never emits and the dark legacy brain cannot. Unreachable; pinned by test.

**F14 —** A `stopped-out` kind exists (`live_orders.py:913+`) that reconciles and clears
state WITHOUT sending a close. Not used: on a phantom stop it ADOPTS (the broker's view
wins and the position is left unmanaged); `market-close` closes it (the agent's view wins),
which is what D5/D6 want.

**F15 — CONFIRMED as stated.** Gap-fill, the 1s merge and parquet-check are
orchestrator-level; `orchestrator/main.py:58-74` reads `position.json["active"]`, which
`place_market_entry` writes itself (`live_orders.py:547-566`); `_on_bar`'s own
session-close block (`automation/main.py:166-176`) is a further backstop.
`on_session_start` still runs the full legacy startup under `trader_only` (daily, SMT
warm-up, first hypothesis, `session_pipeline.py:726-800`) — and it MUST, because
`_daily_triggered` gates the trader hook (`:1081`, set at `:776`). It emits
hypothesis-level signals only. `FORCE_RESET=true` wipes `position.json` there (`:790-792`).

**F16 —** D15(a) is already true by construction: the only positive close is
`take_profit`, and `_death` evaluates `target_reached` on the same bar, after
`_drive_orders` (`executor.py:578-585`; call order at `:262` then `:269`). A stop is never
trailed, so `stop_out` is always adverse. The guard is still written explicitly.
