### 11.5 CANDIDATE — the UNRELATED pre-move path (plan 46, 2026-09-30)

**Not a rule.** An L1-side direction override (plan 37's seam, `analyzer._call`) plus a
take-profit substitution at the fill (`executor._set_target_on_fill`). Neither lives in
§§2-8; entries, stops and the §8 lifecycle are untouched. Flag
`agent/trader/premove_context.UNRELATED_PATH_MODE`, default `"off"`.

**Definitions** (MNQ decides; bars strictly before 09:20 ET):
- *Leg* — the current leg of a high/low zigzag on 1m bars from the 18:00 ET session open to
  09:19, reversal threshold 120 pts x (09:19 close / 29000). Origin A, extreme E, size |E-A|.
- *Big* — size >= 1.14% of the 09:19 close (330 pts at 29000).
- *PART* — a zigzag on 5m bars over the previous 15 calendar days to 09:19, threshold
  0.5 x size: its current leg has the leg's direction, starts before today's 18:00 open, and
  is >= 1.25 x size.
- *UNRELATED* — big and not PART.

**Proposed behaviour.** UNRELATED: force the thesis AGAINST the leg, no model call
(`thesis_source: "premove_unrelated"`). PART: never force; plan 37 arm 1 is suppressed and
the model decides. Not big / unclassifiable: exactly today's path (arm 1, then the model).
On an UNRELATED plan, the take-profit at each fill is (A + the leg's extreme up to that
fill) / 2, fixed for that position; reaching it kills the plan like any T2 (`target_reached`).

**Evidence** (`<global>/studies/premove_mid_retrace/context.md`, 74 big days
2024-01..2026-09, report/half days excluded, auto outcome = `smt_cont.resolve`):

| context | n | 09:30 counter-move reached the leg mid |
|---|---|---|
| UNRELATED | 43 | 56% [41-70] (recent 63% n=19, older 50% n=24) |
| PART | 27 | 33% [19-52] |
| COUNTER (20-session extreme, NOT built) | 4 | 75% |

A mechanical fade to the mid on ALL big legs was ~break-even (`phase1_target.md`); this is

## 2. Design decision: how the path relates to plan 37 arm 1

**Recommended: (c) a separate path that takes precedence over arm 1 on big days only.**

| Classifier status (flag `on`) | What happens |
|---|---|
| `UNRELATED` | Force against the leg (new thesis), with the mid target |
| `PART` | Arm 1 is SUPPRESSED; the model decides |
| `NOT_BIG` / `NO_LEG` / `UNKNOWN` / raised | Exactly today's path: `_override_thesis` (arm 1), then the model |

Reasons:
- Non-big days must keep their behaviour, which today includes arm 1 (fires on about 26% of all days). Option (a), replacing arm 1, would change non-big days and break the control set's byte-identity.
- Option (b), an extra gate on top of arm 1, would lose 06-29, 07-21 and 08-25: UNRELATED days with an age over 30, where arm 1 never fires.
- (c) makes the A/B decomposable. On the six replayable UNRELATED days where arm 1 already forces the same way (05-18, 06-08, 06-09, 07-23, 07-30, 09-01), only the target changes. On 06-29, 07-21 and 08-25 both the direction and the target change.
- Option (a) stays reachable as an optional harness arm C via a new module constant `stretch_override.ARM1_ENABLED = True` (read at call time; default True, so behaviour is unchanged).

**`shadow` mode.** The classifier runs and writes `premove_context.json`, but nothing changes. Live evidence at no risk. Enabling it is the operator's call; the default is `off`.

**T1. `agent/trader/premove_context.py`, a pure classifier ⚠️**

Lives in `agent/trader/` so that `test_gate_no_legacy_writes.py` scans it and the default suite runs its tests.

```python
UNRELATED_PATH_MODE = "off"          # "off" | "shadow" | "on"; read at CALL time (module attr)

@dataclass(frozen=True)
class PremoveParams:
    cut_pts_at_ref: float = 120.0    # 1m leg zigzag reversal, scaled by px / ref_price
    ref_price: float = 29000.0
    big_pct: float = 1.14            # size / px_0919 * 100 >= big_pct
    history_days: float = 15.0       # 5m window = [D - history_days, 09:20)
    history_slack_days: float = 3.0  # frame must start <= window start + slack, else UNKNOWN
    part_k: float = 0.5              # 5m zigzag threshold = part_k * size
    part_mult: float = 1.25          # big-scale leg >= part_mult * size
    session_open_hours_before: float = 6.0   # D 00:00 - 6h = 18:00 ET prior day
    boundary_hhmm: tuple = (9, 20)
    mid_min_ahead_pts: float = 5.0   # executor fallback floor (see §11.5 Q3)
    ticker: str = "MNQ"

DEFAULT_PARAMS = PremoveParams()

@dataclass(frozen=True)
class PremoveContext:
    status: str        # "UNRELATED" | "PART" | "NOT_BIG" | "NO_LEG" | "UNKNOWN"
    reason: str
    leg_direction: str | None; origin: float | None; origin_ts; extreme; extreme_ts
    size: float | None; size_pct: float | None; px_0919: float | None; cut_pts: float | None
    big_direction; big_origin_ts; big_extreme_ts; big_size
    boundary: pd.Timestamp | None; params: dict
    def forced_direction(self) -> str | None   # opposite of leg_direction iff UNRELATED
    def mid_at_boundary(self) -> float | None  # (origin + extreme) / 2
    def to_dict(self) -> dict                  # JSON-safe (isoformat timestamps)

def leg_zigzag(frame, thr)       # exact port of studies/.../build.leg_zigzag
def pivots_zigzag(frame, thr)    # exact port of studies/.../context.pivots_zigzag
def classify(mnq_1m: pd.DataFrame, now: pd.Timestamp, params=DEFAULT_PARAMS) -> PremoveContext  # never raises
def leg_mid(origin: float, extreme: float) -> float
def extend_extreme(leg_direction: str, extreme: float, highs_or_lows) -> float  # max for UP, min for DOWN
```

Rules for `classify` (must reproduce the study exactly):
- **Input handling.**
  - Accept capitalised or lower-case OHLC columns.
  - De-duplicate the index, keeping the last row.
  - `D = now.normalize()`, `boundary = D + 09:20`.
  - If `now < boundary`, return `UNKNOWN("armed before boundary")`.
- **Leg frame.** `pre = rows in [D - 6h, boundary)`.
  - Require a 09:19 bar, else `UNKNOWN` (matches the study's `T(9,19) in index` skip).
  - `px = pre.close[-1]`.
  - `z = leg_zigzag(pre, 120 * px / 29000)`; if `z` is None, return `NO_LEG`.
- **Big test.** If `size / px * 100 < 1.14`, return `NOT_BIG` (the record still carries the leg).
- **5m frame.** `hist = frame[[D - 15d, boundary)]`.
  - Require `frame.index[0] <= D - 15d + slack`, else `UNKNOWN("history <N> d")` (the replay-before-05-17 case).
  - `resample("5min").agg(first/max/min/last).dropna()`: left-labelled, midnight/18:00-aligned, as in the study.
- **PART test.**
  - `piv = pivots_zigzag(hist5, 0.5 * size)`. If `len(piv) < 3`, return `UNKNOWN` (the study's `"?"`).
  - `cur_o, cur_e = piv[-2], piv[-1]`.
  - PART iff `dir(cur) == leg dir`, `cur_o.ts < D - 6h` and `|cur_e - cur_o| >= 1.25 * size`. Otherwise UNRELATED.
  - **No COUNTER branch.** The study's COUNTER days (07-30 and three older ones) map to UNRELATED; documented in the module docstring and in §11.5 Q2.
- **Purity.** No I/O, no wall clock (`get_et_now`, `datetime.now` and `Timestamp.now` banned), MNQ frame only.

  Otherwise `mid = leg_mid(origin, self._pm_ext)`, `entry = self._sim.position["entry"]`:

- **After the mid:** `_death` → `target_reached` kills the plan, exactly as T2 does.
- **A second fill** (after a stop-out) recomputes the mid with the extension up to that fill; fixed per position, as T2 is re-picked per fill.

## 5. Tuning and evaluation harness: `scripts/ab_premove_unrelated.py`

Pattern: `ab_micro_smt.py` — one process, arms replayed SEQUENTIALLY (memory budget), flags flipped as module attributes (`premove_context.UNRELATED_PATH_MODE`, `DEFAULT_PARAMS`, `stretch_override.ARM1_ENABLED`). Rows appended to `.agents/ab_premove_unrelated.jsonl`, with `--resume`; `--regression-dir` sets `ACT_REGRESSION_DIR`.

**Arms:** A = `off` (today); B = `on`; C (optional, `--arm-c`) = `on` plus `ARM1_ENABLED=False` (option (a)); **D (`--arm-d`, run by default in the final A/B) = `on`, but on days that have an operator leg start the leg ORIGIN is the operator's.**

**Arm D (operator decision 2026-09-30).** The mid target depends on the leg origin, and the automatic 120-pt leg often starts earlier than the operator's (2026-07-23: auto origin 05:03 → mid 28896.9, the 09:43 bounce topped at 28883.75 and misses by 13 pts; the operator's 07:00 origin → mid hit). Arm D isolates that effect:
- Source: `<global>/studies/premove_mid_retrace/operator_labels.json` (exported from the labelling page; `labels[date].leg_start` = ET HH:MM on the raw front-month chart; 07-23 = "07:00" from the operator's chat). Read-only.
- Mechanism: a harness-only override, e.g. `premove_context.LEG_START_OVERRIDES: dict[str, str] = {}` (date → "HH:MM"), read at call time by `classify`; when today's date is present, the origin is the bar at that minute (its High for a DOWN leg, Low for an UP leg) and the extreme is re-taken from that bar to 09:19 in the same direction, exactly like the labelling page's `customLeg`. Status (big/PART/UNRELATED) is still computed; record `origin_source: "operator"` in `premove_context.json`. Default `{}` → production behaviour byte-identical; a unit test proves `{}` changes nothing and one proves the override moves the origin/mid.
- Days where it changes anything among the replayable set: 06-08 (01:48), 07-23 (07:00), 09-01 (03:28), 09-17 (02:01, PART — expected no change) — i.e. thin; report per day B vs D (mid price, mid hit, P&L).
- The offline sweep also reports mid-reach with operator origins on every labelled day (all 39 labels, not only replayable ones).

**Modes**
- **`--preflight`**: replays A on each date with `allow_calls=False`, catches `NetworkCallRefused`, prints the dates that need `--seed` with their recorded token usage.
- **`--seed-missing`**: seeds A only on the listed dates; requires `--yes` and prints the list first.
- **`--dates` / `--big-days` / `--controls`**: `--big-days` classifies every date with 1s coverage using the replay era's 1m parquet (`_main_dir_for_date`) and keeps the big ones. Report/half days are excluded by a hard-coded operator list: 2026-07-03, 2026-08-12, 2026-09-10, 2026-03-06.
- **Per-day output:** date, era, classifier status (from B's `premove_context.json`) vs the offline 1m-parquet status (parity flag), leg direction/size/A/E, and per arm: `thesis_source`, direction, n trades, attempts, P&L pts; target level at each fill; `mid_hit` (plan_dead `target_reached` with level `premove_leg_mid`); first entry time. Aggregates: ΣA, ΣB, Δ (overall, UNRELATED-only, and split "target-only" vs "direction+target"), controls byte-identical or not.
- **Control check:** for every non-big control date and every PART date where arm 1 does not fire, assert `trader_decisions.jsonl`, `plans.json` and `thesis_state.json` are identical across A and B. Any difference fails the run loudly.
- **`--arm-d`** adds arm D on every date where `operator_labels.json` has a `leg_start` (others: D = B, not re-run).
- **`--offline-sweep`**: no replays. Production classifier on `main/2026-12` 1m data over the 692-day list (`studies/premove_last_moment_direction/days.csv`), with a copied `resolve` outcome (provenance noted). Per cell: n UNRELATED/PART and the mid-reach rate, recent/older. At the defaults it must reproduce `context.md` (COUNTER folded into UNRELATED).
- **`--sweep` (replay sweep):** grid cut {90, 120, 150} × big% {1.0, 1.14, 1.3} × k {0.4, 0.5, 0.6} × mult {1.0, 1.25, 1.5}. Per cell, each date's decision key is `(status, A, E)` for UNRELATED, `"PART"`, or `"baseline"`; replay only keys not already in the jsonl, assemble each cell's P&L from cached per-key runs (~30-60 unique replays). DESCRIPTIVE ONLY — the verdict is taken on the pre-registered defaults.
