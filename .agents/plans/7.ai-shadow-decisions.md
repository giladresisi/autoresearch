# 7. AI Shadow-Decisions Module (GIL-44 Phase 3, step 1) 🔴 Complex

> **Source of truth for scope:** `prod-agent.md` Phase 3 (shadow / gate-OFF). This plan builds the
> **first slice**: an AI decision module that runs ALONGSIDE the hypothesis engine at the same
> triggers, LOGS paired records (hypothesis said X, AI said Y, price did Z), and changes NOTHING
> about trades/P&L. Flag-gated, default OFF. It does **not** build the entry gate (that is the rest
> of Phase 3) and does **not** run calibration (Phase 4).
>
> **You implement NOTHING from this file** unless you are the executing agent. This is a plan.
>
> **Repo discipline (non-negotiable):** flag-gated default OFF · 1s A/B byte-identical with flag OFF
> · trades byte-identical with flag ON · unit tests per component · production library paths are
> silent (structured logging only, no prints) · API keys from `.env` via the existing loader, never
> written/echoed · this stays on branch `autoresearch/strategy-agent-poc`; no commits/push unless the
> user asks.

Goal: extract importable cores WITHOUT changing any existing output. This is pure refactor; the
gate is *identity*.

### Wave 1.1 — `derive_facts` → library (`agent/derive_facts.py`)
**Provides to 1.2/Phase 2:** a pure `compute_facts(mnq_df, mes_df, *, ath_mnq, ath_mes, hist_mnq,

- **T1.1a** Extract every inline computation in `main()` (`derive_facts.py:183-490`) into a

- **T1.1b** `render_facts_text(bundle)` reproduces the exact print output; `main()` becomes

- **T1.1c** `facts_to_validator_dict(bundle)` — the JSON view the semantic validator + audit consume

**Test cases (`agent/test_derive_facts_lib.py`):**
1. *golden text identity* — `render_facts_text(compute_facts(<burned POC cut slices>))` byte-equals

2. *validator-dict parity* — `facts_to_validator_dict(bundle)` `levels`/`now_price`/`checkpoint`

3. *empty/short slice* — `compute_facts` on a <1000-bar stub raises no exception and truncates the

4. *no-ATH path* — `ath=None` omits the ATH line, no crash (edge).
5. *checkpoint truncation* — data after `now` never enters the bundle (no-lookahead precondition).

## PHASE 2 — Shadow module core (offline, pure, no pipeline yet)

New package `agent/shadow/` (importable, silent, side-effect-free except its own cache/audit files).

### Interface contract this phase must satisfy (consumed by Phase 3)
```
ShadowEngine(config, backend, docs_root, out_dir, cache_dir)
  .on_checkpoint(now, frames) -> None          # recompute + persist standing daily-trend
  .on_hypothesis_trigger(now, frames, hyp_event, trigger_kind) -> ShadowRecord
  .standing_daily_trend -> dict                # consumed by next-move calls
  .flush() / .finalize(session_parquet) -> None
frames := {mnq_today, mes_today, hist_mnq, hist_mes, hist_1hr, hist_4hr, ath_mnq, ath_mes, now}
```
`frames` are the pipeline's **live rolling frames** (`today_mnq`, `self._hist_mnq_1m`, …) — **no
parquet re-reads** (`prod-agent.md` Phase-3 facts module). See HOLE H1 for the
recompute-vs-reuse-engine-state decision.

### Wave 2.1 — Online facts adapter (`agent/shadow/facts_adapter.py`)
**Requires from 1.1:** `compute_facts`, `render_facts_text`, `facts_to_validator_dict`.
**Provides:** `build_snapshot(frames, *, checkpoint=None) -> Snapshot{text, validator_dict,
content_hash, max_ts}` — feeds `compute_facts` from the live frames (not slices), optionally
truncating at a checkpoint timestamp, and computes a stable `content_hash` (sha256 of the canonical
JSON view) used as the replay-cache key and drift detector.

- **T2.1a** Adapt live frames to `compute_facts` inputs (the frames are already 1m/1s OHLC with the
  same columns `derive_facts.load` produces after `str.lower`; align column casing + tz).
- **T2.1b** Checkpoint truncation: for daily-trend, drop bars after the checkpoint (`prod-agent.md`:
  "facts truncated at the checkpoint even if invoked later").
- **T2.1c** `content_hash` over the canonical JSON (sorted keys) — deterministic; the same trigger +
  same facts always hashes identically.

**Test cases (`agent/shadow/test_facts_adapter.py`):**
1. *frame-vs-slice parity* — snapshot text from live frames byte-equals `render_facts_text` from the
   equivalent parquet slices for a known bar (happy path; this is the core correctness claim).
2. *checkpoint truncation* — a snapshot at checkpoint C contains no bar `> C` even when `now > C`
   (no-lookahead).
3. *hash stability* — identical frames → identical `content_hash`; a one-bar change → different hash
   (drift-detector edge).
4. *empty MES frame* — 1s-mode empty `mes_1m_today` at session open handled (edge, matches
   `backtest_smt.py:1336`).

### Wave 2.2 — No-lookahead guard (`agent/shadow/guard.py`)
**Provides:** `assert_no_lookahead(snapshot, trigger_ts)` — raises `LookaheadError` if
`snapshot.max_ts > trigger_ts`. Called before every LLM call; a violation **kills the call loudly**
(the record is written with `error="lookahead"`, the decision discarded).

**Test cases (`agent/shadow/test_guard.py`):**
1. *clean snapshot passes* (happy path).
2. *poisoned future bar* — inject a bar at `trigger_ts + 1s` → guard raises (the mandated
   poison-test).
3. *exact-boundary bar* — a bar at exactly `trigger_ts` passes (`<=`, off-by-one edge).

### Wave 2.3 — Decision core + standing daily-trend (`agent/shadow/engine.py`)
**Requires:** 1.2 `decide`/call-core, 2.1 snapshots, 2.2 guard, replay cache (2.4).
**Provides:** the `ShadowEngine` above. `on_checkpoint` runs the daily-trend call (checkpoint-truncated
facts) and stores `standing_daily_trend`. `on_hypothesis_trigger` runs the next-move call consuming
`standing_daily_trend`, both via the Phase-1 `decide` core. Churn guard (`SHADOW_CHURN_GUARD`): when
ON, suppress a re-decision if no new fresh event since the last call (production-faithful); when OFF
(compare mode), always decide. See HOLE H7 — with hypothesis-formation as the trigger, churn is
largely inherent.

- **T2.3a** Two-call orchestration reusing `decide` (daily-trend already standing → pass it as the
  next-move's standing input, exactly as `run_agent.run_cut:594-601`).
- **T2.3b** Failsafe: any exception / guard-kill / repeated-invalid → `failsafe_decision()` block,
  recorded with the reason; never raises into the pipeline.
- **T2.3c** Build the `ShadowRecord` (see 2.5 schema) and the paired diff (Field-mapping table).

**Test cases (`agent/shadow/test_engine.py`):**
1. *checkpoint then trigger* — `on_checkpoint` sets standing; a subsequent `on_hypothesis_trigger`
   consumes it; record carries both (happy path).
2. *trigger before any checkpoint* — next-move runs against a neutral/low standing default (edge:
   pre-06:00 formation).
3. *guard-kill path* — poisoned snapshot → record `error="lookahead"`, no API call, engine returns
   cleanly (error path / async cleanup analogue — must run in a `finally`).
4. *failsafe path* — stub backend forces failsafe → record `verdict="failsafe"`, decision = NEUTRAL/LOW.
5. *churn guard ON* — second trigger with no new event → standing decision returned, no new API call
   (config path).

### Wave 2.4 — Replay cache (`agent/shadow/cache.py`)
**Provides:** content-addressed cache keyed by `(trigger_kind, content_hash)` → the cached raw LLM
outputs, so re-running the same regression day replays deterministically with **no API spend and no
re-sampling**. A cache **miss on an unchanged trigger is itself a drift signal** (facts changed →
hash changed) and is logged.

**Test cases (`agent/shadow/test_cache.py`):**
1. *miss then hit* — first call populates, second identical `(trigger,hash)` returns cached, zero
   backend calls (happy path).
2. *hash change → miss* — a changed snapshot re-calls and logs a drift note (drift-detector edge).
3. *corrupt cache entry* — unreadable/partial file → treated as miss, not a crash (error path).
4. *concurrent write* — two processes writing the same key don't corrupt (atomic temp-write+rename;
   concurrency edge).

### Wave 2.5 — Audit + dual-event records (`agent/shadow/records.py`)
**Provides:** two writers.
- **(a) events-native:** AI decisions rendered into the SAME event shapes hypothesis outputs use
  (a `new-hypothesis`-shaped dict + a `daily-trend`-shaped dict), **marked** `"source":"ai-shadow"`,
  so existing analysis/plot/replay tooling reads them natively. Emitted into `events.jsonl` **only
  when the flag is ON** (see the A/B tension, HOLE H10).
- **(b) AI-only audit JSONL** (`shadow_audit.jsonl`): one record per call —
  `{trigger_ts, arrival_ts, trigger_kind, facts_content_hash, facts_snapshot_ref (path or inline),
  rendered_prompt_ref, standing_daily_trend_superseded, attempts[] (each: violations, retries,
  raw_text, usage, latency), reasoning, decision (daily_trend+next_move), paired_diff (vs hypothesis
  event), verdict, fallback, error, outcome: null}`. The `outcome` slot is filled by the Phase-4
  annotation job. Designed from day one for the future evals/self-improvement loop.

**Test cases (`agent/shadow/test_records.py`):**
1. *round-trip* — a written audit record reloads and validates against the record schema (happy path).
2. *events-native shape* — the AI `new-hypothesis`-shaped event carries every key the real event has
   plus `source:"ai-shadow"` (compat path).
3. *snapshot ref vs inline* — large snapshot stored as file+hash, small inline; both re-resolve (edge).
4. *outcome slot empty on write, fillable later* (schema-evolution edge).

**Exit Phase 2:** all shadow unit tests green with the **stub backend** (no keys, no network); guard
+ cache + failsafe proven; nothing touches the pipeline yet.

## PHASE 3 — Backtest integration + latency emulation + flag

### Wave 3.1 — Pipeline hook (`session_pipeline.py`, `backtest_smt.py`)
**Contract:** `SessionPipeline.__init__` gains an optional `shadow=None` param. When `None` (flag
OFF) there is **zero** added work and **zero** state touched → byte-identical by construction. When
set, the pipeline calls:
- `shadow.on_hypothesis_trigger(now, frames, hyp_event, trigger_kind)` **immediately after** a
  `new-hypothesis` event is emitted — one shared helper wrapping the 5 emit sites (`:774, :800,
  :1178→emit, :1291, :1337, :1476`); simplest: a `self._on_new_hypothesis(evt)` chokepoint the emit
  sites already funnel through, or observe `_emit` for `kind=="new-hypothesis"`.
- `shadow.on_checkpoint(now, frames)` from `on_1m_bar` when a `SHADOW_CHECKPOINTS_ET` timestamp is
  first crossed this session.

`backtest_smt.py:1355` constructs `shadow` (reads `AI_SHADOW_ENABLED`/env) and passes it; `finalize`
runs at day end (Phase 4). The shadow decision is **never read back** into strategy logic.

### Wave 3.2 — Latency-arrival bookkeeping
The backtest loop is synchronous/single-threaded (no clock). Emulation is **bookkeeping**, not real
async: at trigger `T` the engine snapshots facts **frozen at T** (guarded), computes the decision
(cache-first), and stamps `arrival_ts = T + SHADOW_DECISION_LATENCY_SEC`. The record is evaluated /
compared **as of `arrival_ts`**; nothing in `(T, arrival_ts]` enters the facts. Express latency in
**seconds → arrival timestamp** (NOT "bars" — bar size differs 1s vs 1m; HOLE H5). In 1m mode the
arrival rounds to the containing 1m bar.

### Wave 3.3 — Flag gating + dual logging wiring
- Flag OFF ⇒ shadow not constructed ⇒ no AI events, no audit, no API, no state → **A/B byte-identical**.
- Flag ON ⇒ audit JSONL always written; events-native AI lines appended to `events.jsonl` (breaks the
  event byte-diff **by design** — resolved in Validation: ON asserts **trades** identical + the
  **non-AI event subsequence** unchanged; see HOLE H10).

**Test cases (`tests/test_shadow_integration.py`):**
1. *flag OFF no-op* — a short 1m regression day with `AI_SHADOW_ENABLED=False` yields events+trades
   byte-identical to the pre-integration baseline (the core safety claim).
2. *flag ON, stub backend, trades identical* — same day with flag ON + stub backend → `trades.tsv`
   byte-identical to baseline; `events.jsonl` differs only by `source:"ai-shadow"` lines (removing
   them re-yields the baseline).
3. *arrival stamping* — a trigger at `T` produces a record with `arrival_ts == T + latency`; the
   facts snapshot `max_ts <= T` (no-lookahead under latency).
4. *checkpoint firing* — the four ET checkpoints each fire exactly once per session; a day started
   mid-checkpoint fires only the crossed ones (edge).
5. *cancellation/short day* — a day that ends before 13:00 flushes cleanly, no dangling records
   (interruption / `finally`-cleanup edge).

**Exit Phase 3:** validations (1) and (2) below pass with the stub backend; real-API run deferred to
Phase 6 to avoid spend during dev.

## PHASE 4 — Outcome annotation + comparison + consistency check

### Wave 4.1 — End-of-session annotation job (`agent/shadow/annotate.py`)
Fills each record's `outcome` slot from bars **after `arrival_ts`** over the finished session
parquet. **Reuse the calibration truth-label logic** (`calibration/score_results.py`
MOVE_MIN/RATIO/DAY_MIN) so shadow outcomes are directly comparable to Phase-4 calibration ground
truth. Outcome captures: realized direction at horizon, whether `move_target` was reached before the
`flip_trigger`, MFE/MAE, and the hypothesis-vs-AI-vs-price verdict.

**Test cases:** (1) target-reached-first, (2) flip-fired-first, (3) neither within horizon (all
against a synthetic price path); (4) missing post-arrival bars (session end) → outcome `truncated`.

### Wave 4.2 — Comparison harness (`agent/shadow/compare.py`)
Produces the side-by-side table: per trigger, the hypothesis output vs the AI decision **as of

**Test cases:** (1) matching paths → zero drift; (2) an injected convention difference (e.g. week

## PHASE 5 — Live async wrapper (design + thin implementation)

`prod-agent.md` shadow "respects the contention prerequisite" (16 GB box, live 1s loop must not
block). Implement the interface so live wraps the SAME engine:
- **Worker thread:** `on_hypothesis_trigger`/`on_checkpoint` enqueue a job; a single worker computes
  off the 1s loop; the loop never blocks on the API.
- **Staleness guard:** when a job completes, if its triggering hypothesis is no longer standing
  (a newer `new-hypothesis`/`trend-broken` supervened), the record is written but **flagged
  discarded** (logged, not compared as live-actionable).
- **Real asynchrony = the same as the backtest's latency emulation** — arrival is when the worker
  finishes; the frozen-at-T facts are identical to backtest.

**Recommendation:** land the worker/queue + staleness interface and unit-test it with a fake clock;
**defer the supervised live smoke behind its own gate** (this slice is shadow-only and cannot lose
money, but live API contention on the trading box is a separate operational check). This mirrors the
GIL-36/42 "gate: run the smoke before the next orchestrator run" pattern.

**Test cases:** (1) job computed off-thread, loop returns immediately; (2) staleness: hypothesis
flips before completion → record flagged discarded; (3) worker exception → failsafe record, worker
survives (error/cleanup in `finally`); (4) shutdown drains/join the queue (cancellation).

## HOLES & OPEN DECISIONS (adversarial — read before implementing)

### Holes (requirement ↔ code conflicts / risks)

- **H1 — "reuse engine state" vs `prod-agent.md` "same computations from live frames" (DIRECT
  CONFLICT).** The task says the adapter should reuse live engine level maps / sweep+depletion / the
  GIL-25 latch and "compute only what the engine lacks." `prod-agent.md` Phase-3 facts module says
  the opposite: "**same computations fed from the live rolling frames** (no parquet re-reads)." The
  engine's representations are NOT 1:1 with `derive_facts` (its own `DEPLETE` table
  `derive_facts.py:41`, its week anchor `:63`, TWO fallback chain `:160`, FVG "visited" rule `:470`,
  maintenance-bar drop `:54` all differ from how the engine stores state via `_invalidated_target_names`
  / dynamic liquidities). Reusing engine state for SOME sections while `derive_facts` computes others
  guarantees drift exactly at the section boundaries — and the model was validated on the
  `derive_facts` text. **Recommendation: recompute via the Phase-1 `derive_facts` pure functions over
  the live frames** (satisfies "no parquet re-reads," guarantees the validated schema, makes the
  consistency check trivially green). Treat "reuse engine state" as a later CPU optimization, not this
  slice. **RESOLVED 2026-07-07 (user approved): recompute-from-frames. See D1.**

- **H4 — `derive_facts` is a print-only script, not importable.** All maths is inline in `main()`
  (`derive_facts.py:183-490`); `parse_facts` (the text→dict reverse) lives in
  `calibration/validate_results.py`, not `agent/`. Phase 1 must extract pure functions AND a JSON
  view that reproduces what `parse_facts` yields for the semantic validator, or the online semantic
  layer will diverge from the bench. Non-trivial; sequenced as a hard prerequisite (Wave 1.1).

- **H8 — "first slice" is actually most of the Phase-3 orchestrator.** To shadow next-move you need a
  standing daily-trend, which needs the 4 checkpoint triggers + standing state + a next-move trigger
  policy. That IS the deterministic state machine `prod-agent.md` Phase 3 describes (minus the entry
  gate). Scope is honest about this (the module is a mini-orchestrator) but the effort is larger than
  "a logging hook." If the user wants a truly minimal first cut, an option is **next-move-only at
  hypothesis triggers with a fixed neutral standing daily-trend** (drops Waves 2.3-checkpoint + the
  06:00/18:00 logic) — smaller, but the daily-trend/next-move alignment (the 87/35 conditioner) is
  then untested. **RESOLVED: full mini-orchestrator (D2).**

- **H10 — dual event logging vs the byte-identical A/B gate (TENSION).** Requirement (a) says emit AI
  decisions **into `events.jsonl`** so existing tooling sees them; the repo gate is a **line-by-line**
  `events_1s.jsonl` diff (`regression.py:218-221`). Both cannot hold with the flag ON. Resolution
  baked into the plan: **flag OFF ⇒ events+trades byte-identical** (nothing emitted); **flag ON ⇒
  trades byte-identical + the non-AI event subsequence unchanged**, AI lines carry `source:"ai-shadow"`
  and are filtered out to recover the baseline. **RESOLVED: this is the contract (D3).**

- **H5 — latency unit.** The task says "expose it as a config constant in BARS." Bars are
  mode-dependent (1s vs 1m); 75 s = 75 bars (1s) but ~1 bar (1m). The plan pins latency in
  **seconds** and derives an arrival timestamp. If the user specifically wants a BARS constant, it
  must be mode-qualified. **RESOLVED: seconds + derived arrival timestamp.**

- **H9 — checkpoint set mismatch.** `derive_facts` only computes candidate checkpoints at 09:20 /
  13:00 (`:217-223`) because the POC cuts were taken there; `decisions/daily-trend.md §1` wants
  06:00 / 09:20 / 13:00 / 18:00. The online checkpoint driver must implement all four independently
  of `derive_facts`'s candidate logic.

- **H19 — "56 tests green" is unverified.** `agent/` + `calibration/` hold only 3 test files; the
  broader `tests/` dir holds the rest. Phase 0 must run **all three dirs** and record the real
  baseline; do not assume 56 refers to the whole repo.

- **H-contention — real API in a CPU-heavy replay.** A full-day 1s A/B already runs minutes; adding

  as a default on every regression → the plan defaults real-API OFF (stub) in tests and gates real
  runs behind Phase 6 + the cache. On the live box (16 GB) the worker thread + staleness guard are

- **C1 — study data volume:** a hypothesis forms once and persists until trend-broken
  (`hypothesis.py:2246`), so triggers are few (~4/day on 2026-05-01). The minimal-hypothesis day
