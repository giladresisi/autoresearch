## Design

### Consumer (1) — per-ticker level depletion retirement in `_detect_level_smts`
Reserved state key `state["__level_inv__"] = { name: {"mnq": bool, "mes": bool} }` (latched,
terminal for the session; no `"|"` so the adverse-run/post-pass loops skip it).

1. **Skip-if-either-invalidated** (top of the per-level loop, after `sub` validation):
   if `__level_inv__[name]` has `mnq` or `mes` True → `continue` (no fire, no re-arm, no
   latch update). This is the core retirement.
2. **Latch update** (bottom of loop, **wick pass only** `not body` — needs bar High/Low):
   - tier = `_level_class(name)[1]`; `thr_mnq=_fulfill_pts(tier,"mnq")`, `thr_mes=…"mes"`.
   - `*_high`: ticker invalidated once `bar.high >= level_price + thr` (ran well above → pool
     consumed). `*_low`: once `bar.low <= level_price - thr`. Per ticker, using each
     instrument's own wick level price (`lvl["price"]`).
   - Append a lightweight audit event to `state["__level_retirements__"]` on each flip.
   - Body pass READS the latch (skip) but never UPDATES it.
   - Ordering: wick pass runs before fill/body in the pipeline → body sees the latch.
   Rationale (occurrences): asia_high — MES ran >7421.5+3 (cleared) while MNQ sat at 29647.5 →
   MES latched → skip @ 05:35. prev1_day_high / prev2_day_high — price ran above level+thr
   earlier (latched) → skip @ 04:19/04:20 & 00:05/00:06. Latched terminal so a later re-touch
   from either side stays retired.

### Consumer (1b) — fixed-level re-arm-until-invalidated (AC#3, GIL-25 2026-06-13)
Replace "fixed never re-arms" (smt_detect.py:367 `kind_cls=="dynamic"` gate):
- Track `st["departed"]` (bool). After a fixed level fires, departure resets False.
- Each bar, for a fired fixed level: if `abs(mnq_close - mnq_lvl_price) >= _fulfill_pts(tier,
  "mnq")` → `departed=True`. (Upward departure of a high level implies the invalidation latch
  fires first → skipped; so departure→re-arm in practice means a **reversal** then re-approach.)
- Re-arm block: `if not armed and kind_cls=="fixed" and st["departed"]: re-arm; departed=False`.
- Terminal = level invalidation, enforced by the skip-continue at loop top (an invalidated
  level never reaches the re-arm block). Lifecycle: fire → reversal(held) → re-arm → fire …
  → invalidate → retire.
- Dynamic re-arm unchanged (fulfilled / opposite-SMT).

### Consumers (2)/(3) — drop invalidated levels from cautious + hypothesis targets (LIVE)
- `compute_cautious_prices(..., invalidated_names: set[str] | None = None)`: when a set is
  given, skip any candidate whose `name` ∈ set (main loop + terminal-fallback loop). `None` →
  no drop (PURE; preserves all existing direct-call tests).
- `build_hypothesis_from_direction`: load MNQ-invalidated names once; filter the step-7 targets
  loop (skip names in set) AND pass `invalidated_names` to its `compute_cautious_prices` call.
- `recompute_cautious_for_fill` (hypothesis.py ~173): load + pass `invalidated_names`.
- Helper `_invalidated_target_names()` in hypothesis.py: `smt_state.load_smts()` →
  `detect_state["__level_inv__"]` → `{name for name,v in items if v.get("mnq")}`. **MNQ only**
  (the traded instrument; MES depletion does not deplete MNQ's order pool at the MNQ price).
  Add `load_smts` to the hypothesis.py `from smt_state import (...)`.

## Tasks (TDD — tests first each step)
1. **Consumer (1) latch + skip** — tests in `tests/test_smt_invalidation.py` (new cases) /
   `tests/test_smt_detect.py`:
   - high level latches mnq when high≥lvl+FULFILL; low level latches on low≤lvl−FULFILL.
   - below-threshold run does NOT latch.
   - once latched, the level is skipped (no fire) even on a fresh divergent re-touch.
   - asymmetric: MES latched, MNQ not → skipped (Q8 shape).
