> **RULE: when an implementation moves a documented number, the delta MUST be explained
> before the result is accepted.** An unexplained delta is a defect; an explained delta is a
> pass. Never assert a headline number a later-dated knob change has superseded — §6.2's
> CURRENT-rules column exists precisely for this.

**Accepted tolerances, carried verbatim from the doc — do NOT chase these:**

- §6.1: the doc-literal subsequent-bar gate differs from a raw exit-tick reading by **±1 cycle on 08-06**. Doc-literal is the specified reading; the discrepancy is "a known ±1-cycle uncertainty, not a defect to chase".

**3. Oracle §10.2 stress** — invert the thesis, re-run the named set, assert the adverse band holds. Meaningful now that predicate-based plan death works.

**Attempts: assert, never score.** Record attempts used/remaining and compare against each named case's documented count (08-14 "exactly 3 attempts"; 07-21 "one attempt in reserve"). They contribute NOTHING to P&L arithmetic. A row reproducing the right P&L via a *different* attempt count is a real discrepancy — attempts-used is a sharper change detector than P&L, since a stopped-out attempt followed by a winner nets the same as one clean entry.

## Task 1: Eligibility must read EXISTENCE, not identity 🔴 Complex

**Files:**
- Modify: `agent/trader/executor.py:454-480` (`_eligible_gaps`)
- Test: `agent/trader/test_existence_gating.py` (create)

**Interfaces:**
- Consumes: `Fact.extra["exists_from"]` (populated by `agent/facts/detectors/fvg.py`).
- Produces: `Executor._exists_by(fact, now) -> bool` — the single time gate every mechanism uses.

**Why this task exists, and why it is first.** `_eligible_gaps` currently gates on

```python
if f.reference_ts is not None and now is not None and f.reference_ts > now:
    continue
```

`reference_ts` is the gap's **IDENTITY** — the MIDDLE bar. §2 pins that *everything time-gated reads EXISTENCE, never identity*, where existence is the THIRD bar's completion (`label(T+1) + timeframe`). Verified on a real snapshot: a 1m gap carries `reference_ts 09:23` and `exists_from 09:25`. So the Executor currently admits every gap **two bar-widths early** — a 5m gap **10 minutes** early.

That is look-ahead: the engine can bind a pattern before it could be known. It is the exact defect §11's erratum documents, where a recorded 09:36:04 fill was impossible because the gap existed only at 09:40:00. **08-21's named test ("must be FLAT") cannot pass until this is fixed**, because the gap becomes visible from its 09:30 identity and a pre-existence retrace would satisfy §5's precondition.

Note the inconsistency this resolves: the §8 recency selection added in phase 1 already reads `f.extra.get("exists_from") or f.reference_ts` (`executor.py:752`). Selection is correct; the eligibility gate is not.

    @staticmethod
    def _exists_by(fact, now) -> bool:
        """Has this fact's EXISTENCE instant arrived?

        §2 (pinned 2026-08-27): identity is the MIDDLE bar; EXISTENCE is the third bar's
        COMPLETION. Everything time-gated reads existence. Gating on `reference_ts`
        admits a 5m gap ten minutes early — the look-ahead the §11 08-21 erratum
        documents, where a 09:36:04 fill was recorded on a gap that existed at 09:40:00.

        The `or reference_ts` fallback exists only so facts predating the field stay
        readable; the detector always populates it.
        """
        if now is None:
            return True
        at = fact.extra.get("exists_from") or fact.reference_ts
        if at is None:
            return True
        return pd.Timestamp(at) <= now

```python
    def _gaps_on(self, tf: str, now: pd.Timestamp, *, initial: bool = True,
                 direction: "str | None" = None) -> list:
        """Live MNQ gaps on ONE timeframe facing `direction` (default: the trade
        direction).

        §4's 1m fallback, §6 and §8's takeover all need 1m gaps. §11 records two
        independent manual walks that scanned only 5m and produced a wrong 07-21 ledger
        and a mis-bound 07-31 takeover — a timeframe-blind query reproduces exactly that
        failure, so the timeframe is an explicit argument with no default.
        """
        want = direction or ("bear" if self._is_short() else "bull")
        black = set(self._plan.get("blacklist") or ())
        out = []
        for f in self._store.query(cls=FactClass.FVG, ticker=self._ticker,
                                   state=FactState.LIVE):
            if f.timeframe != tf or f.extra.get("direction") != want:
                continue
            if f.id in black:
                continue
            if not self._exists_by(f, now):
                continue
            if not self._height_ok(f, initial=initial):
                continue
            if tf == PRIMARY_TF and self._distance_dead(f):
                continue          # §4: 5m distance invalidation does NOT extend to 1m
            out.append(f)
        return out

    def _eligible_gaps(self, now: pd.Timestamp, *, initial: bool = True) -> list:
        """The 5m query. Kept as a named method because it is the primary-timeframe
        call site the ladder and the §8 recency selection both use."""
        return self._gaps_on(PRIMARY_TF, now, initial=initial)
```

**Note the `tf == PRIMARY_TF` condition on `_distance_dead`.** §4 is explicit: "the §2 5m distance invalidation does NOT extend to 1m-bound gaps (close-through eligibility only, for now)."

"""§5's two-phase binding gate: has price retraced INTO this gap on a FRESH tick?

SETTLED 2026-08-26. The retrace-in tick must be strictly after the settle window ends
(09:30:30). Penetrations completed before that — pre-arm or in-window — count for
eligibility and close-through tracking ONLY; they do not satisfy the precondition and do
not arm §2's crossed-trigger execution.

The superseded "or immediately if price is already inside / has already entered it"
clause is DELETED (§11.0's retired list). The 19-day A/B that settled it: FRESH +570.50
vs LITERAL +410.50, and the "max-distance guard alone suffices" hypothesis was REFUTED —
the guard delays the literal entry into a chase rather than blocking it.
"""
from __future__ import annotations

import pandas as pd


class RetraceGate:
    def __init__(self, settle_end: pd.Timestamp) -> None:
        self._settle_end = settle_end
        self._seen: set = set()

    def note_tick(self, gap_id, price, gap_low, gap_high, now) -> None:
        """Record one tick. Cheap enough for the per-second path: two comparisons."""
        if gap_id in self._seen or price is None or now is None:
            return
        if now <= self._settle_end:
            return                       # strictly after; the boundary does not qualify
        if float(gap_low) <= float(price) <= float(gap_high):
            self._seen.add(gap_id)

    def fresh_entry_seen(self, gap_id) -> bool:
        return gap_id in self._seen

    def reset(self, gap_id) -> None:
        """After a stop-out the gap must earn a fresh retrace again."""
        self._seen.discard(gap_id)
```

# agent/trader/extreme_reject.py
"""§7 `extreme_reject_close`: the first rejecting 1m bar at a swept day extreme.

ICT basis: liquidity sweep / turtle soup. A stop-run through a fresh day extreme that
immediately rejects — the extreme-making 1m bar closing back in the thesis direction —
marks the manipulation completing.

STALE-EXTREME ANCHOR (re-keyed from DISTANCE to AGE, 2026-08-26). When the
counter-thesis 24h day extreme is more than ~2h old AT THE PLAN ARM, the machine tracks
the post-09:30 extreme instead. The invariant: this gate identifies the liquidity pool
whose sweep the mechanism waits for, and STALENESS decides which pool that is. An
extreme set forty minutes ago IS the liquidity the market is currently working; one
belonging to an earlier session phase is not, and the RTH leg prints its own signature.

The >150 pt DISTANCE key is RETIRED and must not be reintroduced: 08-07 (152.50) and
08-25 (123.50) are adjacent in distance and need opposite answers. Their ages — 0.60h
and 3.55h — separate cleanly, and the measured ages leave a gap from 0.60h to 1.90h, so
T is not fitted (identical totals for any T in 1.0h-3.0h).
"""
from __future__ import annotations

import pandas as pd

QUIET_CLOSES_TO_ARM = 3
SL_CAP_PTS = 15.0                 # §9; the cap15-vs-w3c30 A/B is a DEFERRED knob
STALE_EXTREME_AGE = pd.Timedelta(hours=2)


def choose_track(age, threshold_h: float = 2.0) -> str:
    """Which extreme series §7 follows. `age` is measured AT THE PLAN ARM."""
    if age is None:
        return "24h"
    return "post_0930" if age > pd.Timedelta(hours=threshold_h) else "24h"


class ExtremeReject:
    def __init__(self, direction: str, plan_arm_ts, *, track: str = "24h") -> None:
        self._short = str(direction).upper() in ("DOWN", "SHORT")
        self._arm = plan_arm_ts
        self._track = track
        self._extreme = None          # the standing counter-thesis extreme
        self._quiet = 0
        self._armed = False

    def state(self) -> dict:
        return {"armed": self._armed, "quiet": self._quiet,
                "extreme": self._extreme, "track": self._track,
                "age_measured_at": self._arm}

    def on_bar_close(self, now, bar) -> "dict | None":
        """Drive one completed 1m bar. Returns a fire dict, or None."""
        adverse = float(bar["High"]) if self._short else float(bar["Low"])
        new_extreme = (self._extreme is None
                       or (adverse > self._extreme if self._short
                           else adverse < self._extreme))

        if new_extreme:
            self._extreme = adverse
            self._quiet = 0           # a new-extreme TICK restarts the count, whatever
                                      # the close colour (08-10's 09:35 bar closed green)
            if self._armed and self._closes_in_thesis_direction(bar):
                return self._fire(now, bar)
            return None               # adverse close: no fire, and NO disarm

        self._quiet += 1
        if self._quiet >= QUIET_CLOSES_TO_ARM:
            self._armed = True
        return None

    def _closes_in_thesis_direction(self, bar) -> bool:
        c, o = float(bar["Close"]), float(bar["Open"])
        return c < o if self._short else c > o

    def _fire(self, now, bar) -> dict:
        entry = float(bar["Close"])
        wick = float(bar["High"]) if self._short else float(bar["Low"])
        capped = entry + SL_CAP_PTS if self._short else entry - SL_CAP_PTS
        stop = min(wick, capped) if self._short else max(wick, capped)
        return {"time": now, "price": entry, "stop": stop,
                "mechanism": "extreme_reject_close"}
```

Plus: a new day extreme against the thesis printed after the last 5m FVG's creation, and thesis-direction (continuation) 1m FVGs created since that extreme.

**Episode model.** An episode begins when price enters a candidate gap **strictly inside — at least one tick beyond the near edge** (edge touches don't count; no traversal requirement) and tracks the excursion extreme until a trade starts. **Adverse 1m closes beyond the gap do NOT invert a candidate** for this mechanism — the close-colour gates replace close-through invalidation, and the episode survives escapes and re-entries (validated 08-05, where the winning entry came two bars after a close above the gap top).

**§6.1's four NORMATIVE clauses — implement exactly this:**

1. **Intra-bar ordering is load-bearing.** The episode begins at the TICK that first enters the gap strictly beyond the near edge. The early-runaway test and the excursion extreme are evaluated ONLY over ticks at or after that tick — never over the whole entering bar. Named trap: 08-06's 09:38 bar prints 29437.00 (= gap top + 25) at **09:38:14, thirteen seconds BEFORE** price enters the gap at 09:38:27; scanning the whole bar fires a phantom runaway on a print that preceded the episode.
2. **Early-runaway fills at the trigger price** (`exit-side edge ± 25`), not the market mid. Named test: 07-21 gap B fills **29149.75** = 29174.75 − 25 exactly. Close-verdict and exit-tick entries DO fill at the 1s mid at placement.
3. **The stop-out cooldown gates entry evaluation** — no cycle may complete while it is in force, and all gap cycles reset to idle across it. Without this the machine re-enters within seconds of every stop-out.
4. **Candidate-gap evaluation order: most-recently-ENTERED gap first**, per §6's own parenthetical. Measured OUTCOME-NEUTRAL on all four recorded days, so this is a tie-break convention specified only so two implementations agree.

**Entry rules (short side; mirror for long), all by market:**
- *The entering bar* never triggers intra-bar — its verdict waits for its close: enter at the close only if it closed beyond the gap on the exit side **AND** against its own open (red). A with-trend-coloured close = skip, episode continues.
- *Early-runaway exception:* if before the entering bar closes price has run ≥ 25 pts beyond the exit-side edge **AND** is beyond the bar's open in the trade direction, enter by market immediately. **The beyond-open condition is load-bearing** — it blocked a false fire on 08-05 where the runaway price was still above the bar's open.
- *Subsequent bars:* exit-tick market entry gated by the previous completed 1m bar — if it closed inside the gap, or beyond on the exit side, or against its own open, the exit tick fires; if it closed with-trend-coloured beyond the gap on the adverse side, defer to the current bar's close.
- *A skip voids the cycle:* entries fire only on an actual exit TICK or close verdict of a LIVE cycle — never on already-crossed state carried over from a skipped one. **§2's crossed-trigger rule does NOT apply within this mechanism.**

**SL:** the episode's excursion extreme **+ 2 pts**, capped at **30 pts** from entry.

**The rule.** When a **5m-bound** attempt (§4/§5) stops out and, between the stop-out and the next attempt (**the stop-out bar itself included**), price ticks into a deeper eligible thesis-appropriate FVG farther along the adverse path — **any timeframe, 1m included** — the re-entry binds that deeper gap and the failed gap is **blacklisted for the plan**.

**The blacklist is strictly CONDITIONAL** on the deeper-gap penetration: with no deeper gap penetrated, the same failed gap may re-bind as before. An unconditional blacklist would break 07-23's validated same-gap re-entry.

**Neither the min-height filter nor §4's creating-bar ≥ 09:30 filter applies to the takeover gap** — deepest-penetration binding role, same exemption precedent as ladder targets (08-14's takeover gap is 3.0 pts tall, created 09:11).

**Re-entry mode:** §6's episode machinery, NOT a resting stop-entry — with ONE modification: a **close-verdict (defer) entry whose excursion-anchored SL distance exceeds the 30-pt cap is SKIPPED** (cycle consumed; wait for a closer cycle). Exit-tick/intra-bar entries are **never** length-gated.

**Crossed-trigger precedence at cooldown end.** When the takeover has fired and the cooldown ends, check the FAILED binding's trigger FIRST. If price is already CROSSED beyond it, §2's crossed-trigger market execution takes precedence and the takeover does NOT divert. If UNCROSSED, the takeover/episode path governs.
