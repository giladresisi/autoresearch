## Feature Description

A batch of seven related, largely-independent improvements to the L1 thesis-decision system
(`agent-docs/strategy/decisions/thesis.md` + its code: `agent/derive_facts.py`,
`agent/contracts/schemas.py`, `agent/contracts/validate_contracts.py`, `agent/run_agent.py`,
`agent/bench/facts.py`), surfaced by a manual point-in-time testing session
(`manual-l1-thesis/test_l1_thesis_manual.py`) that ran the model against 13+ real historical
boundaries and compared its declared evidence/reasoning against ground truth pulled directly from
the parquet data. Each item closes a concrete, verified gap found during that session — a real
liquidity level the system can't see, a recurring polarity-narration bug, an unscored evidence
type, or a structuring gap for data the model already reasons about informally.

## User Story

As the L1 thesis model deciding market direction from historical price structure,
I want a deeper, correctly-scoped, and more completely-scored evidence ledger,
So that decisions are less likely to miss real cross-asset divergence signals, narrate their own
correctly-computed evidence backwards, or ignore evidence types (FVG fills, equilibrium
reclaim/reject, stale SMTs) that the facts already contain but the scoring model can't yet use.

## Problem Statement

Manual testing this session found, with verified ground-truth confirmation for each:

1. The system only tracks 2 prior day-extremes and 1 prior week-extreme per side
   (`prev1_day`/`prev2_day`, `prev1_week`). A genuine, uncontested cross-asset SMT divergence at
   `prev3_day_low` (2026-07-14 01:00 boundary — MNQ swept it, MES never came within 15.5 points of
   its own analogous level all session) is completely invisible today, and thesis.md §2.1b's
   nested/superseded-liquidity pruning rule is ambiguous about whether a same-asset "superseded"
   level can still carry independent cross-asset evidence (it can, and today nothing in the code
   or prompt says so).
2. The model's own **correctly** code-scored P2 evidence item gets narrated backwards in its own
   free-text reasoning (example #13: a bullish, correctly-`side: UP`-scored SMT reject described in
   prose as "adds weight to the DOWN thesis").
3. The model states its own scoring/tallying rule correctly in prose, then miscomputes its own
   declared net tally when applying it — recurring across multiple examples even after two prior
   mitigations (schema property reordering; HIGH/LOW prompt reinforcement) shipped earlier this
   session.
4. FVG (Fair Value Gap) fill data already exists in the facts text but is not part of the scored
   evidence vocabulary at all — a real, visited bullish FVG (example #10) never appeared in the
   model's evidence ledger.
5. Stretch (distance from a stale SMT's origin) is only used to discount P3/regime confidence, not
   to actively exclude evidence from an old, already-played-out SMT (example #10: a stale bearish
   SMT kept counting as continuation evidence 5.6× past its origin).
6. P3 (equilibrium) and P4 (reclaim/failed-reclaim) are reasoning-only — they cannot compete on
   equal footing against code-scored P1/P2 items in the net tally.
7. Immature (`mature: False`) evidence on a real day/week-tier level is informative (the model
   already narrates when/how it will resolve, informally, in prose) but not structured, so an
   execution layer consuming the thesis has no reliable way to read it.

## Solution Statement

Extend `derive_facts.compute_facts()`'s tracked-level depth (day-tier to 7 days back, week-tier to
3 weeks back) by **reusing already-computed long-horizon data** (`bundle.historical_extremes`,
today used only for audit-only confluence tagging) rather than re-scanning the primary frame —
this was benchmarked this session at near-zero incremental cost via reuse vs. +7s/facts-build via
naive re-scanning. Pair this with a thesis.md §2.1b clarification that same-asset nesting pruning
never suppresses cross-asset P2/SMT candidacy. Then, independently: extend the existing P1
HIGH/LOW polarity prompt reinforcement to cover P2's SMT-reversal framing; spike a structured
"scratch tally" consistency-check design for the standing arithmetic bug; wire FVG-fills into the
scored evidence vocabulary as a new criterion; add a code-suggested (model-overridable) SMT
exhaustion flag driven by tier-relative stretch; partially code-derive P3/P4; and structure
immature-evidence pending-resolution as a schema field. Every new value follows this codebase's
existing "model judges, code computes" architecture — the model tags/selects, code derives
sign/points/consistency, never the model's own arithmetic.
