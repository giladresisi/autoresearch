Complexity: ⚠️ Medium. One new import-cheap module, small edits at 6 call sites, tests that simulate POSIX on a Windows
dev box. No change to strategy, agent, executor or data logic. On Windows behaviour must stay byte-for-byte the same.

## 1. Context an implementer needs

**The project.** `auto-co-trader` is a futures (MNQ/MES) trading system. `trade.py start` launches the orchestrator
(`uv run python -m orchestrator.main`), which spawns the trading subprocess `automation.main` (streams IB bars, the
agent brain decides, orders go out through PickMyTrade/Tradovate). `trade.py terminate` and the orchestrator itself find
and stop these processes with `psutil`, scoped to the current worktree by cwd (so a sibling worktree's live run is never
touched). A trading process that outlives its supervisor is a real-money hazard (incident 2026-06-12 D2: an orphaned
`automation.main` kept trading) — which is why the process-matching and detach logic below matters.

**Why this plan.** The operator will add a second physical machine (a Mac) for live runs (plan 50 = R2 data sync, merged
PR #121; plan 51 = start guards). Everything was written and tested on Windows only. A read-through (not a run) found
these POSIX/macOS problems, all small and mechanical:

| # | Where | Problem on macOS/Linux |
|---|---|---|
| 1 | `trade.py` `start` branch, `CREATE_NO_WINDOW = 0x08000000` + `subprocess.Popen(..., creationflags=CREATE_NO_WINDOW, ...)` | `creationflags` is Windows-only: CPython raises `ValueError` for a nonzero value on POSIX, so `trade.py start` crashes before the orchestrator exists. It also has no detach: closing the terminal would SIGHUP the orchestrator. |
| 2 | Process matching `proc.info.get("name","").lower() not in ("python.exe","python")` at `trade.py` (3 sites: profile-snapshot request, orphan-orchestrator sweep, automation sweep) and `orchestrator/main.py` (2 sites: stale-orchestrator kill, `_kill_automation_main`) | On macOS a venv interpreter's process name can be `python3.12`, `Python` or `python`; `python3.12` is not in the tuple, so `terminate` / the fresh-start sweep / the exit-time safety net can MISS a live process → duplicate orchestrators or an orphaned trader. |
| 3 | `orchestrator/main.py` ~L213-219: `ctypes.windll.kernel32.SetThreadExecutionState(0x80000001)` inside `try/except Exception: pass` | Silently does nothing on macOS: the Mac may idle-sleep and drop the IB connection mid-session (the Windows code exists for exactly that failure). |
| 4 | `trade.py` ~L293: kill of a `powershell.exe` wrapper | Never matches on macOS — harmless; leave as is. |
| 5 | `scripts/bootstrap_env.py` | Documented no-op on macOS/Linux (unsigned-DLL workaround is a Windows Smart-App-Control thing). Nothing to do. |
| 6 | `_shadow_smt_analysis.py` hard-codes `C:/Users/gilad/...` | A study script only, never on the live path. Leave. |

Facts already verified in the code (do not re-derive): the graceful stop path is FILE-based and platform-independent
(`orchestrator/stop_request.py` `AUTOMATION_STOP_FILE`; `ProcessManager._request_stop` writes it, `automation.main`'s
`_watch_stop_request` thread honours it), so POSIX needs no signal-based graceful stop; `ProcessManager._terminate` and
`trade.py`'s stop helpers fall back to `proc.terminate()` (SIGTERM on POSIX, which ends a Python process immediately
without running `finally` unless a handler is installed — the same practical effect as the hard kill on Windows, so
no new handler is required; decision 5). Paths use `pathlib`/`paths.py`; time handling uses explicit `ZoneInfo`, never the
machine timezone.

## 2. Decisions

1. **New module `platform_compat.py` at the repo root** (next to `paths.py`; import-cheap: `os`, `sys`, `subprocess`,
   `shutil` only; psutil is NOT imported here). It is the single place that knows the OS. Functions:
   - `is_python_process_name(name: str) -> bool`: lower-case, strip a trailing `.exe`, then `name == "python"` or
     matches `python3`, `python3.12`, `python3.12.1` etc. (`re.fullmatch(r"python(3(\.\d+)*)?", n)`), and `"pythonw"`.
     Replaces all five tuple checks. It must NOT match `uv`, `powershell`, `pythonista` or an empty/None name.
   - `detached_popen_kwargs() -> dict`: Windows → `{"creationflags": 0x08000000}` (exactly today's value);
     POSIX → `{"start_new_session": True}` (detaches from the terminal/SIGHUP, new process group).
   - `prevent_idle_sleep(pid: int | None = None) -> object | None`: Windows → today's `SetThreadExecutionState`
     call (same constant, same swallow-everything behaviour), returns `None`; macOS (`sys.platform == "darwin"`) →
     spawn `caffeinate -dimsu -w <pid>` (defaults to the current pid; it exits by itself when the process ends) and
     return the `Popen` handle; other POSIX → no-op returning `None`. Never raises; if `caffeinate` is missing,
     print ONE line to stderr ("macOS sleep prevention unavailable") and return `None`.
2. **Call-site edits (behaviour on Windows unchanged):**
   - `trade.py` `start`: replace the hard-coded `CREATE_NO_WINDOW` / `creationflags=` with `**detached_popen_kwargs()`.
   - `trade.py` (3 sites) and `orchestrator/main.py` (2 sites): `is_python_process_name(proc.info.get("name") or "")`.
   - `orchestrator/main.py`: replace the `ctypes.windll` block with `platform_compat.prevent_idle_sleep()`; keep the
     explanatory comment (generalised: Windows Modern Standby / macOS idle sleep both tear down the IB TCP session).
3. **`caffeinate` scope:** started by the ORCHESTRATOR process (not `trade.py`), once, at import time where the
   Windows call lives; `-w <orchestrator pid>` ties its life to the orchestrator, so no cleanup/orphan. Flags
   `-d` (display), `-i` (idle), `-m` (disk), `-s` (system, only on AC power), `-u` (declare user active).
4. **Do not touch** the stop-file mechanism, `_terminate`/`_reap_descendants` logic, `psutil.cwd()` worktree scoping, the
   PowerShell-wrapper kill, or any strategy/agent file.
5. **No SIGTERM handler** in this plan (would change shutdown semantics on every OS). If the operator later wants
   `finally` cleanup on SIGTERM, that is a separate plan.
6. **Testing without a Mac:** tests monkeypatch `platform_compat.sys.platform` / `os.name` and `subprocess.Popen`, and use
   fake psutil process objects with `.info` dicts. They must run identically on Windows, macOS and Linux.
7. **Process-name policy:** match by NAME first (`is_python_process_name`), then the existing cmdline substring tests
   (`"orchestrator.main"` / `"automation.main"`) and worktree-cwd scoping — those remain the real discriminators, the
   name check only has to stop excluding legitimate interpreters.

## 7. Out of scope

A supervisor/alerting service; Linux/VPS-specific packaging (systemd units, headless IB Gateway, xvfb for the PMT
browser); rewriting the Claude skills for POSIX shells; a SIGTERM-driven graceful stop; sleep prevention for Linux.

## 8. Risks

- `caffeinate -s` only holds on AC power; on battery the Mac may still sleep (checklist item 3).
- Matching is intentionally permissive on the interpreter NAME and strict on cmdline + worktree cwd; a mistake there is the
  dangerous direction (killing a foreign process or missing a live one), hence the explicit negative tests.
- psutil on macOS may raise `AccessDenied` for `cwd()` of other users' processes; the existing code already treats that as
  "skip", which stays correct.
- No env vars are added or changed by this plan.
