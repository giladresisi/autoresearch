# Plan 11 — L1 predicate vocabulary: schema enforcement + menus (+ failsafe recall)

Complexity: ⚠️ Medium
Context: `agent-optimizations.md` (v2 spec §2.1/§6) · plan 10 execution report · bench runs
`run0_baseline` + `test_0702_run1` (the "before" scorecards). This is the first L1-internals
slice, layered per the agreed approach:

1. **Syntax → JSON schema.** Predicate fields in the structured-output schemas become a
   strict `anyOf` of per-type shapes, so an unknown predicate type is impossible at
   generation time (kills the `SYN_BAD_PREDICATE` → failsafe class seen on all 4 bench dates).
2. **Grounding → menus.** `derive_facts` pre-computes candidate DOLs and candidate
   falsification/exhaustion/recall predicates with concrete parameters; the model selects
   (escape hatch allowed, validated).
3. **Judgment → KB prose.** OUT OF SCOPE here (the thesis.md KB merge is its own effort).
   Task-prompt changes in this plan are mechanical instructions about menus/vocabulary only.

Plus: **failsafe recall max-age** — the 07-02 run showed a failsafed 18:00 call leaves the
system blind all session (failsafe thesis has no recall). Event-driven design requires a
failsafe to schedule its own retry.

Repo-standing constraints: no commits/pushes (user will ask), real-API spend per-run shell
env only, meta docs stay untracked. Real-API budget this plan: **< $6 total** (Phase-5
measurement runs; more calls/day expected once theses stand and die intraday).

## Design decisions (locked)

- **Predicate schema shape:** one shared predicate-schema fragment used by `falsified_if`,
  `exhausted_if`, `recall.events` in `THESIS_SCHEMA` (and the same fragment in
  `TRADE_PLAN_SCHEMA`'s predicate fields, for consistency): `anyOf` over the six atoms, each
  with `type` as a const + exactly its required params, plus `all_of`/`any_of` whose items
  are **atoms only** (composition depth 1 — avoids recursive schemas, which structured-output
  backends handle poorly; the contracts evaluator already supports nesting, so depth-1 is a
  schema restriction only, documented in `agent-optimizations.md` §6 as a note).
- **Menus (new facts section, S8):** computed in `derive_facts` (offline + online paths get
  it for free via the shared core):
  - **DOL menu:** eligible target pools per direction — in-facts, unswept/undepleted,
    correct side of current price — with level name + wick/body price + tier. (This is the
    batch's "eligible-target menu" engineering recommendation.)
  - **Predicate menu:** per direction, candidate falsification / exhaustion / recall
    predicates with IDs and filled params: e.g. `F1: n_closes_beyond(daily_mid, above, 5m, 2)`,
    `F2: price_beyond(<pool>, above)` for each nearby anti-thesis pool, `X1: price_beyond(DOL)`
    per DOL-menu entry, `R1: n_closes_beyond(daily_mid, ..., 3)`, plus `time_elapsed`
    variants. Generation is config-driven (which families × which levels × param variants),
    NOT hardcoded per level name.
  - Rendered into the facts sheet text (compact table w/ IDs) AND into `validator_dict`.
- **Selection contract:** the model emits real predicate JSON (schema-enforced), optionally
  tagged with the menu ID it corresponds to. The validator checks each predicate EITHER
  matches a menu entry (params exact) OR — escape hatch — is schema-valid and passes the
  existing grounding checks (level exists in facts, correct side, unswept/undepleted where
  applicable). Audit records whether each predicate was menu-hit or escape-hatch (iteration
  telemetry).
- **Failsafe recall:** `failsafe_thesis()` gains `recall.max_age_min` (config,
  default 60) so a failsafed call retries. Honored identically by the bench engine and the
  production TradeDirector path (both already implement max_age handling — this is a data
  change in the failsafe factory + config constant, not new engine logic).
- **Bench gate override (diagnostic):** `--gate calibrated|self|stand-directional` on
  run_bench. `calibrated` = current behavior (default). `self` = use model self-report.
  `stand-directional` = any valid directional thesis stands (for lifecycle observation while
  the calibration table is placeholder). Gate source is stamped into run metadata and
  scorecard header so diagnostic runs can't be mistaken for production-config runs.
  PRODUCTION gate behavior unchanged.

## Phase 1 — Schema enforcement (`agent/contracts/schemas.py`)
Strict predicate fragment + depth-1 composition; wire into THESIS_SCHEMA + TRADE_PLAN_SCHEMA.
Named tests: each atom accepted; unknown type rejected BY SCHEMA (jsonschema validation of
the fragment itself); all_of with atom items accepted; all_of nested inside any_of rejected
by schema; existing contracts tests still green (dataclasses/validator unchanged in meaning).
NOTE: verify the chosen backends accept the anyOf construct in structured output (stub +
one cheap real-API structured call in Phase 5 covers real verification).

## Phase 2 — Menus in derive_facts (S8)
DOL menu + predicate menu generation (config-driven), rendered text + validator_dict.
Named tests: menu contains only in-facts, unswept/undepleted, correct-side pools (synthetic
fixture with swept + wrong-side + depleted pools all excluded); predicate IDs unique and
params concrete; text section renders deterministically (byte-stable given same facts);
menu presence does not change any existing S0–S7 content (hash of S0–S7 unchanged).

## Phase 3 — Validator + prompt wiring
- `validate_contracts`: menu-membership check with escape-hatch grounding path; audit
  tagging menu_hit/escape_hatch per predicate.
- `run_agent` `_TASK_THESIS`: teach the vocabulary + menus mechanically (select-by-ID
  preferred, escape-hatch rules, depth-1 composition). No judgment content.
Named tests: menu-matching predicate passes; escape-hatch valid predicate passes with
tag; escape-hatch predicate referencing a non-facts level rejected; audit record carries
the tags.

## Phase 4 — Failsafe recall max-age
`failsafe_thesis()` + config default 60 min; bench engine + TradeDirector honor it (should
be data-only; add regression tests): bench — failsafed day now re-calls at +60 (07-02
shape becomes ≥2 calls); executor — failsafe thesis schedules L1 recall at max_age.
