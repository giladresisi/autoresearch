# Facts Layer + Analyzer / Planner / Executor — Cycle 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the deterministic facts layer and the Analyzer → Planner → Executor chain inside the live process, running to the point of emitting structured intended-entry records — without placing a single order.

**Architecture:** Pure detectors `(state, bars) → (facts, state)` are shared by two drivers: an *incremental* driver fed by the live 1 Hz bar loop, and a *batch* driver (the lookback) invoked when a per-class coverage precondition fails. Facts land in an in-memory multi-class store keyed by content-derived IDs; every fact is recomputable from bars, so only execution state is durable-for-correctness. The Analyzer is a self-contained once-daily LLM call that ignores the store entirely (it calls the lookback and consumes the returned view); the Planner deterministically derives a plan from the thesis; the Executor continuously binds artifacts and emits decision records. The legacy engine keeps running untouched beside it, detached from the broker by config only.

**Tech Stack:** Python 3.12, pandas, pytest, existing `agent/` package (`run_agent.decide_thesis`, `agent/contracts/`, `agent/derive_facts.py`), `session_pipeline.SessionPipeline` as the graft host.

**Spec:** This plan implements the design settled across the `system-design` session. Primary source documents in-tree: `l2-mechanisms.md` (§1–§9 mechanism rules, §11 implementation gaps), `agent-docs/strategy/decisions/thesis.md` (L1 policy), `agent-optimizations.md` (v2 structure, superseded where this plan says so).

- **Facts are recomputable from bars; execution state is not.** Durability is an optimization for facts and a correctness requirement for execution state.

## NEW INSIGHTS — read before starting

Five verification findings contradict assumptions made during design. They change the plan.

**NEW-INSIGHT 1 — the 09:20 hook is dead on any normal session.** `session_pipeline.py:1078` documents "Only one fires per calendar date — whichever comes first sets `_last_daily_date`", and there is a test named `test_0920_skipped_if_midnight_already_ran` (`tests/test_session_pipeline.py:1110`) asserting exactly that. Because the CME session opens at 18:00 the prior evening, 00:00 ET always arrives first and consumes the once-per-date budget. **The 09:20 daily re-run never fires on a normal overnight session.** The Analyzer therefore cannot piggyback on it and needs its own independent trigger with its own guard (Task 12).

**NEW-INSIGHT 2 — the KB cutover is a REPLACE, not an APPEND.** `manual-l1-thesis/test_l1_thesis_manual.py:66-78` defines `MANUAL_KB_FILES` as the five concept docs **plus `decisions/thesis.md`**, explicitly dropping `decisions/daily-trend.md` and `decisions/next-move.md`, with the comment "thesis.md REPLACES decisions/daily-trend.md + decisions/next-move.md". Every recorded L1 run used that 6-file configuration. Appending `thesis.md` to the current 7-file `KB_FILES` would put contradictory v1 and v2 policy in one system prompt and invalidate every recorded result. Production `KB_FILES` must become byte-identical to `MANUAL_KB_FILES` (Task 11).

**NEW-INSIGHT 3 — do not use the existing PRIMARY hook, and `agent/executor/` is already taken.** `session_pipeline.py:1057-1070` shows `if self._trade_primary is not None: … return []` — the primary hook *bypasses the legacy engine entirely* (one-brain). Cycle 1 needs legacy and the new Executor running side by side, so the correct template is the additive `_ai_decisions_on_bar` hook (`session_pipeline.py:1018-1029`), which does not early-return. Separately, `agent/executor/` already exists holding the v2 skeleton (`trade_director.py`, `primary_runner.py`, `decision_service.py`). We are not reusing it — it is the one-brain path and carries the documented fills-not-wired limitation. New code goes in `agent/trader/`.

**NEW-INSIGHT 4 — "use `get_et_now()` everywhere" was wrong.** `get_et_now()` lives in `orchestrator/scheduler.py:18` and is used *only* by the orchestrator. Nothing in the trading path calls it; `session_pipeline`, `strategy`, `trend` and `hypothesis` all derive time from the bar timestamp passed in. Using wall-clock time inside the bar loop would make cycle-2 replay impossible. The correct rule is **bar-time inside the loop, `get_et_now()` only outside it** — and the underlying hazard the original constraint was guarding against (machine clock is Bangkok, 11h ahead of ET) is handled by the bar timestamps already being tz-aware ET.

**NEW-INSIGHT 5 — `decide_thesis` has a precise, enumerable facts contract.** `agent/run_agent.py:1081-1140` reads exactly these keys off the `facts` dict: `levels`, `menus`, `fvg_zones`, `fvg_zone_meta`, `suppressed_p1_levels`, `suppressed_p2_sites`, `level_htf_close_status`, `level_tiers`, `smt_candidates`, `week_extremes`, `now_price`, `mid_reclaim`, `htf_reversal`, `mid_position`, `p1_stale_levels` — plus positional `facts_text`, `context_text` and keyword `evidence_magnitude`. This turns the abstract "requirement declaration" into a concrete 15-key contract the Analyzer's assembler must satisfy exactly. Task 13 pins it as a test.

```python
# agent/facts/bars.py
"""The single owner of timeframe bar construction.

Every producer of timeframe-derived facts — incremental and batch alike — MUST call
this module. Two independent notions of a "5m bar" inside one view is the failure
mode l2-mechanisms.md §11 records for 07-23, where a resampled 5m close appeared to
invalidate a gap before a validated fill.

Conventions, pinned:
  - left-labeled, closed-left bins
  - COMPLETED bins only; the trailing partial is dropped
  - session-anchored to 18:00 ET (not midnight) for >= 1h timeframes
  - bins never span the 16:55-18:00 CME maintenance break
"""
from __future__ import annotations

import datetime

import pandas as pd

SESSION_OPEN_HOUR = 18
MAINT_LO = datetime.time(16, 55)
MAINT_HI = datetime.time(18, 0)

_AGG = {"Open": "first", "High": "max", "Low": "min", "Close": "last", "Volume": "sum"}
_SUPPORTED = {"5min", "15min", "1h", "4h"}


def _session_origin(first_ts: pd.Timestamp) -> pd.Timestamp:
    """The 18:00 ET session open at or before `first_ts`."""
    anchor = first_ts.normalize() + pd.Timedelta(hours=SESSION_OPEN_HOUR)
    if first_ts < anchor:
        anchor -= pd.Timedelta(days=1)
    return anchor


def _drop_maintenance(df: pd.DataFrame) -> pd.DataFrame:
    t = df.index.time
    keep = ~((t >= MAINT_LO) & (t < MAINT_HI))
    return df[keep]


def resample(df: pd.DataFrame, tf: str, *, session_anchored: bool = True) -> pd.DataFrame:
    """1m bars -> `tf` bars. Completed bins only. See module docstring for conventions."""
    if tf not in _SUPPORTED:
        raise ValueError(f"unsupported timeframe {tf!r}; expected one of {sorted(_SUPPORTED)}")
    if df is None or len(df) == 0:
        return df.iloc[0:0] if df is not None else pd.DataFrame()

    src = _drop_maintenance(df)
    if len(src) == 0:
        return src.iloc[0:0]

    kwargs = {"label": "left", "closed": "left"}
    if session_anchored:
        kwargs["origin"] = _session_origin(src.index[0])

    out = src.resample(tf, **kwargs).agg(_AGG).dropna(how="all")

    # Completed-bins-only: drop any bin whose span extends beyond the last source bar.
    if len(out):
        span = pd.Timedelta(tf)
        last_covered = src.index[-1] + pd.Timedelta(minutes=1)
        out = out[out.index + span <= last_covered]
    return out
```

```python
# agent/facts/records.py
"""The fact record. One shape, per-class extras in `extra`.

State is an enum plus a timestamp, never a pile of booleans — booleans proliferate
and drift out of consistency. `price` (wick extreme) and the body/close extreme in
`extra["body_price"]` are BOTH carried: thesis.md's P1/P2 criteria turn on the
distinction.
"""
from __future__ import annotations

from dataclasses import dataclass, field
from enum import Enum

import pandas as pd


class FactClass(str, Enum):
    LEVEL = "level"
    FVG = "fvg"
    LEG = "leg"
    EXTREME = "extreme"
    ANCHOR = "anchor"


class FactState(str, Enum):
    LIVE = "live"
    SWEPT = "swept"
    DEPLETED = "depleted"
    INVALIDATED = "invalidated"
    SUPERSEDED = "superseded"
    TRAVERSED_BY_GAP = "traversed_by_gap"


@dataclass
class Fact:
    id: str
    cls: FactClass
    ticker: str
    label: str
    name: "str | None"                 # mutable, current (e.g. prev2_day_high); levels only
    reference_ts: pd.Timestamp
    price: "float | None"
    price_low: "float | None"
    price_high: "float | None"
    timeframe: "str | None"
    resolution: str
    state: FactState
    state_ts: pd.Timestamp
    provenance: dict = field(default_factory=dict)
    extra: dict = field(default_factory=dict)

    def set_state(self, state: FactState, ts: pd.Timestamp) -> None:
        self.state = state
        self.state_ts = ts
```

```python
# agent/facts/ids.py
"""Content-derived fact IDs plus human labels.

The ID hashes IDENTITY-DEFINING fields only, never mutable state and never the
level `name` — names move (yesterday's prev1_day_high is today's prev2_day_high),
so hashing the name would make one fact look like two. Keeping the ID stable while
the name moves makes level aging traceable, and gives the future per-plan gap
blacklist a handle that survives re-binds.
"""
from __future__ import annotations

import hashlib

import pandas as pd

from agent.facts.records import Fact, FactClass

_ID_LEN = 12


def _norm(v) -> str:
    if isinstance(v, pd.Timestamp):
        return v.isoformat()
    if isinstance(v, float):
        return f"{v:.4f}"
    return str(v)


def fact_id(cls: FactClass, ticker: str, **identity) -> str:
    """Stable short hash over (class, ticker, sorted identity fields)."""
    parts = [str(cls.value), str(ticker)]
    parts += [f"{k}={_norm(identity[k])}" for k in sorted(identity)]
    digest = hashlib.sha256("|".join(parts).encode("utf-8")).hexdigest()
    return digest[:_ID_LEN]


def fact_label(fact: Fact) -> str:
    """Human rendering. Always logged next to the ID; never used as an identifier."""
    when = fact.reference_ts.strftime("%m-%d %H:%M")
    if fact.cls is FactClass.FVG:
        direction = fact.extra.get("direction", "?")
        return (f"{fact.ticker} {fact.timeframe} {direction} FVG {when} "
                f"[{fact.price_low}, {fact.price_high}]")
    if fact.cls is FactClass.LEVEL:
        return f"{fact.ticker} {fact.name or '?'} {fact.price} ({when})"
    if fact.cls is FactClass.LEG:
        return (f"{fact.ticker} {fact.timeframe} leg {fact.extra.get('direction','?')} "
                f"{when} range={fact.extra.get('range','?')}")
    return f"{fact.ticker} {fact.cls.value} {when}"
```

- [ ] **Step 3: Implement both drivers**

`run_batch` iterates the requirement's classes; for each, slices bars to the class window, resamples via `bars.resample`, runs the detector, evaluates lifecycle state forward to `now`, re-runs `apply_supersession` over the whole level set, and calls `store.extend_coverage`. **It replaces the class's facts wholesale rather than topping up** — "refill" means "produce the canonical view for this scope", never "add what's missing", or stale derived state survives.

`run_incremental` runs the cascade: per-second only running extremes; on 1m close, 1m FVGs and close-through re-evaluation; on 5m/15m/1h/4h close, that timeframe's FVGs plus leg re-segmentation. `bar_complete=False` defers everything but extremes.
