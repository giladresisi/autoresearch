## 1. Background / current state (grounded @ HEAD 0250177)

The SMT layer is SHADOW: it produces a detection stream + the cross-session carry
(`pending_smts.json` → `smt-carry` audit events → `smt_active_set`) but does NOT drive trades.
Phase 1.4 reworked the LEVEL-reversal carry to source from the **producer lifecycle**
(`detect_state`) instead of the relevance-gated active set, via
`session_pipeline._detect_state_pending_entries`. Fills were left on the OLD relevance-gated
active-set path — **the gap this plan closes.**

### The carry WRITE block today (`session_pipeline.py:2205-2212`)
```python
_carry_session = cme_session_date(now).isoformat()
_level_entries = self._detect_state_pending_entries(_carry_session)          # producer lifecycle
_fill_entries = [
    self._active_record_to_pending(r, _carry_session)
    for r in _active if r.get("kind") == "fill"                              # relevance-gated — the gap
]
_smt_state.save_pending_smts(
    {"entries": _level_entries + _fill_entries, "schema": 1})
```
`_detect_state_pending_entries` (`session_pipeline.py:2285-2343`) walks `detect_state`, skips
`__*__` reserved keys and any key without exactly 3 `|`-parts (so it skips fills, whose key is the
bare FVG name), and emits each fired & non-terminal LEVEL record as a pending entry.
`_active_record_to_pending` (`session_pipeline.py:2345-2381`) is the relevance-gated mapper used
for fills today.

### The fill detector lifecycle (`detect_fill_smts`, `smt_detect.py:913-1022`)
- Fill state `st` is keyed by the **bare FVG name** (`skey = str(name)`, line 941) — confirmed by
  `_record_key` (`smt_detect.py:1044-1045`: `if record.get("kind")=="fill": return str(ref_name)`).
- `st` fields today: `armed`, `fill_a_fired`, optional `fill_b_fired`, `mnq:{entered,passed}`,
  `mes:{entered,passed}`, `fire_price`, `direction` (init block lines 945-952).
- Fill-A fires at lines 981-999; Fill-B fires at lines 1004-1020. **Both set
  `st["fire_price"] = mnq_close`** (lines 999, 1020) — so the fire close IS captured in `st`
  (the "armed sample showed `fire_price: null`" is the pre-fire init state; a FIRED fill has it).
- **NOT stored in `st` today:** the FVG zone (`fvg["mnq"]` = `{top, bottom}`), the phase
  (`fill_a`/`fill_b` — only emitted on the *record* `type`, never persisted to `st`), and the
  `fire_time` (the bar `iso`, line 932). Phase 1.5 must capture these at fire time.

### Read-side pure core (`smt_detect.py`)
- `pending_smt_terminal(direction, fire_price, tier, window_high, window_low)`
  (`smt_detect.py:168-199`) — 2-state fire-close-relative FULFILLMENT test. `day` tier MNQ = 40
  (`FULFILL_PTS_MNQ`, line 36), MES = 6 (`FULFILL_PTS_MES`, line 37). **Reuse with tier="day".**
- `revalidate_and_filter_pending(...)` (`smt_detect.py:225-375`) — per-entry AGE-CAP →
  RE-VALIDATE (fulfillment + level-relative depletion backstop) → DEDUP → REBUILD. The
  depletion backstop (lines 339-354) keys off `e["price"]` (the swept LEVEL); fills have no
  swept level, so this branch must be SKIPPED for fills (locked design pt 4: fulfillment only).
  Dedup (lines 274-290, 356-369) is already by `(ref_name, direction)` — works for fills as-is
  (FVG name IS `ref_name`).
- `_pending_entry_to_record(e)` (`smt_detect.py:378-401`) — rebuilds **every** survivor as
  `kind:"smt"` (line 383). Must branch on kind so a carried fill stays `kind:"fill"`.

### Task B — Producer-lifecycle fill carry source (`session_pipeline.py`)
Add a new method `_detect_state_fill_entries(self, session_date)` mirroring
`_detect_state_pending_entries` (`session_pipeline.py:2285-2343`) but for FILL keys:
- Walk `self._detect_state`; SKIP reserved `__*__` keys.
- A fill key is one whose `st` is a dict carrying the fill lifecycle (`fill_a_fired` /
  `fill_b_fired` present). SELECT a key as carryable iff `st.get("fill_a_fired")` OR
  `st.get("fill_b_fired")` is True (i.e. it FIRED). Distinguish from level keys by the bare-name
  key shape (no exactly-3 `|`-parts) **and** the presence of `fill_a_fired`/`fill_b_fired`.
- Emit a fill pending entry (see Task C schema) per fired fill key, sourcing:
  `price=None` (no swept level — this also makes the depletion backstop a no-op on read),
  `fire_price=st["fire_price"]`, `direction=st["direction"]`,
  `tier="day"` (hard-coded — locked design pt 4), `type=st["fire_phase"]`,
  `phase=st["fire_phase"]`, `zone=st["fire_zone"]`, `fire_time=st["fire_time"]`,
  `ref_name=skey` (the bare FVG name), `side="bearish" if direction=="short" else "bullish"`,
  `leader=st.get("fire_leader")`, `kind="fill"`, `session_date=session_date`, `valid=True`.
  Total: malformed/missing → skip that key; never raises (mirror the try/except shape of
  `_detect_state_pending_entries`).

Then **replace** the `_active`-sourced `_fill_entries` at `session_pipeline.py:2207-2210` with:
```python
_fill_entries = self._detect_state_fill_entries(_carry_session)
```
Leave `_level_entries` and the `save_pending_smts(... _level_entries + _fill_entries ...)` line
(2206, 2211-2212) untouched.

`pending_smts.json` outside `revalidate_and_filter_pending` exists (verified — only consumer is
`_ingest_pending_smts`), so the additive fields are safe.
