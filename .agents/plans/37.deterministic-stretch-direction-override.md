# 37. Deterministic stretch override: decide direction without an LLM call

⚠️ Medium in code. The uncomfortable part is not the code — see §"What this actually is".

**Supersedes plan 35.** Keeps 35's D1 (`session_stretch`, already implemented and tested);
**retires 35's D2** (the S9 render block) and its whole context-only premise. 35 stays on
disk as the record of why — see §"Disposition of plan 35".

## Goal

When the pre-09:20 stretch meets a fixed set of criteria, decide the session's direction
DETERMINISTICALLY as the opposite of the stretch, and skip the L1 model call, the declared
evidence ledger, the scoring and the weights entirely. Calibrated so 2026-09-01 resolves
UP without a model call. Thresholds are expected to move as replays and live runs
accumulate; this plan is the seam, not the final numbers.

## What this actually is, stated before anything else

**It is not a fix for a model error. It overrides the repo's own arithmetic.**

Scored with ZERO model input — an empty declared ledger, the code's own P3 auto-derivation
over `mid_position` — 2026-09-01's facts produce:

```
ARI_THESIS_BIAS: bias 'UP' inconsistent with the evidence ledger's net score
                 -12.125 (expected 'DOWN'; NEUTRAL is acceptable when |net| < 1.0)
```

Price sat below both the daily and the weekly mid on both assets, and that alone is
−12.125. **L1 did not misjudge 09-01; it reported the scoring faithfully.** The model's
twelve unanimous DOWN items were the same conclusion the deterministic path reaches on its
own. So this override asserts UP against a −12.125 code-computed ledger, and every later
adjustment of its criteria is an adjustment to how far we are willing to do that.

That is a legitimate thing to build — the scoring is a hypothesis, not ground truth — but
it must be built knowingly, and it means the usual safety net does not apply: there is no
model to disagree, no confidence to gate on, and (see D3) no contract validation.

## D1 — the predicate (pure)

`stretch_override(stretch) -> {"fires", "direction", "reason"}` over plan 35's
`session_stretch`.

**AS SHIPPED — the clock is the whole rule:**

```
size >= SIZE_FLOOR_PTS (40)   # noise floor only; NOT the discriminator
and age_minutes <= AGE_MAX_MIN (30)
direction = "UP" if stretch.direction == "DOWN" else "DOWN"
```

**The retrace arm this section originally specified was BUILT AND THEN REMOVED.** The first
cut fired on `age <= AGE_MAX or retrace_pct <= RETRACE_MAX`, which reads as a faithful
rendering of "still extending, or halted but barely retraced". D0 says it is an ANTI-signal:

    age<=30 ONLY                       22 days   68%
    age<=30 or retrace<=25 (first cut) 47 days   55%   (base rate 53%)
    the retrace arm ALONE (age>30):  retrace<=5 25% | <=10 22% | <=25 44%

A stale stretch that has NOT retraced CONTINUES. Removal is pinned by
`test_2_a_halted_stretch_never_fires_however_little_it_retraced`.

D0 also killed every size gate: `age<=30 AND size>=300` gives 61% and `>=450` gives 50%,
against 68% for the clock alone — the same inversion the >=450/>=400 buckets showed.
`SIZE_FLOOR_PTS` must stay a noise floor.

**Which asset decides?** MNQ is the traded instrument, but on 09-01 MES's own stretch reads
DOWN with `age_minutes` 15 — also firing. Settle explicitly: MNQ-only, both-must-agree, or
either. Both agree on 09-01, so that date cannot discriminate; use D0's distribution.

## D2 — the bypass seam

The predicate is a FACT-layer function; **the `Analyzer` honours it.** `_arm` evaluates it
before reaching the backend; if it fires, synthesize, persist, return — no model call, no
cache read or write.

Not inside `decide_thesis`: that is the LLM adapter and must not carry strategy. Not inside
`derive_facts` either — computing the stretch belongs there, *deciding direction* does not.

**Fail-dark is preserved and is not optional.** If `session_stretch` is missing or the
predicate cannot be evaluated, fall THROUGH to the model rather than guess. A degraded
snapshot must lose the override, never invent a direction.

## D3 — the synthesized thesis, and the validation hole

Shape: `bias` from the predicate; `dol` = `build_menus` D1 for that direction; `regime`
deterministic or omitted; `confidence` — decide, noting `stands()` does not gate on it;
`falsified_if` — recorded and never acted on, so an empty list is defensible;
`evidence: []`; and a `thesis_source: "stretch_override"` stamp so no artifact can ever
read as a model call.

**The override thesis will not be contract-validated, and that is a consequence, not a
choice.** `validate_thesis` is called inside `decide_thesis`; the Analyzer never calls it.
Bypassing the model therefore bypasses validation for free — which is FORTUNATE here,
because as shown above the synthesized UP thesis fails `ARI_THESIS_BIAS` outright. Two
readings, and the plan must pick one:

- **Accept it.** The check exists to catch a model declaring a direction its own evidence
  does not support. With no evidence and no model, there is nothing for it to check.
  Coherent, and it is what the architecture already does.
- **Add an explicit exemption** keyed on `thesis_source`, so the bypass is visible in the
  validator rather than implicit in the call graph.

Recommendation: **the exemption.** The first reading is true today only because of where
`validate_thesis` happens to be called; a future refactor that validates in the Analyzer
would silently start rejecting every override. An explicit exemption states the intent.

## STATUS (2026-09-15): D1/D2/D3 SHIPPED. D0's P&L arm DEFERRED, deliberately.

Implemented and tested: the predicate, the Analyzer bypass, the synthesized thesis and the
`ARI_THESIS_BIAS` exemption. Suite 747 passed / 2 pre-existing failures.

**D0's firing-rate half WAS run, and it earned its keep**: it caught the first cut's
retrace arm as an ANTI-signal (47 days/55% vs 22 days/68% for the clock alone), which is
now removed and pinned by a test.

**D0's two-arm P&L replay is DEFERRED, with a reason — this is a decision, not an omission:**

1. **It is confounded by the entry layer.** Eleven of fourteen head-to-head runs lose money,
   and they lose the same way whether the direction was right or wrong — the 3-attempt
   budget dies inside the first ten to twenty minutes. On 06-23 the override was RIGHT and
   lost 16 pts MORE than L1 being wrong. A P&L verdict over 22 days would measure plan 36's
   problem and bill it to this one.
2. **The accuracy half has no valid yardstick.** It needs an oracle, and both definitions
   tried mislabel sessions a human reads correctly by eye: "first session extreme is the
   manipulation" fails 2026-07-23 (calls DOWN; the first real move was +227.75 UP off the
   09:30:42 low), and "first displacement >= 1x avg_1h" fails 2026-09-01 (calls DOWN; the
   day ran +277 UP). The two disagree on 52 of 94 sessions — a coin flip.
3. **A hand review already exists and is better.** Ten firing days read off the charts:
   correct on 05-18, 06-23, 07-23, 08-06, 09-01; wrong on 06-08, 06-22, 07-30; 09-10 and
   09-11 are release days that will not be traded.

**Re-open D0 when the entry layer stops dominating** (plan 36), or when an agreed oracle
exists. Running it before then risks a confident number resting on a broken yardstick —
five plausible rules have already been refuted by measurement in this cycle, and one
attempted CORRECTION (the replacement oracle) was itself wrong.

## D0 — measure FIRST. It costs zero model calls, which is the whole advantage.

1. Fire the predicate across all 94 sessions. Report: which days, how many, direction hit
   rate against the tape's oracle (first session extreme is the manipulation). Use the
   distribution to set `RETRACE_MAX` and `SIZE_FLOOR` rather than fitting them to 09-01.
2. Replay every firing day twice — override direction, and oracle direction. Both LLM-free.
   The delta is the price of being 68% right instead of 100% right, in points.
3. Where a current L1 recording exists, compare the override's direction to it.
4. **Stop rule:** if override P&L on the firing days is worse than the current engine's on
   those same days, it does not ship, whatever the 68% says.

Step 2 is the number nobody has. We know the direction hit rate; we do not know what
68%-correct direction is WORTH once the 3-attempt budget and the 25-pt stop are in play.

## Disposition of plan 35

- **D1 (`session_stretch`) — KEEP.** It is this plan's input and is already tested.
- **D2 (the S9 render block) — REVERT.** It cannot flip a direction (a context-only block
  contributes 0.000 to the net score, so it can only push a call toward NEUTRAL, never to
  the opposite side), and it re-keys `thesis_cache` for every recorded boundary. Reverting
  it keeps the cache warm.
- **D3 (the P1 tier pre-pass) — independent.** Verified inert (54/54 identical scores across
  22 boundaries). Keep as hardening or revert as churn; it has no bearing on this plan.
- **The plan FILE stays**, marked superseded. This repo keeps its dead ends
  (`32.cycle5-exit-trigger-refuted.md`), and 35 records two expensive findings: that a
  context-only block cannot move direction, and that its D3 premise was false because
  `london(cur)_low`'s week/session tags are §2.1 promotion working correctly.
