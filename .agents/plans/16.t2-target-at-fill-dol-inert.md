# 16. T2 target selection at the fill; DOL and dol_floor made inert

⚠️ Medium

## Goal

Two coupled changes to the Executor:

1. **Wire T2 to production.** The take-profit stops being the 09:20 DOL and becomes
   `build_menus`'s nearest-first `D1` re-anchored **at the entry fill** — the T2 selector
   measured in `l2-target-selection.md` §3 (12,966 pts vs T1's 11,814 on 84 corpus dates).
2. **Make the DOL and `dol_floor` inert**, on the same terms `falsified_if` already has
   (`records.would_have_falsified`): the code that derives them stays, every firing is
   RECORDED, and nothing acts on it.

## The three DOL effects being removed

`_dol_price()` feeds four sites (`executor.py`):

| line | use | after |
|---|---|---|
| 115 | `OrderSim(dol=...)` — the take-profit | **replaced** by the T2 pick, set at the fill |
| 499 | `_death` → `dol_reached` kills the plan | **record-only** (`would_have_killed`) |
| 1242 | the `dol_floor` entry veto | **record-only** (`would_have_vetoed`) |
| 1277 | `dol=` on the `intended_entry` record | unchanged — it is already only a record |

Rationale for including line 499: killing the plan blocks every later bind, so it is an
effect on ENTRY, which is exactly what the instruction removes. Leaving it would also be
incoherent — the plan would die on a level that no longer has any role.

## Deliverables

### Wave 1 — plumbing (no behaviour change on its own)

- `agent/trader/target.py` (NEW). `select_target(bars, now, direction, ticker="MNQ")`
  → the D1 menu row dict, or `None`.
  - Built from production's own path: `assemble.build_bundle(bars, now)` then
    `derive_facts.build_menus(bundle, facts_to_validator_dict(bundle))`, taking
    `menus["dol"][direction][0]`. NOT `agent/study/*` — that tree is study-only.
  - **Total**: any exception or degraded input returns `None`. It is called from inside
    the bar loop and must never raise into it.
- `agent/trader/order_sim.py`: add `set_target(price)` so the take-profit can be set
  after construction. `OrderSim(dol=...)` keeps working for the existing tests.
- `agent/trader/records.py`: add `target_selected`, `would_have_vetoed`,
  `would_have_killed`. Same one-object-per-line shape; `would_have_*` mirror
  `would_have_falsified` (recorded, never acted on).

### Wave 2 — Executor rewiring

- `__init__`: `OrderSim(dol=None)`.
- On EVERY fill (both sites — `_drive_orders`'s `sim.on_bar` events and `_enter`'s
  `fill_market`): call `select_target`, `sim.set_target(pick.price)`, record
  `target_selected`. An empty menu → no target: the position is then managed by its
  stop and the window mark only. Recorded as `target_selected` with `pick=None`.
- `dol_floor`: record `would_have_vetoed` (keeping `_veto_once`'s per-(mechanism, gap,
  reason) dedupe) and FALL THROUGH instead of returning.
- `_death`: drop the `dol_reached` branch. Record `would_have_killed` once per plan
  (one-shot latch, like `_falsify_recorded`).

## Test cases (each must be named, not "run pytest")

`agent/trader/test_target_at_fill.py` (NEW):

1. `select_target` returns the D1 row for a direction whose menu is non-empty.
2. `select_target` returns `None` on degraded bars (empty frame) — and does not raise.
3. `select_target` returns `None` for a direction whose menu is empty.
4. A resting-order fill sets the sim's target to the D1 price and writes one
   `target_selected` record.
5. A market fill (`fill_market` path) does the same.
6. An empty menu at the fill leaves the sim with NO target; the position survives to the
   window mark rather than taking profit anywhere.
7. `dol_floor` no longer vetoes: a trigger inside the floor still places/fills, and a
   `would_have_vetoed` record is written exactly once.
8. `dol_reached` no longer kills: price through the 09:20 DOL leaves `plan_alive` True,
   and a `would_have_killed` record is written exactly once (not once per bar).
9. Take-profit fires at the T2 target, not at the 09:20 DOL, when the two differ.

## Out of scope (explicitly)

- **Live latency.** `build_bundle` costs ~1.5 s on the graft's bounded 17-day history
  (~4.5 s unbounded). Replay has no wall clock to protect, but LIVE calls this from the
  1s tick callback that drives order execution. Threading or pre-warming it is a separate
  decision and is NOT done here.
- Removing `DOL_FLOOR_PTS`, `_dol_price` or the L1 `dol` field. They stay defined.
- MES-side menus (`build_menus` is MNQ-only by design).
- Continuous re-anchoring (re-picking on every bar rather than at the fill).
