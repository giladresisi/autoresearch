- **Phase 1 (merged, in master):** per-ticker level-depletion retirement latch `detect_state["__level_inv__"]` + `__level_retirements__`, fixed re-arm-until-invalidated, cautious/hypothesis target fan-out (`smt_detect.py:258 _detect_level_smts`, latch at `smt_detect.py:457-482`, skip at `smt_detect.py:301-303`).

- **The gap (Phase 1.2 target):** the warm-up only replays `[session_open(18:00), now)`. A divergence that fired BEFORE today's open (e.g. a bullish SMT at 15:14 yesterday) is neither replayed nor carried, so today's initial hypothesis can't see it. Phase 1.2 carries the still-valid **SMT occurrences themselves** forward.

### The shadow active set (the consumer we seed into)
- Computed every completed 1m bar in `session_pipeline.py:2101-2178` (the "SHADOW active-set compute" block inside `_run_smt_v2_detection`). It loads `hypothesis.json["smt_active_set"]`, drops terminal records (`collapsed_relevance != "unfulfilled"` — `hypothesis.py:317`), ingests this bar's fresh records (`hypothesis.py:441 ingest_smts`), applies Rule A/B + leg suppression, computes `dominant`, and writes back `smt_active_set` / `smt_dominant` on `hypothesis.json`.
- **The initial hypothesis reads exactly this field:** `hypothesis.py:2217  divs = hypothesis.get("smt_active_set", []) or []` → fed to `_determine_direction` / `build_hypothesis_from_direction`. So seeding carried SMTs into `smt_active_set` before the first `run_hypothesis` call makes the initial hypothesis consider them. **This is shadow** — `divs` does not currently drive `direction` to a trade (Phase 3 was net-negative and is shelved). Verify the carry mechanism, NOT P&L.
- **Record schema** (what one active-set entry / carried SMT must look like) — from `hypothesis.py:349 to_record`:
  `{kind:"smt", type:"wick"|"body", side, direction:"long"|"short", timeframe, time(ISO fire bar), leader, ref_name, tier("week"|"day"|"session"), key, fulfilled:bool, invalidated:bool, mnq_price, mes_price, mnq_lvl_price, keys:[key]}`.
  Logical dedup key = `(ref_name, direction)` (`hypothesis.py:493 _logical_key`). Detect key = `f"{ref_name}|{direction}|{type}"` (`smt_detect.py:723 _record_key`).

### Direction / threshold semantics (for the re-validation helper)
- A swept `*_low` → `direction="long"` (bullish down-sweep); a swept `*_high` → `direction="short"` (bearish up-sweep) (`smt_detect.py:321`).
- **Fulfilled** (terminal, favorable follow-through): MNQ runs `FULFILL_PTS[tier]` past the FIRE close in the SMT direction — long ⇒ price ≥ fire_close + FULFILL; short ⇒ price ≤ fire_close − FULFILL (mirror of `smt_detect.py:371-452` block (a)).
- **Invalidated** (terminal, adverse run): MNQ runs `INVALIDATE_PTS[tier]` AGAINST the fire close — long ⇒ price ≤ fire_close − INVALIDATE; short ⇒ price ≥ fire_close + INVALIDATE (mirror of `smt_detect.py:484-522` block (a2)).
- Thresholds: `FULFILL_PTS_MNQ/MES`, `INVALIDATE_PTS_MNQ/MES` (`smt_detect.py:36-47`); accessors `_fulfill_pts`/`_invalidate_pts` (`smt_detect.py:106-113`); tier via `_level_class(name)[1]` (`smt_detect.py:82`). Re-validation is **price-anchored on the MNQ leg** (the live latches measure against MNQ close), consistent with `pre_session_depleted` and block (a)/(a2).

### State layer (grounded) — and the hard persistence problem
- `smt_state.py:54 _state_paths()` resolves the five state JSONs. `global.json` is the live-vs-backtest exception (`smt_state.py:69-70`): `(_base/"global.json") if _IN_MEMORY else general_live_dir()/"global.json"`.
- In-memory mode: `_atomic_write`/`_load` key `_STORE` by full path string (`smt_state.py:236-237, 285-317`). `reset_in_memory()` (`smt_state.py:253`) **clears `_STORE` entirely** at the start of each backtest date (`backtest_smt.py:1278`).
- **Why global.json "survives" across backtest dates is NOT persistence — it is recompute.** Each date `paths.set_state_dir(per-run dir)` (`backtest_smt.py:1276-1277`) then `reset_in_memory()` wipes `_STORE`; on `on_daily_or_startup` the pipeline reloads `global.json` (returns DEFAULT, all_time_high=0), then recomputes `all_time_high = max(0, hist 60-day window max)` (`session_pipeline.py:403-419`). So global.json is rebuilt from the rolling hist window every day — there is no carried in-memory state.
- **Consequence:** prior-session SMT occurrences CANNOT be recomputed from the 60-day hist window (that would require replaying detection across the prior session, which is exactly what the warm-up does NOT do). A naive `pending_smts` stored under the per-date run dir in `_STORE` would be wiped by `reset_in_memory()` AND its path changes per date — so June-8's write would never reach June-9. **This must be solved explicitly (see §3).**

## 2. Grounded design

### 2.1 `pending_smts.json` schema
A separate global file beside `global.json`, NOT the per-session `smts.json` (whose `detect_state` is keyed by level NAME bound to today's rotating prices — reusing it would corrupt detection). Schema:

```json
{
  "entries": [
    {
      "price":      29541.5,         // anchor = the swept MNQ level price (mnq_lvl_price at fire)
      "fire_price": 29512.0,         // MNQ close at fire (fire_mnq_close) — adverse/fulfill reference
      "direction":  "long",          // "long" | "short"
      "tier":       "day",           // "week" | "day" | "session"  (_level_class(ref_name)[1])
      "type":       "wick",          // "wick" | "body" (reference; preserved for the rebuilt record)
      "fire_time":  "2026-06-08T15:14:00-04:00",  // ISO ts of the original fire bar
      "ref_name":   "prev1_day_high",// reference only (name rotates daily; NOT used for re-validation)
      "side":       "bullish",       // reference (rebuild convenience)
      "leader":     "mnq",           // reference
      "mes_price":  7421.5,          // reference (rebuild convenience; not used by re-validation)
      "session_date": "2026-06-08",  // the CME session date this SMT belongs to → age-cap
      "valid":      true             // last-known liveness when written (re-checked on wakeup)
    }
  ],
  "schema": 1
}
```
- `DEFAULT_PENDING_SMTS = {"entries": [], "schema": 1}`.
- The entry carries enough to (a) re-validate (price-anchored: `price`, `fire_price`, `direction`, `tier`) and (b) rebuild a `to_record`-shaped active-set member on ingest (`ref_name`, `type`, `side`, `direction`, `tier`, `time=fire_time`, `leader`, `mnq_price=price`/`mnq_lvl_price=price`, `mes_price`).

### 2.2 `smt_state` load/save + cross-day persistence mechanism

**Add to `smt_state.py`:**
- `DEFAULT_PENDING_SMTS` constant (above).
- A path resolver mirroring `global.json`'s live-vs-backtest branch. Add a `"pending"` entry inside `_state_paths()` (`smt_state.py:59-71`):
  ```python
  "pending": (_base / "pending_smts.json") if _IN_MEMORY
             else (paths.general_live_dir() / "pending_smts.json"),
  ```
  and `def _pending_path() -> Path: return _state_paths()["pending"]`.
- `load_pending_smts()` / `save_pending_smts(d)`.

**CHOSEN cross-day persistence mechanism — Option (a): a dedicated in-memory store that `reset_in_memory()` deliberately does NOT wipe.**
- Rationale: the carry is a *true cross-session* artifact (like ATH should be), and unlike ATH it **cannot be recomputed from the hist window** — so it must be the one piece of in-memory state that outlives a per-date reset. Keeping it in the state layer (not the harness) honors the "strategy/`smt_state`-owned" constraint: `backtest_smt.py` and `automation/main.py` are untouched; only `smt_state` (the state layer, the same layer that already special-cases `global.json`) changes.
- Implementation:
  - Add a module global `_PENDING_STORE: dict | None = None` (one process-wide slot — pending SMTs are inherently cross-session, so they are NOT keyed by per-date path the way `_STORE` is).
  - In **in-memory mode**, `load_pending_smts()` returns `_fast_copy(_PENDING_STORE)` if set, else `_fast_copy(DEFAULT_PENDING_SMTS)`; `save_pending_smts(d)` sets `_PENDING_STORE = _fast_copy(d)`. **Do NOT route through `_STORE`** (which is path-keyed and wiped per date).
  - In **live mode**, `load_pending_smts()`/`save_pending_smts()` go through the normal `_load`/`_atomic_write` against `general_live_dir()/pending_smts.json` (crash-safe on-disk, survives restart) — `_PENDING_STORE` is unused in live.
  - **Critical:** `reset_in_memory()` (`smt_state.py:253`) currently does `_STORE.clear()`. It must **NOT** clear `_PENDING_STORE` — that is the whole point (June-8's write survives into June-9 within one `run_backtest_v2` process). Leave `_PENDING_STORE` untouched there. Add a one-line comment stating this is the deliberate cross-session carry.
  - `set_in_memory_mode(enabled)` (`smt_state.py:245`) SHOULD reset `_PENDING_STORE = None` (a brand-new backtest invocation starts clean; this is called once at the top of `run_backtest_v2`, `backtest_smt.py:1232`, NOT per date — so it does not break the June8→June9 carry, which happens across the per-date `reset_in_memory()` loop, not across `set_in_memory_mode`).
  - **Live path note:** live never calls `reset_in_memory`; it reads/writes the on-disk file each session, which already persists across sessions/restarts by construction.

> Why not Option (b) (a fixed on-disk path outside the per-date run dir for backtests): it reintroduces a real file shared by every parallel/repeated backtest run in the worktree → cross-run pollution + Windows file-lock races, the exact problems in-memory mode (`smt_state.py:6-7`) was created to avoid. Rejected. Option (a) keeps backtests hermetic per-invocation while still carrying across dates within one invocation.

### 2.3 Pure re-validation helper (price-anchored; mirrors `pre_session_depleted`)
Add to `smt_detect.py`, beside `pre_session_depleted` (`smt_detect.py:116`):

```python
def pending_smt_terminal(
    direction: str, fire_price: float, tier: str,
    window_high: float, window_low: float,
) -> str:
    """Phase 1.2 (GIL-25): re-validate a carried SMT against the gap/pre-open price window.
    Returns "fulfilled" | "invalidated" | "unfulfilled". Price-anchored on the MNQ leg,
    measured from the SMT's FIRE close (mirrors _detect_level_smts blocks (a)/(a2)). Pure; total.

      long : fulfilled if window_high >= fire_price + FULFILL_PTS[tier]["mnq"]
             invalidated elif window_low  <= fire_price - INVALIDATE_PTS[tier]["mnq"]
      short: fulfilled if window_low  <= fire_price - FULFILL_PTS[tier]["mnq"]
             invalidated elif window_high >= fire_price + INVALIDATE_PTS[tier]["mnq"]
    Fulfilled takes precedence over invalidated (matching smt_status)."""
```
- Use `_fulfill_pts(tier, "mnq")` / `_invalidate_pts(tier, "mnq")`. Both terminal → the entry is dropped on wakeup; `"unfulfilled"` → survives.
- Edge: if `tier` is unknown, `_fulfill_pts`/`_invalidate_pts` fall back to the `session` row (existing behavior) — acceptable; no new constant.

### 2.4 WHERE the still-valid set is MAINTAINED (write side)
The carried set mirrors the live shadow active set. Maintain it at the **end of the SHADOW active-set block** in `_run_smt_v2_detection` (`session_pipeline.py:2168-2175`), right after `_active` is finalized and before/after the `save_hypothesis(_hyp2)` write, INSIDE the same `try/except` (so a defect can never break detection):
- Translate the finalized `_active` (the still-valid, unfulfilled records) into `pending_smts` entries via a small pure mapper `_active_record_to_pending(rec)` (place it in `session_pipeline.py` near the block, or as a `@staticmethod`). Map: `price=mnq_lvl_price (fallback mnq_price)`, `fire_price` (see note), `direction`, `tier`, `type`, `fire_time=rec["time"]`, `ref_name`, `side`, `leader`, `mes_price`, `session_date = cme_session_date(now).isoformat()`, `valid=True`.
  - **`fire_price` source:** the active-set record from `to_record` does not carry the fire MNQ close. Read it from `detect_state` by the record's detect key: `self._detect_state.get(key, {}).get("fire_mnq_close")` (set at `smt_detect.py:452`). Fall back to `rec.get("mnq_price")` if absent. (For a collapsed record use the first of `rec["keys"]`.)
- `save_pending_smts({"entries": [...], "schema": 1})`. This runs every completed 1m bar (cheap; mirror-on-write keeps it crash-safe — a live restart finds the last set on disk).
- **Live restart continuity:** because the write happens each bar to `general_live_dir()`, a mid-session crash/restart resumes with the last still-valid set already on disk; the wakeup ingest (§2.5) is cold-start-only so it won't double-seed on a warm restart.

> Note: this write is in `session_pipeline` (strategy), satisfying "strategy-owned". It uses only `smt_state` for IO.

### 2.5 WHERE it is INGESTED + re-validated + seeded (read side)
In `on_session_start`, in the cold-start block, **immediately AFTER `_warmup_replay_smts(...)` and BEFORE the `run_hypothesis` calls** (`session_pipeline.py:703-732`). Add a new method `_ingest_pending_smts(now, today_mnq_at_open)` called right after the warm-up:

```python
if _cold_start:
    self._seed_pre_session_invalidation(now)
    self._warmup_replay_smts(now, today_mnq_at_open)
    self._ingest_pending_smts(now, today_mnq_at_open)   # Phase 1.2
```
Placement rationale: after warm-up so the warm-up's per-bar shadow writes to `smt_active_set` are already in place (we MERGE into them, not overwrite); before `run_hypothesis` so `divs = hypothesis["smt_active_set"]` sees the survivors.

`_ingest_pending_smts` algorithm (exception-isolated like the shadow block):
1. `pend = _smt_state.load_pending_smts()`; `entries = pend.get("entries", [])`. If empty → return.
2. **Re-validate** each entry against the gap/pre-open window. The window is `(entry.fire_time, session_open)` on the MNQ hist leg — but for the carry case the decisive overnight test is the bars between the prior fire and TODAY's session open. Use `self._hist_mnq_1m` (the warm-up already showed hist holds pre-open MNQ bars) masked to `index > fire_time` AND `index < cme_session_start(now)`. Compute `window_high = win["High"].max()`, `window_low = win["Low"].min()`. Call `pending_smt_terminal(direction, fire_price, tier, window_high, window_low)`. Drop if result != `"unfulfilled"` (record an audit reason). If the window is empty (no bars) → keep (no evidence of a take-out).
3. **Age-cap:** drop entries with `(today_session_date - entry.session_date) > K` sessions. Define `K = PENDING_SMT_MAX_AGE_SESSIONS = 1` (carry only the immediately-prior session by default; a module constant in `smt_detect.py` or `session_pipeline.py`, documented as tunable). Count by business days between `session_date` and today's CME session date (use `pd.bdate_range` length − 1, or a simple calendar-day diff with a comment that weekends collapse — `K=1` makes Fri→Mon the boundary; if Mon should still receive Fri's SMTs, compute age in **business days**, which the executor MUST implement so Fri→Mon = age 1).
4. **Dedup vs freshly-detected SMTs:** load the current `smt_active_set` (post-warm-up) and build the set of logical keys `(ref_name, direction)` already present (reuse `hypothesis._logical_key` semantics — `ref_name` + `direction`). Drop a carried entry whose `(ref_name, direction)` already appears among today's fresh active-set members (fresh detection wins; the carried copy is stale). Also dedup carried-vs-carried by the same logical key (keep the newest `fire_time`).
   - Subtlety: `ref_name` rotates daily (`prev1_day_high` yesterday names a different price than today). The spec's dedup intent is "same-price/direction" — so ALSO treat two records as duplicates when `direction` matches AND `abs(carried.price - fresh.mnq_lvl_price) <= DEDUP_TOL_PTS` (reuse the existing dedup tolerance used by `_dedup_level_smts`; grep `DEDUP_TOL_PTS` in `session_pipeline.py`). Implement BOTH: logical-key match OR price+direction proximity.
5. **Rebuild + seed survivors** into the active set: for each surviving entry, build a `to_record`-shaped dict (kind="smt", with `time=fire_time`, `ref_name`, `direction`, `type`, `tier`, `side`, `leader`, `mnq_price=price`, `mnq_lvl_price=price`, `mes_price`, `fulfilled=False`, `invalidated=False`, `key=_record_key(...)`, `keys=[key]`), then MERGE into the existing `smt_active_set` (append; the next per-bar shadow pass will collapse/supersede via `ingest_smts`). Write back with `save_hypothesis` (read-modify-write only `smt_active_set`; leave every other field untouched, matching the shadow block's discipline).
6. Emit an audit event per ingested/dropped entry (kind `"smt-carry"`, with `reason` ∈ `{ingested, drop_fulfilled, drop_invalidated, drop_age, drop_dedup}`) via `self._emit` so the regression `events.jsonl` shows the carry (used by verification). Keep `source="v2-carry"`.

> Shadow-only note: seeding `smt_active_set` only affects `divs` in `run_hypothesis`, which is shadow (does not drive a live trade in this branch). No SMT→direction wiring is added. The feature is foundational/trade-neutral.
