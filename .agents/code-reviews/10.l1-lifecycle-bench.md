## MEDIUM

```
severity: medium
file: agent/bench/run_bench.py
line: 110 (also 89, and score.py latency fields)
issue: decisions.jsonl embeds wall-clock latency → stub cross-run byte-equality is non-deterministic (flaky test).
detail: In stub mode decide_thesis still runs through run_agent._run_call, which records
  latency = round(time.perf_counter()-t0, 3) per attempt and as latency_total. Those wall-clock
  values are written verbatim into decisions.jsonl (latency_total_sec, attempts[].latency_sec).
  test_run_bench.test_stub_end_to_end asserts _read(dec_a)==_read(dec_b) across two independent
  stub runs (line 65). A stub call is normally sub-ms → 0.0, but a cold/loaded call that crosses
  ~0.5ms rounds to 0.001, making the two files differ intermittently. The plan's real determinism
  guarantee is over LIFECYCLES (which carry no latency and ARE stable) and over rescore (which does
  not depend on latency); the decisions-level byte-equality assertion over-reaches into a wall-clock field.
suggestion: Either (a) restrict the stub-determinism assertion to lifecycles.jsonl only (the real
  guarantee), or (b) compare decisions with the latency fields stripped, or (c) zero out
  latency for StubBackend paths. Rescore byte-stability itself is unaffected (it re-serializes the
  logged records), so this is test robustness, not a product-determinism break.
```

```
severity: medium
file: agent/bench/run_bench.py
line: 243-244 (make_backend for mode=="real")
issue: the "real spend only via per-run shell env, never .env defaults" guardrail is not enforced.
detail: run_bench(mode="real") calls make_backend(backend_name, model). make_backend
  (run_agent.py:494) unconditionally load_env_file(REPO_ROOT/.env) and, when --backend is omitted,
  auto-selects a provider from ANY key it finds — including one sitting in the worktree .env. So a
  `--mode real` run with no shell key but a populated repo .env will silently spend, contradicting
  plan §Repo-standing-constraints and global CLAUDE ("Real-API spend only via per-run shell env,
  never .env defaults"). The churn cap (default 20) does bound blast radius, and skeleton prompts
  fall to 1 failsafe lifecycle/day, so exposure is small — but the stated guardrail is not actually
  a code guarantee.
suggestion: In real mode, gate on a shell-provided key before make_backend loads .env — e.g. assert
  os.environ.get("OPENROUTER_API_KEY") or ("ANTHROPIC_API_KEY") is present in the process env, or
  pass make_backend an env_path pointing at a non-existent file so only the shell env is consulted.
  At minimum, document that .env keys are live in real mode.
```

## LOW

```
severity: low
file: agent/bench/run_bench.py
line: 178-180 vs 251
issue: per-lifecycle scoring enrichment is not persisted to lifecycles.jsonl (only into scorecard.md).
detail: run_date/rescore_date write lifecycles.jsonl BEFORE scoring, so on-disk false_kill /
  late_kill_adverse are always null. score.score_date enriches a copy that flows only into
  report.write_scorecard (a markdown table). The machine-readable jsonl therefore never carries the
  two headline quality signals the internals effort is meant to "watch move". aggregate.tsv carries
  per-day rollups but not per-lifecycle scores.
suggestion: After scoring in run_bench (line 251), re-write <date>/lifecycles.jsonl from the
  enriched lifecycles so the jsonl is the canonical scored artifact. Keep it deterministic
  (already sort_keys) so rescore stays byte-stable.
```

```
severity: low
file: agent/bench/score.py
line: 58 (_false_kill window)
issue: false_kill lookahead is silently truncated at session end, undercounting late-day deaths.
detail: The window uses source.session_bars(date), which stops at ~16:5x ET. A death at, say,
  15:30 gets <1.5h of the 4h horizon; a death near the close gets ~0 bars → forced False even if
  the DOL is touched next session. This is defensible (mirrors the intraday annotate/prepare_cuts
  convention) but is not stated, so the metric reads as a full-4h test when it is not.
suggestion: Note the session-end truncation in the docstring, or (if next-session touches matter)
  extend the lookahead frame past 16:59 for late deaths.
```

```
severity: low
file: agent/bench/run_bench.py
line: 298-300
issue: CLI summary prints "None%" when a metric is None.
detail: On an all-failsafe run coverage_pct is 0.0 but failsafe_pct can be a number; on an
  empty/degenerate run agg.get('failsafe_pct') / 'coverage_pct' may be None, rendering
  "failsafe=None%". Cosmetic only.
suggestion: Coalesce None → 0 (or "n/a") in the f-string.
```

## NIT

```
severity: low
file: agent/bench/lifecycle.py
line: 357 (_market_view) and 292 (per-bar call in _run_standing)
issue: O(n^2) per-bar re-slicing / resampling over the walk.
detail: _market_view does upto = walk[walk.index <= ts] (a full boolean-mask scan) every bar, and
  _closes_by_tf resamples the growing frame every bar when need_closes. n is bounded by TTL
  (≤180 bars) and mv is only built when predicates exist, so this is not a real hotspot today — but
  it is quadratic per lifecycle. If theses ever carry n_closes_beyond over long TTLs this bites.
suggestion: Walk by integer position (iloc) and slice walk.iloc[:i+1], and/or maintain rolling
  per-tf close lists incrementally instead of re-resampling.
```

```
severity: low
file: agent/bench/conftest.py
line: 10-13 (also facts.py:29-31, run_bench.py:34-37, per-test files)
issue: sys.path.insert(0, ...) pollutes the global import path for the whole pytest session with
  bare-name bench modules (config, score, report, facts, lifecycle, run_bench).
detail: These are inserted at the FRONT of sys.path, so `import config` etc. resolve to the bench
  package for the entire session once the bench conftest loads. No collision exists in the repo
  today (verified: no other top-level config/report/score/facts/lifecycle modules, no bare imports
  of those names elsewhere), so the full suite stays green — but the names are generic and
  collision-prone for future top-level modules or a combined `pytest agent/` + `tests/` run.
suggestion: Prefer package-relative imports (from agent.bench.config import ...) or append rather
  than insert(0); not required now, just risk-reducing.
```
