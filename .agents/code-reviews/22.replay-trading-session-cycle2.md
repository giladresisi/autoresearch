severity: high
file: backtest_smt.py
line: 1250
issue: replay_slice emits a DUPLICATE 1m bar at hist_end, holding a partial (59/60 s) minute
detail: `bridge_src` is selected with `bars_1s.index > hist_end`, but `hist_end` is a 1m
  bin LABEL, not the end of that bin. The 1s bars from `hist_end + 1s` to `hist_end + 59s`
  belong to a minute that is ALREADY the last row of `hist_1m`. `resample("1min",
  label="left")` re-bins them into a second row stamped `hist_end`, and the subsequent
  filter (`bridge.index < window_start`) does not remove it, so `pd.concat` produces a
  non-unique index.

  Reproduced against the real parquet
  (`<global>/general/main/2026-09/MNQ_1s.parquet`, hist cut at 2026-08-11 18:00):

      hist_end: 2026-08-11 16:59:00-04:00
      index unique? False
      2026-08-11 16:59:00-04:00  Open 29648.75  ... Volume 410.0   <- true bar (60 s)
      2026-08-11 16:59:00-04:00  Open 29648.00  ... Volume 386.0   <- bridge dup (59 s)

  This frame is `hist_mnq_1m` / `hist_mes_1m` — passed straight into
  `SessionPipeline(hist_mnq_1m, hist_mes_1m, ...)` (backtest_smt.py:1521) and forwarded to
  the graft as `hist_mnq` / `hist_mes`, where `TraderGraft._frames` (graft.py:128)
  concatenates it into the Analyzer's and Executor's view. So the last minute before the
  overnight session is double-counted, with a wrong `Open` and `Volume`, in level/FVG
  detection and in `run_daily`. A non-unique DatetimeIndex additionally makes `.loc[ts]`
  return two rows and makes `reindex`/`asof` raise `InvalidIndexError` — and every such
  raise is swallowed by `TraderGraft.on_bar`'s blanket `except Exception: pass`
  (graft.py:104), so it degrades silently rather than failing the run.

  The module's own guard test — `test_replay_window.py::test_history_and_slice_meet_
  without_overlap` — passes only because the fixture builds `hist_1m` from a SEPARATE
  `date_range` starting at 17:59 while `bars_1s` starts at exactly 18:00, so the 1s frame
  contains no bars inside the hist's final minute. Real geometry (both frames derived from
  one continuous tape) always does.
suggestion: filter the resampled bridge to bins strictly after hist_end:

      bridge = bridge[(bridge.index > hist_end) & (bridge.index < window_start)]

  Verified: index becomes unique, the 16:59 bar keeps Volume 60/60, the overnight session
  is still fully covered (920 bars in the synthetic case), and `hx.index[-1] < s.index[0]`
  still holds. Add a regression test whose `hist_1m` is the 1m resample of the SAME 1s
  tape (searchsorted-cut at 18:00) and assert `hx.index.is_unique`.

issue: the recorded call meta is written to the cache but can never be read back, so a
  warm replay records call_meta = {} — contradicting the documented "BOTH paths" claim
detail: `ThesisCache.put` stores `{"meta": ...}` (thesis_cache.py:92) but
  `ThesisCache.get` (thesis_cache.py:81-89) returns only `blob["thesis"]` and drops

  and `Analyzer._split_result` filters meta to `_META_FIELDS =
  ("latency_sec","usage","cost","retries","verdict")` (analyzer.py:139), so both keys are
  discarded and `self._meta` ends up `{}`.

  Confirmed on disk across the 14 runs under `regression/sessions/2026-08-12/`:

      19-27-05  call_meta = {latency_sec: 63.664, usage: {...}, retries: 2, verdict: failsafe}
      19-31-29  call_meta = {latency_sec: 25.937, usage: {...}, retries: 0, verdict: clean}
      19-34-21 .. 19-58-33  call_meta = {}       <- every warm replay

  `analyzer.py:409-415` (`call_meta`) documents "Recorded on BOTH the live and replay
  paths so the arrival-latency constant can be re-fitted from real data" — that is only
  true of the two SEEDING runs. Gate 8's
  `test_gate_call_outcome_both_paths.py::test_the_replay_path_persists_call_meta_in_
  thesis_state` globs `regression/sessions/2026-08-12/*/thesis_state.json` and asserts
  `any(...)`, so it passes purely on the presence of those two seeding directories. Delete
  them (or run the gate on a machine that only ever did warm replays) and the assertion
  fails — the gate is currently vacuous for the path it claims to cover.
suggestion: have the cache return the whole record and replay the recorded provenance:

      # thesis_cache.py
      def get_record(self, key):   # returns (thesis, meta) or (None, {})
          ...
      # cached_backend.py, on a hit
      thesis, rec_meta = self._cache.get_record(key)
      return thesis, dict(rec_meta, cached=True, key=key)

  Also add `"cached"` and `"key"` to `analyzer._META_FIELDS` so `thesis_state.json` says
  whether the thesis came from a recording. Then tighten the gate to assert on the newest
  run dir rather than `any()` over all of them.

file: agent/trader/analyzer.py

issue: the `maybe_run` exception handler clears `_thesis` but leaves `_meta` stale, and
  persists outside the lock
detail: `maybe_run`'s `except Exception:` (analyzer.py:273-276) does
  `self._thesis = None; self._save()`. `_meta` is untouched, so `thesis_state.json` is
  written with `"thesis": null` next to the PREVIOUS call's `call_meta` — provenance
  attached to a thesis that no longer exists. `_call`'s handler (analyzer.py:376-380) was
  correctly updated to clear `_meta` under the lock in this changeset; this one and
  `_arm`'s (analyzer.py:355-358) were not. The missing lock is pre-existing, but in
  threaded live mode it now races a worker's `_save()` over one more field.
suggestion: mirror `_call`'s handler in both places:

      except Exception:
          with self._lock:
              self._thesis, self._meta = None, {}
              self._save()
          return None

issue: `_prompt_parts` silently degrades the cache key if a `run_agent` symbol is renamed
detail: `getattr(ra, "_TASK_THESIS", "")` and `(getattr(ra, "DEFAULT_MODELS", {}) or

  the runtime path degrades silently rather than refusing.
suggestion: read them as hard attributes (`ra._TASK_THESIS`, `ra.DEFAULT_MODELS[backend]`)
  and let an `AttributeError`/`KeyError` fail the run loudly; a missing key input must
  never be a silent empty string.

## Deliberate design choices reviewed and accepted

- **`run_replay` raises after the date's run rather than during it** (replay.py:177).
  Correct: `Analyzer._call` and `TraderGraft.on_bar` both swallow every exception, so a
  `NetworkCallRefused` raised inside the bar loop is invisible. Surfacing the backend's
  counters after the fact is the only way to make gate 5 falsifiable. Losing already-
  completed dates from `out` on a raise is acceptable for a fail-loud gate.
- **`_arm_env`** (replay.py:120) correctly restores `ACT_TRADER_ARM_HHMM`, including the
  "was unset" case. Note that `build_replay_trader` called directly (as several unit tests
  do) still leaks the variable — documented in its own docstring, and no test currently
  passes `arm_hhmm` that way.
- **Failsafe verdicts are not cached** (cached_backend.py:105). Genuinely important:
  `decide_thesis` substitutes a synthetic NEUTRAL block past MAX_RETRIES rather than
  returning `None`, so the plan's `None` guard never fires on the real path. The
  08-12 19-27-05 run on disk (`retries: 2, verdict: failsafe`) is the evidence.
- **Analyzer locking.** `standing_thesis`, `armed_at` and `call_meta` all take `_lock`;
  `_call` computes outside it and publishes `_health`/`_thesis`/`_meta`/`_save` inside it.
  No lock is held across a backend call, and `_save` never re-acquires, so there is no
  deadlock or lock-held-during-IO path. `call_meta` returns a shallow `dict(self._meta)` —
  the `usage` sub-dict is shared, which is harmless for read-only provenance.
- **Legacy 1s slice restructure** (backtest_smt.py:1565-1574) preserves the original
  expressions verbatim in the `else` branch; `_replay_sess` is initialised at the top of
  the per-date loop so the 1m branch cannot `NameError`.
