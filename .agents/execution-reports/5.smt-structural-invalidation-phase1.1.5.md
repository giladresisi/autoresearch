## Implementation Summary

### Change A — detection lifecycle rework (`smt_detect.py`, COMMIT 1)
- **Removed the adverse-run invalidation post-loop pass.** Detection no longer sets `st["invalidated"]` from an adverse fire-close run, and no longer appends to the `__invalidations__` trail (the key may now never appear). `_invalidate_pts` / `INVALIDATE_PTS_*` constants left defined (only the usage was removed).
- **Added a supersession pass.** A fresher same-direction (same `rec_type`) record retires OLDER still-pending fired records across any level/tier → sets `st["superseded"]=True` and appends a `__supersessions__` audit row. Informational-only: never mutates `records`/`fired`/`armed`/`fulfilled`/fire fields. **Review-found bug fixed:** same-batch sibling fires must NOT supersede each other — all this-batch fresh keys are excluded via a `fresh_keys` set.
- **Extended the per-ticker depletion latch.** On a NEW flip it marks fired-open record(s) on that level+direction `st["retired_depleted"]=True` and records `retired_records` in the `__level_retirements__` event.
- **Made `pending_smt_terminal` 2-state** (`"fulfilled"|"unfulfilled"`; dropped the adverse-run `"invalidated"` branch). Added a level-relative depletion backstop inline in `revalidate_and_filter_pending` with a new audit reason `"drop_depleted"` (replaces `"drop_invalidated"`), guarded on `e["price"]` present.
- **Extended `smt_status`** so `st["superseded"]` / `st["retired_depleted"]` (and legacy `"invalidated"`) all fold to `"invalidated"`, with `fulfilled` precedence first. This is the SOLE active-set integration point — `collapsed_relevance` (hypothesis.py) already treats `"invalidated"` as terminal, so the §A.2.7 `session_pipeline.py` write-side fallback was NOT applied (no out-of-scope edit needed).

### Change B — contiguous-range carry routing (COMMIT 2)
- `smt_state.set_in_memory_mode(enabled, *, reset_pending=True)` — preserves `_PENDING_STORE` when `reset_pending=False`.
- `backtest_smt.run_backtest_v2(..., reset_pending=True)` — threaded into `set_in_memory_mode`.
- `regression.py` — `_parse_date_tokens` now expands `:` ranges via `pd.bdate_range` (weekend dates dropped; explicit single dates verbatim); new `_is_next_bday` helper; per-date loop passes `reset_pending=(i==0 or not next-bday)` so a contiguous business-day range carries the store and a gap does not.

## What was tested

- An adverse fire-close run (short and long) NO LONGER invalidates a fired record — it stays `fired`, non-terminal, with no `__invalidations__` trail created.
- No `__invalidations__` trail is created across several consecutive adverse bars.
- Fulfillment is still terminal (a favorable follow-through fulfils and, for a fixed level, departs → re-arms).
- A dynamic re-arm still resets `fired`/`fulfilled`/`superseded`/`retired_depleted` to False with no invalidation involved.
- The records list is byte-identical with vs. without an adverse run (informational-only guarantee).
- A later same-direction record on a different level supersedes the earlier one (`superseded=True`, one `__supersessions__` row with correct `superseded_by`/direction/type/ref_name).
- Two same-direction levels swept in ONE batch do NOT supersede each other and create no supersession trail (the review-found regression case).
- An opposite-direction fire never supersedes a pending record of the other direction.
- Supersession does not change the records list (informational-only).
- A superseded fixed level that departs + re-touches + re-fires clears `superseded`.
- The depletion latch marks the fired record terminal on flip (`retired_depleted=True` + `retired_records` in the `__level_retirements__` event) for both `*_high`/short and `*_low`/long.
- The depletion backstop fires only on the latch flip and is idempotent across further depleting bars.
- `pending_smt_terminal` returns `"unfulfilled"` (not `"invalidated"`) for an adverse window, for both long and short (carryable).
- `revalidate_and_filter_pending` drops a level-depleted carried entry with reason `"drop_depleted"`, and KEEPS an adverse-but-within-depletion entry (proves overnight-gap adverse runs no longer kill the carry).
- `smt_status` folds `superseded` and `retired_depleted` to the terminal `"invalidated"` token, preserves `fulfilled` precedence over the new flags, and leaves a plain unfulfilled entry unaffected.
- `set_in_memory_mode` resets `_PENDING_STORE` by default but preserves it when `reset_pending=False`; `reset_in_memory()` still preserves it (Phase-1.2 invariant locked).
- Contiguity routing: a contiguous range carries (2nd date `reset_pending=False`); Fri→Mon carries across the weekend; a non-contiguous explicit list does NOT carry; a `:` range spanning a weekend is filtered to business days only with correct per-date `reset_pending`; a single date starts clean.
- `run_backtest_v2` threads its `reset_pending` kwarg through to `set_in_memory_mode`.
