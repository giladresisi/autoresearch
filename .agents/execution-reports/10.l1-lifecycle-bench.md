### Phase 1 — Lifecycle engine (`agent/bench/lifecycle.py`)
The L1-subset state machine, driven by an injected decision provider + a 1m bar frame (no
facts, no LLM in this module). Per date it walks bars and plays out each decision:

- **Standing** (confident + directional: gate HIGH/MEDIUM and bias UP/DOWN) — arrival-gated
  per-bar evaluation of exhaustion (`completed` = DOL drawn or an `exhausted_if` predicate),
  falsification (`falsified_if`), the code-injected safety nets, and the confidence-tiered
  TTL; excursions (MFE/MAE), distance-to-DOL covered.
- **Waiting** (low-conf / NEUTRAL / failsafe) — does not stand; waits on `recall.events` /
  `max_age_min`. A failsafe waiting-lifecycle is labelled `failsafe` (quality dominates).
- Re-call at every death (+latency); churn cap aborts the day (`churn_cap`); an open
  lifecycle at 16:59 closes `session_end`.

Sweep/depletion state evolves over the walk (inclusive wick cross == engine convention;
exact per-ticker `DEPLETE` thresholds). Predicate evaluation reuses `eval_predicate` over a
`MarketView` built per bar; per-timeframe closes are computed lazily (only when an
`n_closes_beyond` predicate is present) to keep the walk O(n).
Tests (`test_lifecycle.py`, 11): completed, falsified + re-call scheduling, arrival gating,
low-conf recall + max_age, TTL tiers (HIGH survives past the MEDIUM TTL), acceptance_flip &
opposite_extreme (on/off), churn cap, session_end, failsafe labelling.

### Phase 2 — Facts + call integration (`agent/bench/facts.py`, `run_bench.py`)
`ParquetFactsSource` loads the main 1s (facts) + 1m (walk) parquets once, then builds the
S0–S7 fact sheet as of **strictly before** an arbitrary boundary timestamp, mirroring
`calibration/prepare_cuts.py` exactly (17-day 1s primary slice + full-history hist frames +
raw-parquet ATH). A degraded/insufficient snapshot is returned marked (failsafe, no API
call), never raised. `run_bench.make_live_provider` builds facts → `decide_thesis` (stub or
real backend) → the confidence gate → a `BenchDecision`, logging one `decisions.jsonl`
record per call (full thesis JSON, all attempts + violations + usage + latency + facts_hash,
plus a `bench` block of engine inputs for replay).
Tests (`test_facts.py` 3, `test_run_bench.py` 2): **facts byte-parity with prepare_cuts** on
the `2026-06-25_0850` burned cut (identical content hash), lookahead guard (`max_ts <
boundary`), degraded-before-data-start, stub end-to-end (lifecycles.jsonl + decisions.jsonl
with linked ids), stub determinism.

### Phase 3 — Scoring + scorecards (`agent/bench/score.py`, `report.py`)
Per-lifecycle enrichment: `false_kill` (after a non-completion death, was the dead DOL still
touched within H=4h — annotate.py horizon convention) and `late_kill_adverse` (give-back pts
from the peak-favorable point to the falsification fire). Per-day metrics: completion rate,
false-kill count, median late-kill adverse, churn, coverage (% of session minutes under a
standing thesis), failsafe rate, API cost (list-price estimate), latency. `report.py` renders
the per-date `scorecard.md` and the run `aggregate.md` / `aggregate.tsv` with the per-regime
split (static date→regime map). `rescore` re-runs this identically ($0, byte-stable).
Tests (`test_score.py`, 8): false_kill true/false + completed-has-none, distance-covered,
late_kill_adverse, aggregate regime split, scorecard renders with zero directional theses
(the run-#0 shape), and the churn-cap-abort **rescore regression** test.

### Phase 4 — CLI + validation runs (`run_bench.py` CLI)
`python -m agent.bench.run_bench --dates … --mode stub|real|rescore [--run-id …]
[--latency-sec N] [--safety-net …] [--churn-cap N] [--backend …] [--main-dir …]
[--source-run …]`. Unknown safety-net names are rejected. Outputs under
`agent/bench/runs/<run-id>/` (gitignored).

## Divergences from the plan

1. **Engine file named `lifecycle.py`, not `engine.py`.** The plan's Phase-1 filename would
   have created a bare module name `engine` that shadows the production
   `agent/decisions/engine.py` (imported bare as `from engine import DecisionEngine` by
   `agent/decisions/test_engine.py`), breaking `pytest agent/` collection. The scope guard
   forbids touching `agent/decisions`, so the bench module was renamed to `lifecycle.py`
   (and its test to `test_lifecycle.py`). All bench-internal module names are otherwise
   repo-unique. No behavioral change.
2. **Facts primary df is the 1s path (matching prepare_cuts), not the 1m
   `facts_adapter._with_history` path.** The plan referenced both for the offline builder,
   but the *parity gate* is against `prepare_cuts` (1s), so the 1s slice is used and
   byte-parity is proven; the 1m adapter would not reproduce the burned-cut hash.

## Notes / follow-ups

- The API-cost figure is a **list-price estimate** (Haiku 4.5 rates) from logged token
  usage; it is structure-reserved and not a billed number.
- Higher-timeframe (`n_closes_beyond`) closes use the last close per bin (a deterministic
  bench approximation); the workhorse predicates (`price_beyond`, `level_swept`, time/clock)
  are exact. Irrelevant to run-#0 (skeleton predicates never validate).
- **API-error robustness (added in the fix loop):** a backend/transport exception during a
  live call now degrades that call to a failsafe decision (logged with
  `degraded_reason=api_error:*`) rather than aborting the whole multi-date run — spec §4
  failure policy. Covered by `test_score.py::test_api_error_degrades_to_failsafe`.
- The bench, by construction, cannot exercise a *standing* lifecycle end-to-end on real API
  until the internals effort makes the confidence gate return HIGH/MEDIUM and the L1 prompt
  teach the closed vocabulary; the stub/scripted tests cover the standing machinery.
