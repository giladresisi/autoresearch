## Executive Summary

Implemented cross-session carry of still-valid SMT occurrences so that an SMT firing in the prior CME session (e.g. a bullish SMT at 15:14 yesterday) — which the warm-up replay window `[session_open, now)` never sees — is persisted, re-validated against the overnight gap window on the next cold start, and seeded into `smt_active_set` before the first hypothesis. The carry is shadow-only (it feeds `divs` in `run_hypothesis`, which does not drive a live trade on this branch). A code review caught a HIGH-severity placement bug that made the carry a no-op on its primary path; it was fixed and guarded with an end-to-end regression test.

## Implementation Summary

### `smt_detect.py` (pure layer)
- `PENDING_SMT_MAX_AGE_SESSIONS` constant (default 1 — carry only the immediately-prior session, tunable).
- `pending_smt_terminal(direction, fire_price, tier, window_high, window_low)` — pure, total re-validation helper. Price-anchored on the MNQ leg, measured from the SMT's fire close, mirroring the `_detect_level_smts` (a)/(a2) blocks. Returns `"fulfilled" | "invalidated" | "unfulfilled"`; fulfilled takes precedence. Reuses `_fulfill_pts`/`_invalidate_pts` (unknown tier falls back to the `session` row — no new threshold constants).
- `_pending_age_bdays(...)` — business-day age between `session_date` and today's CME session date (Fri→Mon = age 1).
- `revalidate_and_filter_pending(...)` — the core ingest logic factored out as a pure function (re-validate / age-cap / dedup / build survivor records) for direct unit testing.
- `_pending_entry_to_record(...)` — rebuilds a `to_record`-shaped active-set member from a pending entry.

### `smt_state.py` (state layer)
- `DEFAULT_PENDING_SMTS = {"entries": [], "schema": 1}`.
- `"pending"` branch in `_state_paths()` mirroring the `global.json` live-vs-backtest exception: live → `general_live_dir()/pending_smts.json`; backtest → `state_dir()` base. `_pending_path()` accessor.
- `_PENDING_STORE` module global (one process-wide slot — pending SMTs are inherently cross-session, NOT path-keyed like `_STORE`).
- `load_pending_smts()` / `save_pending_smts(d)` — in-memory mode routes through `_PENDING_STORE` (deep-copied), live mode through `_load`/`_atomic_write` on disk.
- `set_in_memory_mode(...)` now resets `_PENDING_STORE = None` (a brand-new backtest invocation starts clean).
- `reset_in_memory()` deliberately does **NOT** clear `_PENDING_STORE` (commented) — this is the cross-session carry: June-8's write survives the per-date reset into June-9 within one `run_backtest_v2` process.

### `session_pipeline.py` (strategy — carry/ingest logic)
- `_active_record_to_pending(rec)` — maps a finalized active-set record to a pending entry. `fire_price` is read from `detect_state[key]["fire_mnq_close"]` with a `rec["mnq_price"]` fallback; `timeframe` is preserved on the round-trip.
- `_ingest_pending_smts(now, today_mnq_at_open)` — cold-start read side, exception-isolated: load pending, re-validate against the overnight window, age-cap, dedup (logical key OR price+direction proximity), seed survivors into `smt_active_set`, and emit `smt-carry` / `v2-carry` audit events per ingested/dropped entry.
- Write-side hook inside the shadow `try/except` of `_run_smt_v2_detection` — mirrors the finalized `_active` set into `pending_smts.json` every completed 1m bar (crash-safe; a live restart finds the last set on disk).
- `_ingest_pending_smts` is called in `on_session_start` on **both** the force_reset and no-force_reset cold-start paths, AFTER any hypothesis reset and BEFORE `run_hypothesis`.

## Divergences from Plan

### Divergence #1: ingest placement corrected after code review (HIGH bug)

**Classification:** ✅ GOOD (caught + fixed pre-commit)

**Planned:** Call `_ingest_pending_smts` on cold start after warm-up and before `run_hypothesis`.
**Actual (initial):** The ingest was placed inside the cold-start block BEFORE the `force_reset` save. That save overwrote `smt_active_set` with `DEFAULT_HYPOTHESIS` (empty) and returned before `run_hypothesis`, making the carry a no-op on its primary path — **backtest and live both pass `force_reset=True`**.
**Fix:** Moved the ingest to AFTER the `force_reset` save and BEFORE `run_hypothesis` on both branches. Added `TestColdStartIngestEndToEnd`, which drives the real `on_session_start(force_reset=True)` without stubbing the ingest, as a regression guard.
**Root Cause:** Plan described placement relative to warm-up but did not account for the `force_reset` save clobbering `smt_active_set` on the path both callers actually use.
**Impact:** Positive — without the fix the feature would silently do nothing in backtest and live. **Justified:** Yes.

### Divergence #2: `timeframe` preserved on round-trip (LOW finding)

**Classification:** ✅ GOOD

**Planned:** Map the active record to a pending entry and back.
**Actual:** Initial mapper dropped `timeframe`; code review flagged it. `_active_record_to_pending` now preserves `timeframe` so the rebuilt record is faithful.
**Impact:** Neutral-to-positive (correctness of the rebuilt record). **Justified:** Yes.

## What was tested

- `pending_smt_terminal` returns `"fulfilled"` for a long when the window high reaches fire + FULFILL[tier].
- `pending_smt_terminal` returns `"invalidated"` for a long when the window low reaches fire − INVALIDATE[tier].
- The short-side mirror of both fulfilled and invalidated outcomes.
- An entry whose window stays within both thresholds returns `"unfulfilled"` (survives).
- When a window crosses BOTH thresholds, fulfilled takes precedence over invalidated.
- An unknown tier falls back to the `session` threshold row without raising.
- `load_pending_smts()` returns a copy of `DEFAULT_PENDING_SMTS` when none is stored (no shared mutation).
- `save_pending_smts` then `load_pending_smts` round-trips an equal payload in in-memory mode.
- `_pending_path()` resolves under `general_live_dir()` in live mode and under the `state_dir()` base in backtest mode.
- `_PENDING_STORE` survives `reset_in_memory()` (the cross-day carry), contrasted against a daily/global value that IS wiped.
- `set_in_memory_mode(True)` resets `_PENDING_STORE` to empty.
- A still-valid carried entry whose overnight window does not breach either threshold is returned as a correctly-shaped `to_record` member.
- A carried entry whose overnight window ran FULFILL beyond fire is dropped with reason `drop_fulfilled`.
- A carried entry whose overnight window ran adverse INVALIDATE is dropped with reason `drop_invalidated`.
- An entry with no bars in the overnight window is kept (no evidence of take-out).
- A carried entry whose `(ref_name, direction)` already appears in today's fresh active set is dropped (fresh wins).
- A carried entry within `DEDUP_TOL_PTS` of a same-direction fresh member (different ref_name) is dropped on price proximity.
- Two carried entries with the same logical key keep the newest `fire_time`.
- An entry older than `PENDING_SMT_MAX_AGE_SESSIONS` business days is dropped with reason `drop_age`.
- Yesterday's (1 business day) entry is kept at default K=1.
- A Friday entry seen on Monday counts as age 1 business day and is kept (business-day, not calendar-day, counting).
- On a real cold start (`on_session_start(force_reset=True)`), a pre-written still-valid pending entry appears in `hypothesis.json["smt_active_set"]` and emits a `smt-carry` / `ingested` event (the regression guard for Divergence #1).
- A non-cold-start (pre-populated detect_state) does not re-ingest — no double-seed.

## Challenges & Resolutions

**Challenge 1:** `force_reset` save clobbered the seeded `smt_active_set`.
- **Issue:** Ingest ran before the force_reset save, which reset the hypothesis to empty and returned before `run_hypothesis` — carry was a no-op on the path both backtest and live use.
- **Root Cause:** Placement was relative to warm-up, not to the force_reset save/return.
- **Resolution:** Moved ingest after the save and before `run_hypothesis` on both branches; added `TestColdStartIngestEndToEnd` driving the real path.
- **Prevention:** End-to-end cold-start tests should not stub the ingest — exercise the real `on_session_start` so save-ordering bugs surface.

**Challenge 2:** Cross-date persistence under in-memory backtest.
- **Issue:** `_STORE` is path-keyed and wiped by `reset_in_memory()` per date, so a naive store would never reach the next date.
- **Resolution:** Dedicated process-wide `_PENDING_STORE` that `reset_in_memory()` deliberately does not clear (and that `set_in_memory_mode` resets per invocation). Kept entirely in `smt_state` (the layer already special-casing `global.json`); harness untouched.
