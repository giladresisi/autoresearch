## Known limitation (explicit — POC scope)

**The runtime cannot reach `IN_POSITION` yet.** In `primary` mode the executor drives
`on_session_open`/`on_bar` (thesis/plan scheduling + predicate evaluation), but nothing calls
`on_fill` / `on_stop_out` / `on_profitable_exit`, because the mechanism adapter's armed
mechanisms are not yet wired to the fill machinery (deferred with the level internals). As a
direct consequence:
- The `IN_POSITION` transitions, the attempt counter, `on_dol_falsified`-while-open, and
  `RiskGate.record_exit` are exercised only by unit tests, never at runtime.
- `RiskGate.record_exit(-1.0)` is a **placeholder magnitude** — until real fill P&L is fed in,
  the daily-loss dollar cap is effectively inert in a live/backtest primary run (max-trades and
  the external-halt path still function).

This is safe for the current POC (stub/real-API both produce zero trades), but it must be the
first wiring completed when the internals effort starts.

## First input for the internals work

The real-API L1 call returned predicate objects **outside the closed vocabulary** (`type:
None`) on all three attempts, so the validator rejected them and the call fell to the NEUTRAL
fail-safe. This is expected — the L1 task prompt is a minimal skeleton that does not yet teach
the model the predicate vocabulary. It confirms "constraints live in code, not prompts" (spec
§5): the validator, retry loop, fail-safe, bus, and audit all behaved correctly. The internals
effort's first job is the L1/L2 KB + task content that teaches the closed predicate/mechanism
vocabularies so a real thesis can pass validation.

## Deviations from the plan

1. **v2 async worker is a new class** (`decision_service.py`) reusing the DecisionWorker
   threading/coalescing idiom, rather than extending `agent/decisions/async_wrapper.py` in
   place — the v1 DecisionWorker is tightly coupled to the v1 DecisionEngine and extending it
   risked destabilizing the shadow observation engine's byte-identity + tests. Coalescing +
   supersede-staleness are implemented and tested. (Reviewed and accepted.)
2. **Per-bar cost optimization**: the full facts snapshot is built only when standing decisions
   reference level state (else a light price+closes MarketView), with a lazy `facts_ref` thunk,
   so primary/real-API runs are not dominated by per-bar `compute_facts`. Off path untouched;
   byte-identity unaffected.
