## Executive Summary

Extended the cross-session SMT carry to **FILL (FVG-divergence) SMTs**, mirroring the already-merged Phase 1.4 reversal/LEVEL carry. Fills were previously carried via the OLD relevance-gated active-set path (`_active_record_to_pending`), so a fired-but-backed-off (still-unfulfilled) fill could be dropped from `_active` by the proximity gate and never written. They now source from the **producer lifecycle** (`detect_state`) via a new `_detect_state_fill_entries`, so a backed-off unfulfilled fill carries forward and is re-validated against the overnight gap on the next cold start. The change is shadow-only (SMT does not drive trades on this branch). A code-review finding (Medium) was fixed: defensive coercion of a present-but-`None` fire anchor so it can no longer raise `TypeError` and trip the caller's blanket `except` into silently discarding ALL carried survivors.

## Implementation Summary

### Task A — Capture fill FIRE state (`smt_detect.py`)
- Added defensive `_fvg_zone(fvg)` helper: reads the MNQ zone as `{top, bottom}` floats, returns `None` on a malformed/missing zone (never raises), keeping fire-state capture total.
- At BOTH fire sites in `detect_fill_smts` (Fill-A and Fill-B), in addition to the existing `st["fire_price"] = mnq_close`, persist to `st`: `fire_time = iso`, `fire_phase = "fill_a"`/`"fill_b"`, `fire_zone = _fvg_zone(fvg)`, `fire_leader = leader`. `st["direction"]` was already set at init.

### Task B — Producer-lifecycle fill carry source (`session_pipeline.py`)
- New `_detect_state_fill_entries(self, session_date)` mirroring `_detect_state_pending_entries`: walks `self._detect_state`, skips reserved `__*__` keys and any key containing `|` (LEVEL keys), requires `fill_a_fired`/`fill_b_fired` to be present, and selects a key as carryable iff `fill_a_fired OR fill_b_fired` is True. Emits one fill entry per fired key with `price=None`, `tier="day"`, `kind="fill"`, plus `phase`/`zone`/`fire_price`/`fire_time`/`direction`/`leader`/`side` sourced from the fire-state capture. Wrapped per-key in `try/except: continue` (never raises).
- Replaced the old `_active`-sourced `_fill_entries` list comprehension with `self._detect_state_fill_entries(_carry_session)`. The `_level_entries + _fill_entries` save line is untouched. Updated the stale carry-block comment to describe the new producer-lifecycle fill source.

### Task C — Pending-entry schema: fill variant
- Additive only: the fill entry dict adds `kind:"fill"`, `phase`, `zone:{top,bottom}` on top of the existing level-entry shape. `schema` stays `1`. No separate code beyond the dicts emitted in Tasks B/D.

### Task D — Read side: kind-branch fulfillment + identity preservation (`smt_detect.py`)
- `revalidate_and_filter_pending`: kind-branch in the RE-VALIDATE block — fills force `tier="day"` and run day-tier FULFILLMENT only; the level-relative depletion backstop is explicitly skipped for fills (`_level = None if _is_fill`). Dedup by `(ref_name, direction)` is unchanged (works for fills, whose `ref_name` is the FVG name).
- `_pending_entry_to_record`: kind-branch rebuild — a `kind=="fill"` entry rebuilds as a fill record preserving `phase`/`type` and `zone`; `_record_key` returns the bare FVG name, preserving fill detect identity. The `else` (level) branch is the unchanged `kind:"smt"` rebuild.

### Code-review fix (Medium)
- Defensive coercion of `fire_price`/`price` in `revalidate_and_filter_pending`: `dict.get` returns a stored `None` (not the default), so `float(None)` would have raised `TypeError`, and the caller's blanket `except` would have silently discarded ALL carried survivors. Now a present-but-`None` fire anchor → `status="unfulfilled"` (keep the entry: no fulfillment evidence), and the `pending_smt_terminal` call is wrapped in `try/except (TypeError, ValueError)`.

- A fill that ran +41 favorable overnight is dropped via `drop_fulfilled` even when the entry's `tier` says `"week"` — the read side forces `tier="day"` (MNQ FULFILL = 40).
- A fill whose overnight window stays within 40 of the fire close survives with audit `reason=="ingested"` and the rebuilt survivor keeps `kind=="fill"`.
- A fill with no swept level (`price=None`) is NOT dropped by the level-relative depletion backstop even on a deeply adverse window (fulfillment is the only drop path for fills).
- A malformed fill whose `fire_price` is present-but-`None` does NOT raise (never-raise contract) and is kept as unfulfilled.
- A carried fill round-trips through `_pending_entry_to_record` preserving `kind`/`phase`/`type`/`zone`/`direction`/`ref_name`, with `carried=True`, `fulfilled=False`, `time==fire_time`, and `key`/`keys` equal to the bare FVG name (identity preserved).
- Two carried fills with the same `(ref_name, direction)` but different `fire_time` collapse to the newest.
- A carried fill whose `(ref_name, direction)` matches a fresh active-set fill is dropped via `drop_dedup`.

## Challenges & Resolutions

**Challenge 1:** `dict.get` masks a present-but-`None` fire anchor.
- **Issue:** `e.get("fire_price", e.get("price", 0.0))` returns the stored `None` (the default only fires on a MISSING key), so `float(None)` would raise.
- **Root Cause:** A raise inside `revalidate_and_filter_pending` propagates to the caller's blanket `except`, silently discarding ALL carried survivors — a high-blast-radius failure from one malformed entry.
- **Resolution:** Explicit `None`-coercion (`fire_price` → `price` → `unfulfilled`) plus a `try/except (TypeError, ValueError)` guard around `pending_smt_terminal`. Covered by `test_fill_none_fire_price_does_not_raise`.
- **Prevention:** Treat any `dict.get(...)` whose value is later passed to `float()`/`int()` as a `None` hazard whenever the key may exist with a `None` value.
