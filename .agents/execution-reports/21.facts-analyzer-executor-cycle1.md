## 3. Issues found by the post-execution reviews, and how each was resolved

Two independent reviews (technical code review, acceptance-criteria validation) ran
after the gates first passed. Both independently surfaced the same two blocking defects.

### B1 — the whole chain was inert on the live driver *(blocking, FIXED)*

`TraderGraft` and `Executor` gated all bar-close work on a truthy `bar_complete`. But
`automation/main.py:246` (the only live call site) and `backtest_smt.py:1597` (the 1s
replay) **hard-code `bar_complete=False` on every tick** — they hand over an intra-minute
partial each second and expect the consumer to notice the minute rollover itself, which
is exactly what `session_pipeline` does for SMT detection. `bar_complete=None`
("auto-detect from cadence") is likewise falsy.

Consequence: under the runbook's own shadow configuration the Analyzer would spend a
real LLM call at 09:20 and then produce **nothing** — no plan, no `plans.json`, no
`trader_decisions.jsonl`. Every test drove `bar_complete=True`, which is why the suite
was blind to it.

**Fix:** `Executor.bar_closed()` and `TraderGraft._bar_closed()` derive the cascade
trigger from a minute rollover, treating `bar_complete` as an override rather than the
sole source. The first call only seeds the minute (no bar has completed yet), which is
what `test_per_second_path_does_no_fvg_detection` requires.
**Regression tests:** `test_chain_runs_on_the_LIVE_cadence_where_bar_complete_is_always_false`,
`test_chain_runs_when_bar_complete_is_none`, `test_bar_close_is_derived_from_a_minute_rollover`,
`test_bar_complete_none_behaves_like_the_auto_detect_it_names`,
`test_explicit_bar_complete_true_still_cascades_immediately`,
`test_hook_still_runs_when_the_live_driver_passes_bar_complete_false`.

### B2 — the Analyzer was fed ~15 h of bars where it needs 17 days *(blocking, FIXED)*

The graft built `bars = {"MNQ": today_mnq, "MES": today_mes}`. Those frames are the
CURRENT CME session only. `ANALYZER_REQUIREMENT` declares 17-day windows and
`EXECUTOR_REQUIREMENT` 14 days for levels.

Consequence: `detect_levels` finds no prior trade date, so no `prevN_day_*` and no
`prev1_week_*` levels exist — yet `build_bundle` still returns a non-`None` bundle
(a 15 h slice is non-empty), so the view is **structurally valid but materially empty**
and nothing reports it. The L1 thesis would be decided against an empty level universe,
silently. Gate 1 cannot catch this: the parity harness feeds the online path the raw
parquet frames (full history), so it stays green while live runs degraded.

**Fix:** `session_pipeline` now passes `hist_mnq` / `hist_mes` to the hook — the same
frames `_build_ai_decisions_frames` already hands the async AI worker for exactly this
reason. `TraderGraft._frames` splices them onto `today_*`, caching the history slice
(it does not change within a session).
**Regression tests:** `test_history_is_spliced_onto_the_session_frame`,
`test_without_history_the_view_is_visibly_degraded` (pins the bug's signature),
`test_hook_receives_the_history_frames_not_just_the_session`.

### B3 — a synchronous LLM call on the per-second tick *(blocking, FIXED)*

`Analyzer.maybe_run` ran `run_batch` + `compute_facts` + a live HTTP model request
inline, on the IB per-second callback that also drives the legacy engine's **order
execution**. A 30–120 s model call would stall live execution for its duration.

**Fix:** `Analyzer(..., threaded=True)` submits to a daemon thread and returns
immediately; the result is picked up by a later bar through `standing_thesis()`. The
graft uses `threaded=True`; the default stays `False` so every plan-specified test keeps
its synchronous, deterministic semantics.
**Regression test:** `test_analyzer_runs_off_the_bar_loop_when_threaded` (asserts the
bar loop returns in < 2 s while the model call blocks).

### B4 — plan death judged by pre-arm price action *(high, FIXED)*

`_death` / `_falsified` ran over the whole session frame (18:00 ET onward), so a plan
armed at 10:30 was killed by a DOL touch that happened overnight. Overnight traversal of
a level a plan later names as its DOL is routine, so in practice most plans would die on
their first bar. **Fix:** `Executor._since_arm()` slices at `arm_ts` first.
**Regression tests:** `test_pre_arm_dol_traversal_does_not_kill_the_plan`,
`test_post_arm_dol_touch_still_kills_the_plan`.

### B5 — the coverage watermark claimed history the bars did not contain *(medium, FIXED)*

`run_batch` set `extend_coverage(cls, tkr, now - window)` unconditionally, so a 14-day
request over a 15-hour slab claimed 14 days. **Fix:** the watermark now records what the
bars actually reached (`max(requested, first_bar)`); a separate `requested_from` tracks
what the lookback was *driven* over and is what the "already at the cap, do not re-batch"
short-circuit reads — so honesty is restored without losing the optimisation.
**Regression test:** `test_coverage_watermark_reports_what_the_bars_actually_hold`.

### B6 — bar-close cascade overran the 1 s loop cadence *(found while re-measuring, FIXED)*

Once real history reached the Executor, the bar-close cascade cost **820 ms mean /
1083 ms p95** on a 24k-row frame. Two hot spots: `bars.resample` computed the session
origin with a Python call per row, and `Executor._refresh_avg_range` resampled the whole
frame to 1h to read the last 20 bars. Both fixed (vectorised; 30-hour tail). Now
**36 ms mean / 93 ms p95** — 23×.

### B7 — `agent/facts/` shadowed `agent/bench/facts.py` *(found during execution, FIXED)*

Creating a package named `facts` under `agent/` broke every bare `from facts import ...`
in the repo, because those modules put `agent/` on `sys.path` ahead of `agent/bench/`.
`agent/bench/test_score.py` went from 13 passing to a collection error. Five call sites
(`run_bench.py`, `test_facts.py`, `test_run_bench.py`, `test_score.py`,
`manual-l1-thesis/test_l1_thesis_manual.py`) now use the unambiguous dotted path
`agent.bench.facts`, with the repo root added to their `sys.path` blocks.

- **A1 — `assemble_facts` ignores its `store` argument.** The plan's Task 10 says "build
  the dict from the store view", but its own acceptance gate compares the result against
  `derive_facts`, and most of the 15 contract keys (HTF close status, mid reclaim, SMT
  candidates, evidence magnitude, the S8/S9 renders) have no representation in the new
  facts layer at all. Reconstructing them would guarantee gate-1 failure and duplicate

  ... ignores the store entirely") over its *task* note. **Consequence, stated plainly:
  the new detectors are never exercised on the Analyzer path, and gate 1 tests input
  preparation rather than fact derivation.** Alternative rejected: reimplement S0–S9 from
  the store.
- **A2 — the hook signature gained `hist_mnq` / `hist_mes`.** See B2. Alternative
  considered: give `TraderGraft` the history at construction time in
  `automation/main.py`. Rejected because the backtest path constructs `SessionPipeline`
  directly and would then be silently history-less.
- **A3 — one generic FVG binder, not four per-mechanism implementations.** The plan
  specifies the Executor's guards precisely (max-distance 60, DOL-floor 60) but gives no
  code for the four mechanism classes. Implemented: select the live MNQ 5m gap facing the
  trade direction whose trigger is nearest current price (§2's single-stop-entry policy),
  entry buffer 3 pts, structural stop capped at 25 pts from entry (§2, 2026-08-22).
  **`fvg_1m_post_extreme` and `extreme_reject_close` are armed by the Planner but cannot
  bind** — they need their own detectors, which cycle 1 does not ask for.
- **A4 — `MIN_SESSION_BARS = 200`, no weekday filter.** `derive_facts` uses 1000 and
  filters weekends; those assume full 1s/1m session frames. This detector is also driven
  over short incremental slices, and a Sunday-evening CME session is a real session.
- **A5 — `segment_legs` emits the currently-forming leg.** A trend in progress is exactly
  what the reversal mechanism reverses; waiting for it to close would leave the plan blind
  for the whole leg. Required to satisfy the plan's own leg tests without lookahead.
- **A6 — `valid_while` evaluates only the `price_beyond` predicate shape.** The closed
  predicate vocabulary is thesis.md's and the plan does not enumerate it. Unknown kinds
  are treated as NOT fired (fail-open on plan death, not fail-closed) and this is stated
  in the code. Guessing at a vocabulary would be worse than leaving it unevaluated.
- **A7 — `ensure_coverage` short-circuits at the cap.** Without it, a class that is
  inherently narrow (EXTREME holds two facts) never reports `OK`, so every call re-drove
  the whole lookback. Not in the plan; required to keep `ensure_coverage` on the bar-close
  path.
- **A8 — `DETECT_TAIL_BINS = 64` in the incremental cascade.** A cascade has exactly one
  new completed bin to inspect; scanning the whole 24 h frame each bar-close is quadratic
  across a session. `detect_fvgs` is idempotent, so the tail overlap is free. Cut the seam
  test from 33 s to 14 s with an identical fact set.
- **A9 — extracted `bundle_to_l1_view` out of `agent/bench/facts.py`.** So the online
  assembler and the offline bench share one copy of the S8/S9 overlay logic. Verified
  behavior-preserving against `git show 186af44:` on two dates across every output field.
  Alternative rejected: duplicate ~145 lines into `assemble.py` and let them drift.
- **A10 — `ACT_TRADER` wired into `automation/main.py`.** The plan names the flag in the
  runbook but never wires it. Without wiring, "flag off ⇒ never constructs" is untestable.

## The one change that could not be done as specified

**D — the harness retargets FORWARD; live cannot.** The manual harness moves the
boundary to a future HTF close because the parquet already holds those bars. Live, they
do not exist yet, so the production shape of the same rule is a **deferral**: hold the
call, re-check each bar, fire once the close has actually happened.

Consequence worth being explicit about: the next qualifying 1h close after 09:20 is
10:00 ET, so on a day that defers, the Analyzer arms at 10:00 and the Executor's settle
window is long past. That is what the recorded panel did, but it is in tension with
"the Analyzer runs at 09:20". The wait is therefore capped (`MAX_RETARGET_WAIT`,
90 min) and switchable (`NEAR_MATURITY_WAIT`); past the cap it calls at 09:20 anyway.

## Judgment calls

- **Ownership rule for the maintainer.** Whoever CREATED it drives it. The graft injects
  one and drives it; a standalone `Executor` creates and drives its own. Without this,
  the graft and the Executor would both cascade on the same bar.
- **The arming bar gets an extra maintenance pass** under the default switch, because
  the maintenance block runs before the Executor exists on that bar.
- **The journal snapshot moved from the Analyzer to the graft.** Change F deleted the
  store it used to snapshot. It now snapshots the SESSION store, once per date, on a bar
  close — describing the store the Executor actually binds against.
- **`slice_for_boundary` accepts both column cases.** The bench's raw frames are
  capital-cased and the online frames are lower-cased; the ATH read handles both rather
  than forcing a normalisation that would alter the offline path.
- **G was applied selectively.** Minute-stepped loops just drop the flag (identical
  semantics, first bar seeds). Single-shot cascade tests gained an explicit seed bar.
  Tests whose subject IS the flag keep it, with a comment saying so.
