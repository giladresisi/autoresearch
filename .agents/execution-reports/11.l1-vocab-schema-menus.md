This is the first L1-INTERNALS slice: it teaches the model the closed predicate vocabulary
(schema-enforced), pre-computes candidate DOL/predicate **menus** in the facts, tags each
predicate menu-hit/escape-hatch, and gives a failsafe its own retry. The measurement runs show
the intended effect: the `SYN_BAD_PREDICATE → failsafe` class that dominated every plan-10 bench
date is **eliminated** (failsafe 66.7–100% → ~0–4%), the model selects overwhelmingly from the
menus (menu-hit ≈ 0.95–0.99), and — under the diagnostic `stand-directional` gate — theses now
STAND, yielding the first real lifecycle metrics (completion / false-kill / late-kill).

### Phase 1 — Schema enforcement (`agent/contracts/schemas.py`)
Every `*_if` / `recall.events` field is now a strict `anyOf` of the six atoms (each `type` a
`const` + exactly its params, `additionalProperties:false`) plus depth-1 `all_of`/`any_of` whose
items are **atoms only**. Defined once in `$defs` and referenced by `$ref` from every predicate
field (`predicate_schema()` gives the self-contained fragment for standalone validation). An
unknown predicate `type` is now impossible to generate.
- **Real-backend constraints discovered + handled** (the plan flagged "verify the backends
  accept anyOf"): the Anthropic structured-output backend (via OpenRouter) (a) rejects `minimum`
  on integers — so numeric bound keywords (`minimum`/`exclusiveMinimum`/`minItems`) were dropped
  from the schema and are enforced by the deterministic predicate validator instead
  (`predicates.validate_predicate`: `n≥1`, `minutes>0`, non-empty `of`) — "constraints live in
  code, not the schema" (spec §5); and (b) rejects the fully-INLINED union as "compiled grammar
  too large" — hence the `$defs`/`$ref` structure, which keeps the compiled grammar small. Both
  verified with a real API call (Phase 5.2).
- Named tests (`agent/contracts/test_schemas.py`, 13): every atom accepted; unknown type / null
  type / no-type rejected by schema; missing/extra param + bad enum rejected; numeric bounds +
  empty composite enforced by the VALIDATOR (not schema); depth-1 `all_of`/`any_of` accepted,
  nested composite rejected by schema; full THESIS/TRADE_PLAN schemas accept the fail-safe blocks
  and reject an unknown predicate.

### Phase 2 — Menus in `derive_facts` (S8)
`compute_facts` captures `bundle.day_mid`; `build_menus(bundle, vd)` + `render_menus_text(bundle)`
produce the S8 block. **DOL menu:** eligible draws per direction — in-facts, unswept, undepleted,
correct side of price, side-tag consistent (a resistance now below price is "spent", excluded) —
with level/wick/body/tier + IDs D1,D2,…. **Predicate menu:** per direction, falsification (F) /
exhaustion (X) / recall (R) predicates with concrete params, generated from a config
(`_MENU_PREDICATE_CFG`: families × level-classes × param-variants) — **no concrete level name is
hardcoded**; level names resolve from the facts at build time.
- **Byte-identity invariant preserved:** `render_facts_text` (S0–S7) and the shared
  `facts_to_validator_dict` are UNCHANGED — the latter is hashed as the shadow engine's facts
  identity (`agent/decisions/facts_adapter.py` `_canonical_hash`), so menus are injected ONLY
  into the bench's own `validator_dict` copy and into a SEPARATE `render_menus_text` block
  appended to the model prompt. The bench `content_hash` remains the S0–S7 hash (prepare_cuts
  parity intact).
- Named tests (`agent/test_menus.py`, 7): DOL menu excludes swept/depleted/wrong-side/side-less
  pools; nearest-first ordering + stable IDs; predicate IDs unique + params concrete; families
  present (exhaustion = one price_beyond per DOL entry; an anti-pool falsification exists);
  config has no hardcoded level names; menu text deterministic + lists IDs/params.

### Phase 3 — Validator menu-membership + prompt (`validate_contracts.py`, `run_agent.py`)
`classify_predicates(thesis, facts)` tags each predicate `menu_hit` (params exactly match a menu
entry for the thesis direction, via a number-normalising canonicaliser so `110 == 110.0`) or
`escape_hatch`, plus DOL menu-hit — **pure telemetry**, adds no rejections (the schema at
generation time + `validate_thesis` grounding remain the gates). Facts without a `menus` block
(production) → everything is escape_hatch, no crash. `_TASK_THESIS` now teaches the closed
vocabulary, the S8 menus (select-by-copying-params, escape-hatch rules, depth-1 composition) —
mechanical instructions only, no judgment content.
- Named tests (`agent/contracts/test_menu_membership.py`, 6): menu-match passes + tagged with the
  menu id; int/float still matches; escape-hatch valid predicate passes with tag; escape-hatch
  non-facts level rejected (SEM_LEVEL_NOT_IN_FACTS) yet still telemetry-tagged; NEUTRAL thesis →
  empty tags; no-menu facts → all escape_hatch.

`FAILSAFE_RECALL_MAX_AGE_MIN = 60` (config const in `schemas.py`); `failsafe_thesis()` now carries

### Phase 5 — Measurement (bench-only `--gate` + telemetry)
`--gate calibrated|self|stand-directional` on `run_bench` (default `calibrated` = production).

## Divergences from the plan
1. **Schema uses `$defs`/`$ref`, not a fully-inlined `anyOf`.** REQUIRED by the real backend
   (inlined union → "grammar too large"). Behaviour is identical (same closed vocabulary, depth-1
   composition); the fragment is just referenced instead of copied. `predicate_schema()` returns
   the self-contained form for standalone validation/tests.
2. **Numeric bound keywords omitted from the schema** (`minimum`/`exclusiveMinimum`/`minItems`) —
   the Anthropic backend rejects `minimum` on integers. The bounds (`n≥1`, `minutes>0`, non-empty
   `of`) are enforced by the deterministic predicate validator, matching spec §5 ("constraints
   live in code, not prompts/schema"). Two Phase-1 tests were adjusted to assert these bounds at
   the validator instead of the schema (not a weakening — the constraint still holds, verified).
3. **Menus injected into the bench's validator_dict copy, not the shared
   `facts_to_validator_dict`.** The shared dict is hashed as the shadow engine's `content_hash`;
   injecting menus there would change the shadow/off facts identity. Menus are therefore an
   additive L1/bench overlay (build on a copy + a separate rendered block). This is stricter than
   the plan's "AND into validator_dict" wording but is the only way to keep the shadow path
   byte-stable (which the brief mandates).
4. **`--churn-cap 6` on the measurement runs** (budget) — see the churn-cap characterization
   above; metrics are on the overnight portion of each session.
5. **`test_run_bench` fixture churn_cap 20→2.** Since the failsafe now re-calls at +60, a full-day
   stub run churns ~20× (each facts build ~8s → >60s pytest timeout). Cap=2 keeps the test fast
   while now MEANINGFULLY exercising the re-call loop; the determinism/linked-id/coverage
   assertions hold at any cap.
