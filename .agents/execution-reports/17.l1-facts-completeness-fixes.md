## Implementation Summary

### Fix 1 — Time-gate `(prev1)` sub-session liquidity levels
The `(prev1)` sub-session emission block now respects the ET clock, mirroring production's
`smt_detect.py::eligible_levels()` semantics for this file's `(cur)`/`(prev1)` naming model:
- `now.hour >= 18` (today's Asia forming): emit `(prev1)` only for `ny_morning`/`ny_evening`;
  `asia`/`london` are skipped.
- `now.hour < 18` ("London onward"): skip all four `(prev1)` sub-sessions — their `(cur)`
  copies are the only valid reference this late.

The `(cur)` block (gated by its own `closes_at`) was left untouched. This produced the golden
fixture's only delta: 49 prev1 sub-session lines deleted, nothing else.

### Fix 2 — Curate + verdict the S9 FVG-fill (P5) block
Added `FVG_LOOKBACK_DAYS = 3` near `SMT_LOOKBACK_HOURS`. Zone-building now computes `visited_at`
and a `fill_verdict` (held / violated / None) per zone via the existing `_htf_close_status()`
(bull zone → LOW edge / `side="below"`; bear zone → HIGH edge / `side="above"`; `beyond=True` =
violated/reject, else held/accept; both TFs immature → None). `render_evidence_text` curates the
S9 FVG list to VISITED zones formed within 3 days of `now` and appends
`-> HELD (accept)` / `-> VIOLATED (reject)` / `-> (fill too recent to verdict)`. The S6 raw list
is deliberately left as the full uncurated 10-day historical scan.

### Fix 3 — HTF-close verdict for `daily_mid`/`weekly_mid`
Added `_last_mid_crossing()` helper. `daily_mid` (`(day_hi+day_lo)/2`) and `weekly_mid`
(`(week_hi+week_lo)/2`) are computed per asset and treated as synthetic per-asset "levels": the
last crossing in the `SMT_LOOKBACK_HOURS` window becomes a synthetic `swept_at`, fed through
`_htf_close_status()` with a fixed `side="above"` mid convention, and populated into
`bundle.swept_at[tkr]` / `bundle.htf_close_status[tkr]`. The existing S9 render loop picks them
up with no new print statements. A bare `daily_mid = …` line was added symmetric to the existing
`weekly_mid = …` scalar. No-crossing → `swept_at=None` → skipped as "never swept, not evidence".

## Divergences from Plan

### Divergence #1: Fix 3 `side` rule — fixed `side="above"` instead of "side from current close"
**Classification:** ✅ GOOD
**Planned:** derive `side` from whether the current close is above/below the mid (`"above"` if
most-recent close is above, else `"below"`).
**Actual:** used a fixed `side="above"` mid convention (beyond=True = closed above the mid =
reclaim held/ACCEPTED; below = REJECTED).
**Reason:** the plan's "side from current close" rule self-contradicts its own test 1 — at
2026-07-27 the plan requires a REJECTED verdict, which the current-close rule would not produce.
**Root Cause:** plan gap (internal inconsistency between the stated rule and its stated expected result).
**Impact:** Positive — the fixed convention makes plan test 1 pass exactly and is direction-consistent
for a mid pivot (a mid has no "swept side" the way a high/low does).
**Justified:** Yes — confirmed ACCEPTED by acceptance-criteria validation.

### Divergence #2: Fix 3 test 2 (07-22 MNQ `weekly_mid`) — immature, not ACCEPTED
**Classification:** ⚠️ ENVIRONMENTAL (faithful-to-data)
**Planned:** assert MNQ `weekly_mid` 1h `beyond` is `True` (ACCEPTED) at 2026-07-22 09:20, "same for MES".
**Actual:** MES `weekly_mid` IS a mature ACCEPTED there (matches the plan). MNQ is honestly immature:
MNQ price straddles its own weekly mid at that instant (last crossing 09:02:47, most-recent completed
1h bar closed just below the mid), so a faithful implementation must leave it `None` rather than
fabricate a verdict.
**Reason:** the plan's expectation was infeasible for MNQ against the real market data at that exact boundary.
**Root Cause:** plan assumption vs. real data — the reclaim was asset-specific, not shared MNQ+MES.
**Impact:** Neutral — the test asserts the honest immature result for MNQ and the ACCEPTED result for MES;
refusing to fabricate is the correct behavior.
**Justified:** Yes — accepted by acceptance-criteria validation.

## Challenges & Resolutions

**Challenge 1:** Plan self-contradiction on the Fix 3 `side` rule.
- **Issue:** the stated "side from current close" rule would not yield the plan's own required
  REJECTED result at 2026-07-27.
- **Root Cause:** plan internal inconsistency; a mid pivot has no natural swept side.
- **Resolution:** adopted a fixed `side="above"` mid convention; verified it satisfies test 1 exactly.
- **Prevention:** when a plan pairs a rule with a concrete expected result, cross-check the rule
  against the result before implementing.

**Challenge 2:** Fix 3 test 2 expectation (MNQ ACCEPTED) infeasible against real data.
- **Issue:** MNQ straddled its own weekly mid at the exact boundary; no qualifying completed 1h close.
- **Root Cause:** the reclaim was MES-specific, not shared.
- **Resolution:** asserted honest immature `None` for MNQ, ACCEPTED for MES; refused to fabricate.
- **Prevention:** verify per-asset market conditions at named boundaries before asserting shared outcomes.

**Challenge 3:** Synthetic mids inflating the mature-P1 evidence count (found in code review).
- **Issue:** the `_mature_p1` counting loop (~`derive_facts.py` L1920) counted the synthetic
  `daily_mid`/`weekly_mid` levels, inflating `mature_evidence_count`.
- **Root Cause:** Fix 3 populated the same dicts the P1 counter iterates; mids are P4 pivots, not P1 levels.
- **Resolution:** added a `levels` guard to `continue` past the synthetic mids in that loop. Also
  refreshed the stale `fvg_zones` field docstring (LOW severity).
- **Prevention:** when reusing a shared per-level dict for a new synthetic entity, audit every
  consumer loop of that dict, not just the renderer.
